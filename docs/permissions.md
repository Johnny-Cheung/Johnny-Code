# 权限模型

Johnny-Code 有三个权限模式：`default`、`read-only`、`allow`。三种模式都是**应用层策略，不是操作系统沙箱**；它们的目的是让日常操作保持流畅，同时把写入、任意命令和范围外访问交给用户决定。

| 模式 | 启动方式 | 文件读写 | `bash` | 审批 |
| --- | --- | --- | --- | --- |
| `default` | `johnny` 或 `--permission-mode default` | 工作目录白名单内自动执行 | 固定查询、项目前缀和会话授权自动执行，其余审批 | 逐次请求 |
| `read-only` | `--read` 或 `--permission-mode read-only` | 只能读启动工作目录内的文件 | 只允许固定查询 | 不请求，直接拒绝 |
| `allow` | `--skip` 或 `--permission-mode allow` | 直接执行 | 直接执行 | 不请求 |

`--permission-mode` 与 `--read`/`--skip` 同时使用时必须一致，否则启动报错。

## 默认模式

不传权限参数时进入默认模式。

自动执行一条 Bash 命令必须**同时**满足：

1. 未命中固定危险后缀黑名单；
2. 每个命令段命中固定查询表、已记录的项目命令前缀或本会话授权；
3. 可识别的路径参数都在项目路径白名单内（含会话路径授权）。

文件工具和查询命令的路径仍逐项检查；已有的命令授权不会顺带放行新的路径。

### 固定查询（21 个）

| 档位 | 命令 |
| --- | --- |
| 纯读（14） | `echo`、`basename`、`dirname`、`pwd`、`realpath`、`ls`、`grep`、`cat`、`head`、`tail`、`wc`、`stat`、`du`、`diff` |
| 逃逸口（7） | `find`、`rg`、`sed`、`sort`、`uniq`、`tree`、`file` |

每个命令使用封闭参数表和语义解析，只放行已知安全的形式。未命中表格或表格外选项的用法按普通命令处理。

### 项目命令前缀

只接受固定工具族的安全子命令，例如 `git status`、`git log`、`go test`、`go build`、`cargo test`、`npm run build`、`make test`。

- 首次审批选择“批准并记录”后写入 `.johnny/permissions.local.json`，后续同前缀自动执行。
- 解释器、shell 和命中危险后缀的命令不提供“记录”。
- 项目前缀命令会检查形似路径的参数和常见选项值；脚本、测试和构建目标内部访问无法静态限制，这是应用层策略的边界。
- 项目规则文件加载前会展示内容并请求确认；确认后的内容哈希保存在 `~/.johnny/trusted_permissions.json`，文件变化后重新确认。

### 分段器

默认模式和只读模式共用同一个分段器：

- 按 `&&`、`||`、`;` 连接管道，`|` 绑定更紧，整条命令最多 **16 个命令段**。
- 逐段判定，全部自动放行才执行；任一段未命中时，默认模式整条命令一次性审批并标出需要审批的段，只读模式整条拒绝。
- `cd <目录>` 只能作为整条命令的第一段；后续段按虚拟工作目录解析相对路径并继续做路径检查。`cd` 不能参与管道，也不能紧邻 `||`。
- 满足条件时按直接 argv 加 OS pipe 执行，不经过 shell；`&&`、`||`、`;` 按原始退出码短路，管道退出码取最后一段，不设 `pipefail`。
- 只认命令段末尾的 `2>&1`、`>/dev/null`、`2>/dev/null`，并按出现顺序应用。
- 未引用的通配符（`*`、`?`、`[`、`]`）直接拒绝，并提示改用 `find -name`；受控执行不展开通配符，给文件通配符加引号也不会展开。
- 超过 16 段的命令直接拒绝，提示拆成多条 `bash` 调用。
- 写入真实文件的重定向、输入重定向、后台执行、命令替换、循环、条件、变量展开不在受控语法范围：默认模式对这类语法做一次完整 shell 审批，且不提供记录或会话授权；只读模式直接拒绝。
- 工作目录内不存在的查询路径不提前审批或拒绝，交给实际程序报告“文件不存在”。
- 直接调用解释器等非查询程序仍需审批；未获项目规则放行的非查询管道消费者不提供会话授权，避免更换上游输入后复用同一个 argv。
- 固定查询命令可以作为管道生产端，项目前缀命令也可以。

### 审批

审批提供四个选项：

| 选项 | 作用 | 出现条件 |
| --- | --- | --- |
| 允许本次 | 只执行这一次 | 总是 |
| 拒绝本次 | 不执行；默认焦点 | 总是 |
| 本会话内允许 | 当前 johnny 进程内有效，不写项目规则 | 请求带有可记住的授权键 |
| 批准并记录 | 写入项目规则，后续同前缀自动执行 | 命令可记录时 |

- “本会话内允许”对主 Agent、子任务和 workflow 任务共享，进程退出即失效。它按可记录前缀加规范工作目录、不可记录命令的完整 argv 加有序重定向和工作目录、或路径规则记住授权。
- 命中危险后缀和 `remember` 始终每次询问。
- 队列中同键的待审批请求在显示前重检，命中已有授权会自动放行。
- 等待审批期间 `Ctrl+C` 取消本轮并丢弃所有待审批请求。

## 只读模式

- 拒绝 `write`、`edit`。
- `read` 只能读取启动工作目录内的文件；允许读取 `.env` 等敏感文件。
- `bash` 只允许固定查询两档共 21 个命令的受限形式，使用与默认模式相同的分段器，支持管道、`&&`、`||`、`;`、工作目录内的虚拟 `cd` 和三种尾部安全重定向，不经过 shell。
- 不支持项目前缀和会话授权；未命中固定表或表格外选项直接拒绝。
- 解析失败时说明具体原因和处理建议，例如：
  - `命令共 17 段，超过 16 段上限；请拆成多条 bash 调用`
  - `不支持未引用的通配符 *；受控执行不展开通配符。查找文件请用 find -name '模式'`
- 不请求审批；所有不在允许范围内的操作直接返回拒绝原因。

## 放行模式

`--skip` 或 `--permission-mode allow`：

- 工具直接执行（包括 `skill`），不逐次确认。
- 不应用路径规则。
- 仍然受工具自身约束，例如 `task` 的文件范围、超时和输出上限。

## 路径与敏感文件

- 默认模式路径白名单包含启动工作目录和项目路径规则。
- 白名单内的 `.env`、私钥、`.git` 和 `.johnny` 权限文件可以直接读写，这是明确取舍。
- 默认模式的子进程环境会过滤 Johnny 和模型服务凭据变量，但不能阻止命令读取磁盘上的配置。

## 边界与限制

1. **不是 OS 沙箱。** 默认模式的 Bash 仍以当前用户权限运行，脚本内部行为不受路径检查限制。
2. **只读是策略性只读。** 允许读取范围内的 `.env`、私钥、`.git` 等文件但拒绝写入；被允许程序的内部行为不在应用层路径检查范围内。
3. **封闭参数表不等于零副作用。** 例如 `sort` 在输入超过内存缓冲时仍可能向系统临时目录写临时文件；`stat`、`file` 等程序的可用选项按平台不同。
4. **参数任务在入口被拒绝。** `johnny "任务"`、管道和重定向不会进入 TUI，也不会进入审批。

完整的设计背景和收口记录见 [v0.7 设计文档](versions/v0.7.md)。

## 常见自动执行示例

```sh
rg -n "TODO" . | head -20
find . -name '*.go' | head
cat a.txt | grep -v '^#' | wc -l
sed -n '1,20p' README.md
git status 2>/dev/null     # 已记录 git status 前缀后
go test ./... | tail -20   # 已记录 go test 前缀后
```

示例中的选项、路径和重定向仍需通过封闭参数表与路径检查。任一段未命中时，默认模式整条命令一次性审批，只读模式整条拒绝。
