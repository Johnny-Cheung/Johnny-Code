# v0.3 · 统一模型接口

**状态：已实现，通过自动化检查、全局安装和多模型真实调用验证；用户反馈各模型可以正确调用，多模型调用初步验收通过。**

## 目标与确认范围

用户授权按讨论方案实现 v0.3，并指定主要验收目标：**换用不同模型都可以正常调用。**

本版通过 Johnny-Code 自己的请求、消息、事件和结果访问模型服务，为 v0.4 工具系统、v0.5 Agent Loop 和 v0.6 TUI 提供基础。

- 使用 Go，继续沿用全局 `johnny` 命令。
- 实现 Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions 三个适配器。
- 现有 `.env` 原位复用，不迁移、不重填，不将凭据放入源码或构建信息。
- 支持通过配置或临时命令行选项切换协议和模型。
- 保留单轮输入、流式正文输出、帮助、版本、取消和跨目录使用。
- 模型层支持工具定义、工具调用和工具结果的协议转换；工具注册执行与 Agent Loop 留在后续版本。

## 方案取舍

### 按协议适配，分别表达服务与模型

模型品牌不能确定请求协议。当前 DeepSeek 使用中转站提供的 Anthropic 端点；同一中转站也可以为 GPT 提供 OpenAI 端点。

参考 pi-ai 的 API、Provider、Model 划分：

| 概念 | 本项目中的含义 |
| --- | --- |
| API | 请求与流式响应的协议 |
| Provider | 提供模型的服务，以规范化后的端点地址标识来源 |
| Model | 服务实际接受的模型标识 |

当前配置只描述一组服务，客户端构造时固定协议、地址和鉴权，每次请求指定模型。尚未建设模型目录、价格表、OAuth 或复杂的 provider 注册系统。

### 首批提供三种协议

| 配置值 | 接口 | 使用方式 |
| --- | --- | --- |
| `anthropic-messages` | `/v1/messages` | 现有默认；实际端点支持时用于 DeepSeek、Kimi、GLM 等模型 |
| `openai-responses` | `/v1/responses` | GPT 优先选择；使用 `store: false`，由调用方持有消息历史 |
| `openai-chat-completions` | `/v1/chat/completions` | 为提供该协议的服务保留兼容入口 |

讨论初期推荐 Messages 与 Chat Completions；核对 OpenAI 官方建议后优先考虑 Responses。实现时一并加入 Chat Completions，并使用当前服务验证三种协议。

协议由配置明确指定，不根据模型名猜测，也不在调用失败后自动切换。兼容某种协议不代表服务支持该协议的全部扩展能力。

## 配置与切换

现有三个字段继续使用：

```dotenv
JOHNNY_API_KEY=服务凭据
JOHNNY_BASE_URL=https://relay.example
JOHNNY_MODEL=服务提供的模型标识
```

新增可选字段：

```dotenv
JOHNNY_API=anthropic-messages
```

完全未配置 `JOHNNY_API` 时默认使用 Anthropic，已有 `.env` 无需改动。显式设置为空仍按覆盖后的无效值报错。

`JOHNNY_BASE_URL` 支持服务根地址或以 `/v1` 结尾的 API 根地址，并保留中转站前缀路径；适配器避免重复追加 `/v1`。完整的 `/messages`、`/responses`、`/chat/completions` 接口地址会被拒绝。

临时切换示例：

```sh
johnny --model "Kimi-K2.7-Code" "请只回复：调用成功"
johnny --model "GLM-5.3-Flash" "请只回复：调用成功"
johnny --api openai-responses --model "gpt-5.6-sol" "请只回复：调用成功"
johnny --api openai-chat-completions --model "gpt-5.6-sol" "请只回复：调用成功"
```

这些模型名来自本次服务提供的目录，仅适用于实际可用的服务。选项放在问题之前；含空格的模型名用引号包围。只指定选项而不提供问题时，仍可以从交互输入读取一个问题。

优先级为：`--api`、`--model` > 对应环境变量 > `.env`。Key 和地址仍使用现有配置；跨服务时通过相应环境变量覆盖。临时切换不会写回配置文件。

## 统一接口与消息

### 一次调用

```go
type Client interface {
    Stream(context.Context, Request, func(Event) error) (Response, error)
}
```

`NewClient(Options)` 接收协议、服务地址和 Key，负责构造对应客户端。模型层不读取 `.env`，也不切换工作目录。

| 类型 | 主要内容 |
| --- | --- |
| `Request` | 模型名、系统指令、有序消息列表、工具定义、输出 token 上限 |
| `Message` | 角色、有序内容块、assistant 消息的来源信息 |
| `Event` | 事件类型、内容块索引、增量或完整块 |
| `Response` | 完整 assistant 消息、结束原因、可选 token 用量 |
| `Error` | 错误分类、安全提示和可用的 HTTP 状态码 |

### 内容块

角色为 `user`、`assistant`、`tool`。系统指令单独放在 `Request.System`，由适配器转换。

| 内容块 | 数据 |
| --- | --- |
| `text` | 正文 |
| `thinking` | 思考文本及必要的协议续接数据 |
| `tool_call` | 调用 ID、工具名、JSON 对象参数 |
| `tool_result` | 对应调用 ID、文本结果、执行错误标记 |

工具定义包含名称、描述和 JSON 输入 schema。校验层检查角色与内容块组合、工具参数格式、调用 ID 唯一性和结果关联；参数是否符合 schema、工具是否允许执行，由后续工具层处理。

assistant 消息记录协议、规范化服务地址和模型名。签名或加密 reasoning 数据保存在带来源的 `Replay` 中，不作为显示正文或错误提示输出。当前优先保证同源消息可续接；带专用数据的历史不允许直接跨协议、服务或模型重放。

### 流式与完整结果

事件使用 `block_start`、`block_delta`、`block_end`，通过稳定的块索引关联。事件数据独立保存，避免先前事件被后续增量修改。

回调在调用的同一 goroutine 中按顺序执行。回调返回错误就停止请求并关闭流，保留错误链；`emit == nil` 时只组装完整结果。整轮完成和失败由函数返回值表达。

正文立即流式显示，同时累积完整 assistant 消息。CLI 补出的终端换行不进入模型消息，最终结果也不会再次重复打印正文。工具参数片段不能提前执行，后续工具层需检查整轮结果及结束原因。

### 结束状态、用量与错误

结束状态覆盖正常完成、请求工具、达到输出上限及拒绝。网络或协议失败返回非空错误，并保留已收集的部分结果；调用方不能将部分结果视为成功消息续接。

用量以可选字段区分缺失与 0。输入总量包含缓存输入，输出总量包含推理输出；缓存和推理分项不能再累加到总数。本版不计算费用。

错误区分无效请求、鉴权、限流、服务、网络、协议和不支持的能力。错误提示不回显服务原始载荷或凭据。取消与超时保留 `errors.Is` 可识别性，回调输出错误同样保留原错误链。

应用层继续设置 5 分钟时限和默认 4096 个输出 token，禁用 SDK 自动重试。

## 代码与执行流程

```text
CLI 参数 → 读取现有配置并应用覆盖 → 创建协议客户端
  → 构造一条用户消息 → 校验统一请求 → 转换并调用服务
  → SDK 流式事件 → 统一块级事件 → CLI 即时显示正文
  → 完整结果或错误 → 检查结束状态、补换行、返回退出码
```

| 文件 | 职责 |
| --- | --- |
| `internal/model/types.go` | 项目自有的协议、请求、消息、事件、结果和错误类型 |
| `internal/model/client.go` | 客户端构造、地址规范化与请求校验 |
| `internal/model/stream.go` | 内容块收集、事件数据隔离与结果完成检查 |
| `internal/model/anthropic.go` | Anthropic Messages 适配 |
| `internal/model/openai_responses.go` | Responses 适配与共用 OpenAI 辅助逻辑 |
| `internal/model/openai_chat.go` | Chat Completions 适配 |
| `internal/config/config.go` | 配置读取、默认协议和命令行覆盖 |
| `cmd/johnny/main.go` | 命令行入口、流式正文显示与进程行为 |

三个适配器均使用对应的官方 Go SDK，供应商类型留在适配器内部。安装脚本沿用 v0.2，安装测试同步覆盖新增生产文件。

## 当前边界

- 当前 CLI 每次只问一个问题，不保存会话历史；接口可以接收调用方提供的历史。
- 工具消息转换已建立，当前命令不执行工具，也不自动进入下一轮。
- 先支持文本与必要的思考续接数据，不包含图片、文件或供应商托管工具。
- Chat Completions 适配标准正文与工具调用；尚不支持的思考历史或额外增量字段会明确报错，避免静默丢失信息。需要思考续接时使用已支持该能力的 Messages 或 Responses。
- 完整跨模型历史转换、模型目录、价格计算和广泛的供应商兼容开关留待实际需求推进。
- 模型自报名称不能作为路由证据；验收同时核对请求传递及真实回复。
