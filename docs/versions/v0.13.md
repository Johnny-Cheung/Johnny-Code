**状态：待讨论（2026-10-28 建立占位）。** 本文只记录范围、边界和已有调研，尚未进入方案讨论，不代表任何设计已经确认。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

让多个 Agent 协作完成任务，而不只是主 Agent 向子 Agent 单向委派。[v0.12](v0.12.md) 的子 Agent 只和主 Agent 交互；v0.13 讨论成员之间如何通信、分工和协调。

## 与 v0.12 的边界

v0.12 提供底座，v0.13 直接复用：

- Manager 与子任务登记、收件箱、结果注入和空闲唤醒；
- 审批来源标注与审批队列；
- 每个 Agent 独立的会话 JSONL 和父子关联；
- 取消沿父子关系传递；
- 写入类任务的文件范围（v0.13 可能升级为一等的文件所有权）。

v0.13 才讨论：成员间消息、共享任务板、用户与成员直接对话、成员的长期存在与恢复。

## 协作梯度

| 层级 | 形态 |
| --- | --- |
| 0 | 并行独立子任务（v0.12） |
| 1 | 主从协作：主 Agent 分派，成员回报，成员之间不通信 |
| 2 | 成员之间互相发消息，主 Agent 仲裁 |
| 3 | 共享任务板，成员自行认领，带依赖 |
| 4 | 成员长期存在，可恢复，用户可直接和成员对话 |

## 候选场景

1. 实现者与审查者来回迭代；
2. 后端、前端、测试按模块分工并行开发，需要对接口约定；
3. 多个研究者提出并互相质疑不同方案；
4. 规划、实现、测试流水线（主要由主 Agent 编排）。

## 调研记录（2026-10-28）

**Claude Code agent teams**（https://code.claude.com/docs/en/agent-teams）：

- 实验性，默认关闭，需要 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`，仅交互模式；
- lead 是主会话，teammates 是各自独立的会话和上下文；
- 共享任务列表有 pending / in-progress / completed 状态和依赖，认领任务用文件锁；
- 每个成员有 mailbox，`SendMessage` 自动投递，成员空闲时把最终结果通知 lead；
- 用户可以选中某个成员，查看并发消息；
- 权限继承 lead，审批冒泡到 lead；Agent 消息不能代表用户同意，也不能转授被拒绝的操作；
- 推荐 3 到 5 人，没有硬上限，成本随人数大致线性增长；
- 官方限制：成员不随会话恢复、任务状态可能滞后、关闭较慢、每个会话一个团队、不能嵌套、lead 固定；文件冲突靠分配不同文件，没有自动隔离。

**Codex**（https://github.com/openai/codex）：

- `multi_agent_v2`：`send_message` 只入队，不触发目标开始新一轮；`followup_task` 会触发目标新一轮；另有 `list_agents` 和 `interrupt_agent`；
- 共享工作目录，只靠提示词约定不要影响他人工作；
- `agent_message_board`（共享讨论板）是实验性功能，默认关闭。

**Anthropic 多 Agent 研究系统**（https://www.anthropic.com/engineering/multi-agent-research-system）：

- 多 Agent 比单 Agent 约多消耗 15 倍 token；
- 常见失败：过度派生、任务含糊导致重复劳动、更新过多、该停不停；
- 编码任务可并行的部分比研究任务少。

## 与现有架构的关系

- `Conversation` 同一时刻只支持一次 `Run`，成员需要各自独立的 `Conversation`（v0.12 已是这种形态）；
- TUI 需要从“子任务状态区”扩展为成员视图，审批需要标明来源并排队（v0.12 已做队列）；
- 需要新增 mailbox、任务存储、成员注册表和文件所有权；
- 工具调用串行执行不变，消息只能在两次模型请求之间被成员看到。

## 待讨论问题

1. 最先要解决哪个协作场景；
2. 协作做到哪一层：只要主从，还是需要成员互相通信；
3. 用户能否直接和某个成员对话；
4. 文件所有权如何表达和拦截，`bash` 怎么处理；
5. 成本如何可见和限制（成员数、消息数、token）；
6. 消息是否持久化，成员是否可恢复；
7. 多个 Agent 同时请求审批时的交互；
8. 默认关闭的实验开关怎么设计。

## 与权限收口的关系

多个 Agent 同时发起审批、Agent 消息不能代表用户同意、成员之间不能转授权限，这些都是新的权限场景。因此 v0.7 权限模型的验收与最终收口安排在 v0.13 之后一并处理。
