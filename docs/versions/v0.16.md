# v0.16 · macOS Seatbelt 沙箱

## 目标

给所有权限模式的 `bash` 增加一层统一的执行沙箱，作为权限策略之外的兜底：

- 权限模式继续决定命令 `allow / ask / deny`；
- 沙箱只决定命令执行时能写什么、能读什么、能不能联网；
- 不引入 Docker、镜像、端口映射等额外配置；
- 用户正常启动即可，沙箱默认开启；
- 沙箱不可用时明确提示，不静默失去保护。

## 已确认的取舍

1. **先只适配 macOS。** 使用系统自带的 Seatbelt（`/usr/bin/sandbox-exec`）；Linux 暂不启用，启动时提示是否本次不使用沙箱继续。
2. **只包 `bash`。** `read`、`write`、`edit` 仍在宿主机按权限模式执行；因此 `allow` 模式的文件工具仍能访问工作目录外。
3. **所有模式共用一层执行器。** default、read-only、allow、jev 的 bash 都经过同一个 `sandbox.Runner`；权限判断不变。
4. **不依赖 Docker。** 不需要镜像、容器、端口映射；命令仍使用宿主机工具链。
5. **默认联网。** 网络默认开启，保证 `npm install`、`go mod download`、`curl` 等日常能力；`JOHNNY_SANDBOX_NETWORK=off` 用于严格离线会话。
6. **写白名单。** 只允许写工作目录、会话临时目录、缓存目录和必要的设备文件；工作目录外只读。
7. **启动检测。** `sandbox-exec` 自检失败时默认退出；交互终端可选择重试或本次无沙箱继续。参数模式直接报错。
8. **保留显式逃生口。** `JOHNNY_SANDBOX=off` 可以关闭沙箱；启动和系统提示都会标注“沙箱关闭”。

## 实现

### 执行器抽象

新增 `internal/sandbox`：

- `Runner` 接口：`CommandContext`、`Environment`、`Describe`、`Close`。
- `Runtime` 增加 `Sandbox` 字段；`Runtime.CommandContext` 在沙箱启用时返回 `sandbox-exec` 命令，否则返回普通 `exec.CommandContext`。
- `Bash.Execute` 和 `executeControlledChain` 都改用 `Runtime.CommandContext`，因此：
  - 完整 shell 命令走沙箱；
  - 默认模式自动放行的受控 argv 链也走沙箱；
  - 只读模式的固定查询链也走沙箱；
  - JEV allow/ask 通过后的完整 shell 也走沙箱。
- 启动时把 `Sandbox.Environment` 合并进 `Runtime.Env`，统一设置 `TMPDIR`、`GOTMPDIR`、`XDG_CACHE_HOME`、npm/pip 缓存目录。

### Seatbelt profile

profile 由 Johnny 运行时生成，写到会话临时目录，使用 `sandbox-exec -f` 加载，避免 inline profile 撞 `ARG_MAX`。

核心规则：

```scheme
(version 1)
(allow default)

(deny file-write*)
(allow file-write* ...工作目录、会话目录、缓存目录、/dev/null 等...)

(deny file-write* (subpath ".../.johnny"))
(deny file-read* (subpath "~/.johnny"))
(deny file-read* (subpath "~/.johnny"))
(deny file-read* (literal "Docker/Colima/OrbStack socket"))

(deny network*)
```

路径规则使用真实路径：

- 工作目录和会话目录先 `realpath`，避免符号链接导致规则失效；
- macOS 的 `/tmp` 实际是 `/private/tmp`，profile 使用解析后的路径；
- 缓存目录只在存在时加入白名单。

### 启动流程

`prepareSandbox` 在进入 TUI 前运行：

1. `JOHNNY_SANDBOX=off`：关闭沙箱，打印警告。
2. `sandbox-exec` 自检失败：
   - 交互终端显示“退出 / 重试 / 本次不使用沙箱继续”；
   - 默认退出；
   - `c` 需要用户主动选择，并明确提示“不安全”；
   - 参数模式直接报错退出。
3. 自检成功：创建 `Seatbelt`，挂到 `Runtime`，打印 `沙箱：Seatbelt（网络开启）`。
4. 系统提示补充执行环境说明；TUI 启动 notice 显示沙箱状态。

### 审计与状态

当前版本通过启动输出、TUI notice 和系统提示标注沙箱状态；尚未把 `sandbox=seatbelt` 写入每个 `permission` 事件。后续可在 `ApprovalAudit` 和会话元数据中补充。

## 边界

- **不保护工作目录本身。** 工作目录必须可写，`rm -rf .` 仍会删除项目；靠 Git/备份兜底。
- **读默认放开。** 包括工作目录内 `.env` 和工作目录外普通文件；沙箱主要限制写入和网络。当前只额外拒绝 `~/.johnny` 和容器 socket。
- **只包 bash。** `read`/`write`/`edit` 不受沙箱约束。
- **网络只有全关/全开。** 还没有 Claude/Codex 那种域名 allowlist 代理；`JOHNNY_SANDBOX_NETWORK=off` 是全局开关。
- **没有按命令例外。** 沙箱里跑不了的命令（例如需要写 `/opt/homebrew` 的 `brew`、需要 Docker socket 的命令）目前只能关闭沙箱或调整环境；后续再做“允许本次联网/路径/沙箱外执行”。
- **`sandbox-exec` 已 deprecated。** 当前 macOS 仍可用，Claude Code 和 Codex CLI 也在使用；Apple 未来移除时需要切换执行器。
- **Linux 未接入。** 启动时会走“无沙箱继续”的提示；后续用 `bubblewrap` 实现。

## 测试

- profile 生成包含写白名单、`.johnny` 保护、断网规则、SBPL 转义；
- 工作区写入成功、工作区外写入失败；
- `git init` 成功、项目 `.johnny` 禁止写入；
- 网络关闭时 `curl` 失败；
- `TMPDIR` 指向会话目录；
- 退出码透传；
- 完整 shell 和受控 argv 链都在沙箱内；
- 取消后进程组及时清理；
- 启动检测、`JOHNNY_SANDBOX=off`、网络开关。

验证命令：

```sh
go test ./...
go test -race ./...
go vet ./...
go build ./...
```
