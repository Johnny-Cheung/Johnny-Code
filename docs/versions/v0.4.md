# v0.4 · 工具系统

**状态：已实现，并于 2026-10-20 与 v0.5 联合通过用户验收。**

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

在 v0.3 统一模型接口的基础上，建立 Johnny-Code 自己的工具系统，让模型可以请求结构化工具，并让程序完成工具定义、注册、参数校验和直接执行，再将结构化结果交回调用方。

本版的直接成果是一个可以独立测试的工具运行层。它可以被 v0.5 Agent Loop 调用，但本版不负责根据工具结果自动再次请求模型。

## 与前后版本的边界

### 复用 v0.3

- 复用 `model.ToolDefinition` 作为发送给模型的工具定义基础。
- 复用 `model.ToolCall`、`model.ToolResult` 和工具消息，保持不同模型协议下的调用 ID 关联。
- 复用 `model.Request.Tools`，由 Agent Loop 在每次模型请求中传入当前可用工具。
- 复用 v0.3 的统一错误、取消和上下文传递约定。

### v0.4 负责

- 工具实现的统一接口。
- 工具注册表和名称查找。
- JSON 参数解析与工具级校验。
- Bash 命令执行、文件读取、精确编辑和文件写入四类基础工具。
- 工作目录、命令执行目录、取消、超时、输出上限和结果错误的明确规则；本版不设置权限审批或人工确认。
- 单个工具的执行结果结构，以及对 v0.3 `ToolResult` 的转换。

### 本版与 CLI 的关系

v0.4 独立交付时提供工具执行层，并通过 `cmd/tool-demo` 手动驱动验证；当时模型请求不携带工具定义，模型返回的 `tool_call` 不会被 CLI 执行。用户确认保持这一范围，模型驱动执行与循环统一放在 v0.5。

**当前 v0.5 已接通 CLI、模型请求和本工具层**，`johnny` 可以根据模型返回的调用执行四个工具、回传结果并继续请求模型。具体循环和调试记录见 [v0.5 文档](v0.5.md)。以下手动入口继续保留，用于单独排查工具行为。

手动验证入口：

```sh
# 完整示例，使用临时目录并在结束后删除
go run ./cmd/tool-demo

# 在当前目录执行单个工具
go run ./cmd/tool-demo bash '{"command":"pwd"}'
go run ./cmd/tool-demo write '{"path":"demo.txt","content":"hello"}'
go run ./cmd/tool-demo read '{"path":"demo.txt"}'
go run ./cmd/tool-demo edit '{"path":"demo.txt","old_string":"hello","new_string":"world"}'
```

手动模式会在当前目录真实创建、修改或执行命令，这是直接执行模式的预期行为。

## 初步架构

```text
Agent Loop / 测试调用方
        ↓ ToolCall
工具注册表 Registry
        ↓ 按名称查找
工具定义 Definition + 执行器 Executor
        ↓
Bash / 读取 / 编辑 / 写入
        ↓ ToolResult
统一模型消息层
```

建议把工具系统放在独立的 `internal/tool` 包中。模型层只负责工具定义的协议转换；工具层不依赖 Anthropic 或 OpenAI SDK。

## 统一工具接口草案

建议工具本身只关心定义和执行：

```go
type Tool interface {
    Definition() model.ToolDefinition
    Execute(context.Context, json.RawMessage) (Result, error)
}

type Result struct {
    Content string
    IsError bool
}
```

执行上下文需要携带本次工具运行的边界信息，而不是让每个工具自行读取全局配置。可在实现时使用显式的 `Runtime` 或构造参数提供：

- 工作目录和命令工作目录。
- 命令执行环境。
- 单次执行超时。
- 输出大小上限的基础值。
- 取消信号。

v0.4 不把工作区根目录当作权限边界，也不通过运行时结构体实现路径审批；工具直接使用当前进程被操作系统授予的访问能力。

具体是否将这些字段放入 `context.Context`，还是使用工具运行时结构体，需要在实现前确定。倾向于用显式结构体表达工作目录和生命周期参数，`context.Context` 只负责取消和截止时间。权限边界、审批策略和凭据隔离不在本版运行时中实现。

工具结果需要区分三种情况：

1. 参数或工具名称无效，工具没有开始执行。
2. 工具已执行但目标操作失败，例如文件不存在或命令返回非零状态。
3. 工具成功完成并产生结果。

前两类都可以转换为 `model.ToolResult{IsError: true}`，但内部错误类型和用户可见文本要保留差异。v0.4 不建立凭据隔离和脱敏策略；实现只避免把不必要的内部堆栈混入结果，正式凭据处理放到 v0.7。

## 注册表草案

```go
type Registry struct {
    // 内部按工具名保存唯一实例。
}

func (r *Registry) Register(Tool) error
func (r *Registry) Get(string) (Tool, bool)
func (r *Registry) Definitions() []model.ToolDefinition
func (r *Registry) Execute(context.Context, model.ToolCall) (Result, error)
```

注册规则初步建议：

- 工具名称不能为空，只允许稳定的 ASCII 标识符。
- 重复名称直接报错，不静默覆盖已有工具。
- `Definition()` 返回的名称必须与注册名称一致。
- 输入 schema 必须是合法 JSON 对象，并与 v0.3 发给模型的定义一致。
- `Definitions()` 返回稳定排序，避免请求内容因 map 遍历顺序变化。
- `Execute()` 只执行已注册工具；未知工具返回结构化错误结果，不 panic。
- 注册表本身不自动执行工具，也不创建新的模型请求。

是否允许注册表在运行中追加或删除工具需要讨论。初步倾向于构造阶段完成注册，运行期间只读；这样 v0.5 Agent Loop 可以在一次调用中稳定地看到工具集合。

## 第一批内置工具

参考 Claude Code 的基础工具形态，建议本版固定为四个工具：

| 工具 | 作用 | 初步输入 |
| --- | --- | --- |
| `bash` | 在工作目录执行命令，也可通过 `grep`、`find` 等完成搜索 | `command`、可选超时 |
| `read` | 读取工作区内的文本文件 | `path`、可选行范围 |
| `edit` | 对已有文件进行精确修改 | `path`、旧文本、新文本、可选替换策略 |
| `write` | 创建或整体写入文件 | `path`、`content` |

搜索不单独提供 `search_files` 工具，由 `bash` 承担。这样工具数量更少，模型需要学习的契约更简单，也与目标产品的基础工具形态保持一致。代价是搜索输出和命令生命周期由 Bash 工具统一处理，需要更明确的超时、输出和取消策略。

工具的具体 JSON schema、输出格式和是否支持二进制文件需要结合实现复杂度确定。第一版优先支持文本文件，遇到二进制或无法按 UTF-8 读取的内容返回清晰错误。

### `bash`

- 命令在明确的工作目录中启动，默认不改变 Johnny 进程的工作目录。
- 可以执行构建、测试、版本控制和搜索命令；工具本身不把搜索另建为特殊 API。
- 直接使用当前进程提供的命令环境，不设置环境变量白名单或 API Key 隔离。
- 捕获 stdout、stderr、退出码和取消状态。
- 设置默认超时和输出上限；超时终止进程组并报告超时，达到输出上限时截断并标记。
- 不要求执行前人工确认；Bash 调用直接启动，权限和审批能力留到 v0.7。

### `read`

- 以运行时工作目录解析相对路径，绝对路径按操作系统现有能力处理。
- 不增加路径白名单、越界审批或符号链接拦截；这些属于 v0.7 的权限策略。
- 返回文件内容以及必要的行号信息，默认按 `行号 + 制表符` 前缀输出。
- 目录、特殊文件、超出单次读取限制的文件返回错误；FIFO 等特殊文件不会阻塞。

### `edit`

- 使用运行时提供的工作目录解析相对路径，不增加人工路径确认。
- 优先使用带上下文的精确替换，避免模糊覆盖整个文件。
- 对目标不存在、匹配次数不符合预期、内容冲突和写入失败分别报错。
- 写入采用临时文件和替换，保留原文件权限；目标是符号链接时写入链接指向的真实文件。
- 不创建目标不存在的文件；创建新文件统一使用 `write`。

### `write`

- 使用运行时提供的工作目录解析相对路径，绝对路径按操作系统现有能力处理。
- 负责创建新文件，也可以按明确规则整体覆盖已有文件，不增加权限确认。
- 父目录不存在时不自动创建，返回执行错误并提示先使用 `bash` 创建目录。
- 写入采用临时文件和替换，避免进程中断留下半个文件。
- `write` 允许覆盖已有普通文件，保留原文件权限；v0.4 不在执行时弹出确认。
- 不执行 `content` 中的命令或表达式，内容只作为文件字节写入。

## 直接执行模式与生命周期

v0.4 明确采用面向开发推进的直接执行模式：工具不弹出确认、不检查权限策略、不启用沙箱或路径白名单。调用方提供工作目录，工具直接使用当前进程和操作系统已有的访问能力。

本版仍保留执行生命周期约束：

- 相对路径基于运行时工作目录解析；绝对路径是否可用由操作系统权限决定。
- Bash 使用调用方提供的命令环境，工具不做环境变量隔离。
- 所有工具都响应 `context.Context` 取消，避免取消后继续写文件或运行命令。
- Bash 设置超时和输出上限，防止测试或开发命令无限占用进程。
- 错误要返回可识别的类型和稳定的用户提示，不能 panic。

人工确认、路径白名单、沙箱、凭据隔离和审计属于 v0.7 安全与权限版本。

## 候选验收标准

- 可以注册四个基础工具，重复名称和非法定义被拒绝。
- `Definitions()` 返回稳定、完整且能直接交给 v0.3 `Request.Tools` 的工具定义。
- 根据合法 `ToolCall` 能找到正确工具并执行，结果包含调用 ID、正文和错误状态。

- `edit` 在匹配失败或匹配次数不符合预期时不改动目标文件。
- `write` 能正确创建文件，并按确定的覆盖和父目录规则执行。
- `bash` 正确返回 stdout、stderr、退出码、取消和超时结果，并遵守工作目录及输出边界。

- 使用临时工作区的自动化测试覆盖正常、非法输入、路径解析、不存在路径、失败、取消和超时场景。
- v0.3 的模型适配器仍可以接收工具定义和工具结果消息；本版不要求 CLI 自动循环调用模型。

## 实现记录

- `internal/tool/tool.go`：统一工具接口、结果、错误分类和 `model.ToolResult` 转换。
- `internal/tool/runtime.go`：工作目录、命令环境、默认超时和输出上限。
- `internal/tool/registry.go`：构造期注册校验、稳定定义排序、名称查找和独立执行入口。
- `internal/tool/fs.go`：直接执行模式下的路径解析、有界输出和原子写。
- `internal/tool/read.go`：带行号的 UTF-8 文本读取、行范围和输出截断。
- `internal/tool/edit.go`：精确文本替换、唯一匹配检查、全量替换和原子写。
- `internal/tool/write.go`：新建或覆盖普通文件，保留已有权限，不自动创建父目录。
- `internal/tool/bash.go`：shell 命令、stdout/stderr、非零退出、超时、取消和输出截断。
- `internal/tool/process_unix.go`、`process_other.go`：Unix 进程组终止和其他平台回退。
- `cmd/johnny/main.go`：仅更新版本号为 `0.4.0`，没有接入工具或循环。
- `scripts/install_test.go`：隔离安装测试同时复制 `internal/model` 和 `internal/tool` 生产文件。

本版 `write` 允许覆盖已有普通文件并保留原权限；父目录不存在时失败，不自动创建。四个工具直接执行，不弹确认、不检查权限策略、不设置路径白名单或环境变量隔离。工具层不调用 `os.Chdir`。

已确定的行为细节：

- **Bash 后台进程与清理。** 命令结束时终止整个进程组，不留下后台进程。若 shell 已成功退出但后台子进程仍占用输出管道（例如 `cmd &`），最多等待 1 秒后关闭管道并按成功返回，同时清理该后台进程；本次调用返回后不会残留进程。
- **Bash 超时。** 默认超时 2 分钟，可通过 `timeout_seconds` 在 1 到 600 秒之间调整；超时终止进程组并报告 `context.DeadlineExceeded`，调用方取消直接返回取消错误。
- **read 文件类型。** 先确认目标为普通文件再打开，FIFO、设备等特殊文件直接返回错误，不会阻塞；输出上限默认 256 KiB，超长行按上限截断。
- **edit/write 与符号链接。** 目标是符号链接时写入其指向的真实文件，不替换链接本身；新建文件权限固定 0644，不额外套用 umask；覆盖已有文件保留原权限，能否覆盖由目录权限决定。
- **原子写。** 同目录临时文件加同步改名；失败或取消时清理临时文件，目标文件保持原内容。
