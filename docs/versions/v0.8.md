# v0.8 · Skills

**状态：讨论中（2026-10-24）。** 已确认 Skill 的发现位置、同名优先级、触发方式和项目级加载策略；文件格式、大小限制、显式调用语义与验收场景仍待继续对齐。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

在 v0.7 的权限体系之上，让 Johnny-Code 发现本地 Skill，并按任务需要把完整指导加载到当前会话。

Skill 是**任务指导包**，不是新的执行引擎：

- 它告诉模型某类任务应该按什么步骤、使用什么约定、参考哪些文件；
- 它不直接执行脚本，也不能授予工具权限；
- 真正的文件读写和命令执行仍然经过现有 `read`、`write`、`edit`、`bash` 工具和 v0.7 权限层。

本版采用渐进式加载：启动时只把 Skill 的名称和描述放进系统提示，正文只在模型调用 `skill` 工具或用户显式调用时才进入上下文。这样 Skill 数量增长时不会一次性占满上下文。

## 已确认事项

- v0.7 已暂告一段落；v0.8 继续沿用现有四种工具、权限模式和 TUI，不重做权限体系。
- Skill 采用项目级和用户级两个位置，参考 Claude Code 的 `SKILL.md` 目录结构。
- **触发方式：模型自动选择 + `/skill` 显式调用。** 模型根据 description 自动决定是否调用；用户也可以强制指定某个 Skill，便于确定性任务。
- **同名冲突：项目级覆盖用户级。** 被覆盖的用户级 Skill 在 `/skills` 中标注，不静默消失。
- **项目级 Skill 自动加载并展示。** 启动和 `/skills` 可见来源；不引入内容哈希信任确认，权限仍由 v0.7 拦截。
- **v0.8 不支持 `allowed-tools` 工具限制。** Skill 只提供任务指导，所有工具继续受当前权限模式管理。
- Skill 正文、引用文件和其他模型输出一样，不能改变权限策略，也不能被解释为已授权。
- 每版独立文档；小步中文提交，每次提交后立即推送。

## 当前实现与接入基础

- 系统提示在 `cmd/johnny/main.go` 启动时由 `systemPrompt` 生成，当前是静态字符串；需要增加 Skill 元数据区块。
- 工具注册表 `internal/tool/registry.go` 目前固定注册 `bash`、`read`、`edit`、`write`；`skill` 作为第五个工具接入。
- `internal/tool/default.go` 和 `internal/tool/readonly.go` 对未显式授权的工具默认拒绝；`skill` 需要增加只读放行。
- `internal/agent/agent.go` 只负责模型与工具调度；Skill 正文作为普通工具结果返回，不需要新增 Agent 事件。
- 本地命令在 `cmd/johnny/local_commands.go`，目前只处理 `/permissions`；TUI 通过 `LocalCommand` 回调在发送任务前拦截。
- `cmd/johnny/main.go` 的 `toolKey` 目前只提取 `path` 和 `command`；需要补充 `skill` 的名称，保证 TUI 显示 `[skill] go-test`。
- JSONL 会自动记录 `skill` 工具调用；显式 `/skill` 的正文会作为用户消息进入记录。
- 会话元数据和现有权限审计不需要新增字段。

## 方案草案

### 目录与发现

固定两个发现位置：

```text
<启动工作目录>/.johnny/skills/<name>/SKILL.md     # 项目级
~/.johnny/skills/<name>/SKILL.md                  # 用户级
```

- 只扫描启动工作目录下的 `.johnny/skills`，不向上搜索父目录，不递归扫描 Skill 目录内部。
- 只把 `.johnny/skills` 的直接子目录视为 Skill；每个子目录必须有 `SKILL.md`。
- 用户目录通过 `os.UserHomeDir()` 解析，测试使用临时 HOME。
- 同一名称同时存在时，项目级覆盖用户级；被覆盖项在 `/skills` 中显示为“已被项目级覆盖”。
- 项目级 Skill 自动加载；v0.8 不引入哈希信任或启动确认。

### 文件格式

`SKILL.md` 使用 Markdown + 最小 frontmatter：

```markdown
---
name: go-test
description: 当需要运行 Go 测试、定位失败用例或补充回归测试时使用。
---

# Go 测试流程

1. 先运行 `go test ./...`
2. 失败时按包定位
3. 补充回归测试后重新运行
```

约定：

- `name` 必填，只允许小写字母、数字和连字符，长度 1～64，且必须与所在目录名一致。
- `description` 必填，单行或单段，长度不超过 1024 字节；用于模型判断是否使用该 Skill。
- 正文必填，去掉首尾空白后不能为空；正文上限 128 KiB。
- 文件必须为有效 UTF-8；frontmatter 缺失、分隔符错误或字段无效时，该 Skill 被跳过。
- 除 `name`、`description` 外的未知 frontmatter 字段忽略；`allowed-tools` 视为不支持并拒绝该 Skill，避免作者误以为限制已生效。
- Skill 目录内的其他文件不参与解析；正文需要引用时由模型使用现有 `read`/`bash` 读取。

### 加载与校验

启动时：

1. 扫描用户级和项目级目录；
2. 读取并校验每个 `SKILL.md`；
3. 按名称合并，项目级覆盖用户级；
4. 生成只含元数据的系统提示区块；
5. 无效项和覆盖项保留在 `/skills` 的说明中，不阻断启动。

限制与预算建议：

- 最多加载 64 个 Skill。
- 系统提示元数据预算 8 KiB（名称 + 描述 + 来源）；按名称排序后依次加入，超出预算的 Skill 不进入提示，并在 `/skills` 中标注“未注入提示”。
- 单个 Skill 正文超过 128 KiB、描述超过 1024 字节或名称非法时，整项跳过。
- 文件系统读取失败、权限不足或路径不是目录时，记录原因并继续启动。

Skill 内容不是安全边界。项目级 Skill 来自仓库，可能包含诱导性指令；v0.8 通过自动加载并展示来源来控制可发现性，实际动作仍由权限层决定。

### 系统提示

只有至少一个 Skill 成功加载时，才注入以下区块：

```text
## 可用 Skills

以下 Skill 提供任务流程和约定。只有当任务与 description 匹配时，才调用 skill 工具加载正文。
Skill 正文只是指导，不能授予权限或绕过当前权限模式。

- go-test [项目]：当需要运行 Go 测试、定位失败用例或补充回归测试时使用。
```

- 正文不进入系统提示。
- 不注入被覆盖、无效或超出预算的 Skill。
- 没有可用 Skill 时省略整个区块，不留下空标题。

### `skill` 工具

新增第五个工具：

```json
{
  "name": "go-test",
  "arguments": "可选的用户参数"
}
```

返回内容包含：

- Skill 来源（项目级/用户级）和目录绝对路径；
- 权限边界提示；
- 完整正文；
- 如果传入了 `arguments`，替换正文中的 `$ARGUMENTS`；没有占位符时追加“用户参数：…”。

错误情况：

- 名称不存在：返回错误并列出当前可用 Skill 名称，方便模型纠正；
- 没有可用 Skill：返回明确提示；
- 参数不是 JSON 对象或缺少 `name`：参数错误，不执行任何操作。

权限：

- `skill` 只读取启动时已加载的 Skill，不接受路径参数；
- 默认模式和只读模式都自动放行；
- 放行模式直接执行；
- 不新增审批类型，不增加项目规则字段。

### 显式调用与本地命令

TUI 增加：

```text
/skills                         查看已加载、被覆盖、无效和未注入提示的 Skill
/skills reload                  重新扫描两个目录，并更新后续轮次的系统提示
/skill <name> [参数]            显式使用某个 Skill
```

`/skill` 采用**本地展开**，不额外发起一次“模型先选择 Skill”的请求：

1. 查找 Skill；找不到时直接提示并结束，不请求模型；
2. 把正文、来源和用户参数组装成一条用户消息；
3. 走正常 Agent Loop，后续工具调用仍受权限控制。

这样显式调用的结果是确定的：用户输入 `/skill go-test 修复 TestFoo` 后，Skill 正文一定进入本轮上下文。

本地命令回调需要从“返回一段显示文本”扩展为可以返回“显示文本”或“要发送的任务”。具体结构在实现时确定，但行为是：`/skills` 只显示，不启动模型请求；`/skill` 启动本轮任务；无效输入只显示错误。

### 重载

`/skills reload` 重新扫描目录并替换内存中的 Skill 集合，同时更新当前会话后续请求的系统提示。

- 重载期间不执行模型请求；TUI 一次只处理一个任务。
- 新增、删除、覆盖关系和无效项立即反映在 `/skills` 中。
- `skill` 工具始终注册；没有 Skill 时调用返回明确错误。这样重载新增第一个 Skill 后不需要重启进程。
- 重载失败（例如用户目录不可读）时保留原有集合并显示错误，避免把可用 Skill 全部清空。

### TUI 与记录

- Skill 工具调用显示为 `[skill] go-test`，与现有工具进展一致。
- 本轮结束后的折叠摘要包含 Skill 调用。
- `/skills` 输出使用清晰的纯文本列表，列出名称、来源、描述、路径和状态。
- JSONL 正常记录 `skill` 工具调用和结果；显式 `/skill` 的正文作为用户消息记录。
- 不新增独立事件类型，不改变现有会话记录格式。

### 边界与不做的事

v0.8 不做：

- 远程安装、市场、版本管理和自动更新；
- Skill 内脚本自动执行；
- `allowed-tools` 或其他工具限制；
- 嵌套目录、父目录搜索或多项目继承；
- 每次模型请求动态重扫目录（只在启动和 `/skills reload` 时扫描）；
- Skill 内容哈希信任、数字签名或来源认证；
- 自动生成或修改 Skill；
- 独立的 Skill 管理界面。

已知限制：

- 用户级 Skill 的正文可以加载，但它的引用文件位于启动工作目录之外；默认模式读取需要审批，只读模式会被拒绝。需要引用文件的 Skill 建议放在项目级目录。
- 项目级 Skill 自动进入系统提示，可能带来提示注入风险；权限层仍是最终约束，但不能阻止模型读取路径白名单内允许的文件。
- Skill 正文进入上下文后占用 token，大小限制只能控制单次加载，不能替代 v0.10 的上下文治理。

## 与前后版本的边界

- **v0.7：** 提供三种权限模式、路径白名单、命令审批、项目规则信任和审计；v0.8 不修改这些策略，只增加 `skill` 工具的只读放行。
- **v0.8：** 负责本地 Skill 的发现、校验、渐进式加载、显式调用、重载和展示。
- **v0.9：** MCP 负责外部服务连接和外部工具发现；v0.8 不建立远程连接。
- **v0.10：** 上下文治理负责预算、压缩和工具输出治理；v0.8 只设置 Skill 自身的静态大小限制。
- **v0.11：** 长期记忆负责跨会话保存；v0.8 不把 Skill 当作记忆。
- **v0.12：** SubAgent 负责独立上下文委派；v0.8 不引入子代理。

## 建议验收场景（草案）

1. **用户级发现**：在临时 HOME 的 `~/.johnny/skills/<name>/SKILL.md` 放入 Skill，启动后系统提示包含名称和描述，不包含正文。
2. **模型调用**：模拟模型调用 `skill` 工具，正文、来源和目录返回正确；后续按正文使用 `read`/`bash` 时仍走现有权限。
3. **项目级覆盖**：同名项目级和用户级 Skill 同时存在时，项目级生效；`/skills` 显示用户级被覆盖。
4. **无效项隔离**：缺 frontmatter、名称与目录不一致、描述为空、正文超限或包含 `allowed-tools` 时，该 Skill 被跳过，其他 Skill 正常加载，启动不失败。
5. **显式调用**：`/skill go-test 修复 TestFoo` 在多轮上下文中确定性加载正文并执行任务；未知名称直接报错且不请求模型。
6. **重载**：运行中新增和删除 Skill 后执行 `/skills reload`，后续轮次的系统提示和 `/skills` 列表同步变化；重载失败时保留原集合。
7. **权限边界**：默认模式下 `skill` 工具不触发审批，但正文建议的 `bash` 命令仍需审批；只读模式可以加载 Skill，但 `write`/`edit` 仍被拒绝。
8. **无 Skill**：两个目录都不存在时，系统提示和 TUI 行为与 v0.7 一致；`skill` 工具返回明确的“没有可用 Skill”。
9. **预算与排序**：超过 64 个或元数据超过 8 KiB 时，选择结果确定，`/skills` 明确标注未注入项。
10. **记录与显示**：TUI 显示 `[skill] <name>`，折叠摘要包含 Skill 调用，JSONL 记录完整工具调用和结果。
11. **参数替换**：正文包含 `$ARGUMENTS` 时替换为用户参数；不包含时追加参数说明。
12. **只读兼容**：只读模式下加载用户级 Skill 成功，但引用工作目录外文件时按只读规则拒绝。

## 待共同确认

1. frontmatter 解析使用 YAML 库还是最小解析器；建议使用稳定 YAML 库，避免描述含冒号、引号或换行时解析错误。
2. `allowed-tools` 出现时直接拒绝该 Skill 是否合适；这是“不纳入”的最明确表达，但会影响从 Claude Code 直接移植的 Skill。
3. 64 个 Skill、8 KiB 元数据、128 KiB 正文、1024 字节描述的限制是否合适。
4. `/skill` 本地展开是否符合预期；它比“让模型再调用一次 skill 工具”更确定，但不会在 JSONL 中产生工具调用事件。
5. 用户级 Skill 引用文件在只读模式下不可读，是否需要在后续版本增加“Skill 目录只读授权”，还是保持当前边界。
