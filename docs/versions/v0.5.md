# v0.5 · Agent Loop

**状态：基础工具循环与同进程多轮交互已实现，并于 2026-10-20 与 v0.4 联合通过用户验收。**

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

连接 v0.3 的统一模型接口和 v0.4 的工具运行层，让 Johnny-Code 能根据工具结果连续推进一个用户任务。

一轮用户任务可以包含多次模型请求和多次工具执行。模型的中间说明、工具调用和最终回答都属于这一轮；不需要用户为每一步工具执行手动再次提问。

### 多轮交互补充范围（2026-10-20 确认）

用户确认将基础多轮对话补充到 v0.5，优先保证基本功能，复杂交互留到 v0.6：

| 启动方式 | 行为 |
| --- | --- |
| `johnny "任务"` | 执行一个任务，完成、失败或取消后退出进程，不读取后续输入 |
| `johnny` | 进入交互会话，每轮结束后继续等待输入；保留当前进程内的用户消息、模型回复和工具结果 |

- 在交互输入提示处输入完整的 `/exit`，本地退出，不请求模型、不执行工具；输入流结束（EOF）也正常退出。
- 空行继续等待输入，不请求模型。退出进程后，新进程从新会话开始，不加载历史记录。
- 每次用户输入独立计算模型请求次数预算，默认每轮 50 次；模型正常结束只代表本轮结束。
- 模型请求失败、截断、拒绝或达到请求上限时说明本轮停止原因，保留合法历史，再等待用户输入；不自动重试工具。
- 沿用现有 `Ctrl+C` 取消并退出进程的行为，本次不扩展逐轮取消、输入编辑、历史导航等交互细节。
- 一个交互会话共用一个调试记录文件，增加用户轮次以区分各轮中重新计数的模型请求；记录只用于排查，不作长期记忆或会话恢复。

## 已确认的基本循环

模型请求工具 → 程序执行工具 → 工具结果回传模型 → 再次请求模型，直到模型以正常结束状态返回且没有工具调用，结束本轮任务。

```text
用户输入任务
    ↓
携带消息历史和工具定义，请求模型
    ↓
接收模型的完整响应，同时流式显示正文
    ↓
检查结束原因和结构化工具调用
    ├─ 请求工具 → 按顺序执行本批工具调用
    │               ↓
    │              将完整 assistant 消息和各工具结果加入历史
    │               ↓
    │              再次请求模型，回到上述判断
    │
    ├─ 正常结束且无工具调用 → 结束本轮
    │
    └─ 拒绝、取消、截断、请求失败或达到执行边界 → 说明本轮停止原因

单任务模式：本轮结束后退出进程。
交互模式：本轮结束后继续等待输入，携带当前会话历史处理下一轮。
用户输入 /exit 或 EOF 正常退出；Ctrl+C 沿用取消并退出进程。
```

图中的正常结束以模型请求成功、结束原因正常为前提。模型停止调用工具只表示本轮停止继续行动，任务是否正确完成仍需核对实际产物和检查结果。

## 已确认的执行规则

### 根据结构化结果继续或结束

- 每次请求携带当前可用工具定义，复用 `Registry.Definitions()` 和 `model.Request.Tools`。
- 根据完整 `Response` 中的工具调用和结束原因判断下一步，不根据正文里的“我已完成”等自然语言猜测。
- 正文继续流式显示；收到中间说明不代表本轮结束。同一条模型回复可以同时包含正文和工具调用。
- 等本次响应完整接收、确认工具调用结构有效且未被截断后，再执行工具。流中的参数片段不直接触发执行。
- 不完整或失败响应中的工具调用不执行。

| 模型结果或运行状态 | Loop 行为 |
| --- | --- |
| `StopToolUse`，包含有效工具调用 | 检查取消和请求次数预算，再执行本批工具，将结果回传模型 |
| `StopEndTurn`，没有工具调用 | 正常结束本轮 |
| `StopMaxTokens` | 提示输出被截断，中断本轮，不执行该响应中的工具调用 |
| `StopRefusal` | 提示模型拒绝，结束本轮，不报告为任务完成 |
| 网络错误、协议错误或响应无法解析 | 提示失败并中止，不自动重试或重新执行工具 |
| 用户取消 | 取消当前请求或工具，停止后续调度 |
| 达到模型请求次数上限 | 提示达到上限，停止后续工具和模型请求，不报告为任务完成 |

### 完整保留调用与结果

- 当前进程的会话历史保留在内存中，随每次模型请求继续传入；交互模式下一条用户输入在相同历史上追加，单任务入口每次从新会话开始。
- 将完整的 assistant 消息加入历史，包括正文、工具调用以及模型层保留的同源 Replay 数据，不能只保存终端显示的文本。
- 工具执行后，使用 `tool.ToModelResult` 补齐调用 ID 和错误状态，再追加到历史。
- 每个已执行调用都生成对应结果，保持 `ToolCallID` 一一对应。
- 下一次请求携带完整历史，使模型知道自己请求了什么、工具实际做了什么。

典型消息顺序：

```text
用户消息
assistant 消息：正文、工具调用及相关 Replay
工具结果消息：与调用 ID 对应的结果
assistant 消息：下一批工具调用
工具结果消息：对应的结果
assistant 消息：最终回答
```

### 多工具按顺序串行执行

- 同一次响应中的多个工具调用按返回顺序串行执行，不在 v0.5 引入并行调度。
- 收集本批全部结果后，再请求模型；不能只执行第一个调用就丢弃其余调用。
- 同一批调用的参数已由模型提前生成，程序不根据前一个工具结果擅自修改后一个调用的参数。
- 后一步需要根据前一步输出才能确定参数时，由模型在收到结果后的下一次请求中生成调用。
- 普通工具失败仍生成错误结果，并继续处理本批其他调用；用户取消时停止剩余调用。

### 工具错误回传，运行失败中止

文件不存在、精确替换未匹配、命令返回非零等工具错误作为 `IsError: true` 的结果回传模型。模型可以调整参数、换一种做法，或说明无法完成；程序不因单个普通工具错误立即结束任务。

工具自身超时也应保留输出和错误状态并回传；如果是用户取消或父任务上下文已经结束，则停止整个循环。

网络请求失败、协议错误、响应无法解析、内部消息状态无法继续等运行失败直接中止，并清楚报告原因。取消、截断和达到执行边界分别记录，不冒充正常完成。

## 已确认的次数上限、超时与取消

| 项目 | 规则 |
| --- | --- |
| 最大模型请求次数 | 每轮用户输入默认 50 次，通过 `--max-turns` 调整为正整数；下一轮重置预算 |
| 次数计算 | 初次模型请求也算一次；一次响应包含多个工具调用，仍只算一次模型请求 |
| 单次模型请求超时 | 沿用当前 5 分钟上限，每次模型请求单独计时 |
| Bash 超时 | 沿用默认 2 分钟；工具参数 `timeout_seconds` 可指定 1～600 秒 |
| 整个任务总超时 | 暂不设置固定总时限，由请求次数上限、单次超时和用户取消控制 |
| 用户取消 | `Ctrl+C` 取消当前模型请求或工具，并停止后续循环；沿用现有再次 `Ctrl+C` 强制退出行为 |

次数上限同时约束下一批工具是否还能启动。例如默认配置下，第 50 次模型响应仍请求工具时，提示达到上限，不再执行这批工具，避免工具产生变更后没有剩余请求机会让模型读取结果。

如果最后一次允许的模型请求正常返回最终回答，则仍按正常结束处理。

## 已确认的终端显示

v0.5 使用普通终端输出，让用户能看到模型说明和工具进展：

- 模型正文继续流式写入 stdout；思考内容不作为正文显示。
- 工具名称、关键参数、执行状态和结果摘要写入 stderr。
- 文件工具主要显示路径和操作摘要，Bash 显示执行命令。
- 失败时显示有助于理解原因的错误输出；较长内容提供有限预览和明确截断提示。
- 终端预览不改变传给模型的工具结果，后者沿用工具层自身的输出限制。
- 本版不实现 TUI，具体布局与交互在 v0.6 完善。

示例：

```text
我先查看入口文件。

[read] cmd/johnny/main.go
[成功] 已读取 120 行

接下来修改输出逻辑。

[edit] cmd/johnny/main.go
[成功] 替换 1 处

[bash] go test ./...
[失败] 退出码 1
……错误输出摘要……

测试发现了一个问题，我继续修复。
```

以上是显示形式示例，不是已经发生的执行记录。

## 基础会话记录：仅用于排查

**本版会话记录是本次任务的诊断材料，不承担记忆处理功能。**

### 保存位置与格式

使用本地 JSONL 文件，每行一条记录：

```text
~/.johnny/sessions/<会话ID>.jsonl
```

从任意目录启动时，记录保存在统一位置，不在每个工作项目中创建日志目录。

### 记录内容

- 会话 ID、开始时间、工作目录、协议和模型名等基本信息。
- 用户输入、完整 assistant 消息、工具结果，以及模型层续接所需的 Replay 数据。
- 工具开始、成功或失败等执行事件，以及与调用 ID 对应的参数和结果。
- 每次模型请求的结束原因、可用的 token 用量，以及每轮任务的停止原因。`user_turn` 标识用户轮次，`turn` 标识该轮内的模型请求序号；一个交互会话使用一个 JSONL 文件。

会话元数据不包含 API Key 或进程环境变量配置。流式文本不逐个片段落盘，主要保存完整消息和执行事件；任务取消或失败时保留已有记录，并记录中断状态。

### 与当前任务历史、长期记忆的区别

| 内容 | v0.5 行为 |
| --- | --- |
| 同一进程的会话历史 | 保留在内存中，用于本轮工具结果回传，以及下一轮用户输入的上下文 |
| 落盘 JSONL 记录 | 供开发者查看执行顺序、结果和停止原因，排查问题 |
| 自动读取旧任务记录 | 不实现，不把旧记录注入新任务 |
| 从记录提取记忆、摘要或语义检索 | 不实现 |
| 跨会话记忆更新、纠错、删除 | 留到 v0.11 长期记忆单独设计 |
| 从记录恢复未完成会话 | 本版不实现，后续另行讨论 |

用户明确：基础会话记录暂时只方便排查，不做记忆处理。任务完成后，记录不会跨会话影响模型行为。

## 与前后版本的边界

- **v0.3：** 继续使用统一 `Client.Stream`、消息、工具定义、调用、结果和结束原因，不在 Loop 内按供应商另写业务循环。
- **v0.4：** 通过 `Registry.Execute` 调用 `bash`、`read`、`edit`、`write`，沿用工作目录、工具输出限制和直接执行模式。
- **v0.5：** 负责本轮消息历史、模型请求与工具执行的衔接、继续或结束判断、执行边界、终端过程显示、基础多轮上下文和调试记录。
- **v0.6：** 在基础多轮对话与工具循环上建设 TUI，完善显示、输入和中断等交互细节。
- **v0.7：** 统一建设权限、确认和隔离机制；v0.5 沿用当前直接执行方式。
- **v0.8、v0.9：** 分别接入 Skills 与 MCP。
- **v0.10：** 建设上下文治理，本版不做自动压缩或预算管理。
- **v0.11：** 建设长期记忆；本版不读取、提取、检索或更新跨会话记忆。
- **v0.12：** 建设 SubAgent；本版不引入代理委派或并行代理。

| 场景 | 检查内容 |
| --- | --- |
| 普通问答 | 无需工具时，正常流式回复并结束本轮；交互模式继续等待输入 |

| 模型响应截断或失败 | 不执行不完整响应中的工具调用，不把中断当作正常完成 |
| 三种模型协议 | 分别完成工具定义、调用、执行结果回传和后续模型请求的完整链路 |
| 基础会话记录 | 能通过同一文件还原多轮消息和工具事件顺序、结果及停止原因；新进程不加载旧记录 |

真实模型用于验证完整任务体验；多个调用、截断、次数上限等需要精确触发的情况，使用本地模拟模型做自动化验证。

验收既检查最终回答，也核对实际文件变更、命令输出和执行记录。联调发现工具问题时回到 v0.4 工具层修复，再分别确认两版结果。

## 实现记录

- `internal/agent/types.go`：循环选项、默认限制、有序事件、任务结果和停止状态。
- `internal/agent/agent.go`：模型请求、完整消息历史、工具串行执行和结果回传、结束判断、请求次数及取消控制。每次模型请求单独创建并释放超时 context，工具使用父任务 context。
- `internal/session/session.go`：仅用于排查的 JSONL 记录，随机唯一会话 ID、独占创建、目录 0700 和文件 0600；不读取旧文件。
- `cmd/johnny/main.go`：版本 `0.5.0`、`--max-turns`、当前工作目录工具运行时、流式正文、工具状态与有限预览、日志失败降级和退出码。System 提示包含工作目录，要求通过实际工具结果确认操作。
- `scripts/install_test.go`：隔离安装源码包含 CLI 和 config/model/tool/agent/session 各包的非测试 Go 文件，验证跨目录运行与 HOME 下的记录位置。

### 已落实的行为细节

- 工具结果预览最多 20 行、4096 字节；关键参数预览最多 256 字节。控制字符转为可见转义，超出时明确标记截断；模型得到的工具结果不因终端预览而改变。
- stdout 或任务进度 stderr 写入失败时保留错误链并停止后续调度；工具开始状态无法输出时不启动该工具。
- 会话记录创建、写入或关闭失败时只警告一次，降级继续原任务。写入失败后关闭记录器并停止后续写入，不重新执行工具。
- 日志用 `arguments_raw` 字符串保存原始工具参数；截断响应中的不完整 JSON 也能记录，不会因为诊断序列化失败覆盖原任务错误。正常 Replay 数据完整保留；非法 Replay 原文可作为诊断字符串保存。
- 正常响应的完整消息与续接数据保留在当前任务内存历史中；日志格式只服务于排查，不提供历史恢复 API。
- Anthropic 适配器遇到空工具结果时省略可选的 `content` 字段，避免发送服务不接受的空 text 块。通用工具结果仍保留原始空字符串，静默成功命令和空文件读取可以继续模型请求。

## 多轮交互补充实现（2026-10-20）

- `agent.NewConversation` 创建当前进程内的会话，连续调用其 `Run` 时复用完整用户、assistant、工具结果与 Replay 历史；原 `agent.Run` 继续作为一次性入口。
- 每轮用户输入独立计算模型请求预算，会话中的调用 ID 持续去重。截断或失败响应只保留在诊断记录，不把残缺参数加入可续接历史。
- 合法工具批被请求上限或中断停止时，保留实际执行结果，未执行项补明确的错误结果与 `tool_skipped` 事件，不重跑工具、不留下未配对调用 ID。
- CLI 无参数模式使用同一个输入缓冲器，避免预读后丢失下一行；空行不请求，完整 `/exit` 和 EOF 正常退出。带任务参数只执行一次且不读 stdin。
- 普通模型错误结束本轮后继续等待，终端输入输出失败或进程取消则退出。当前 Ctrl+C 沿用取消并退出进程的行为。
- 一个交互会话只在第一条有效输入开始执行时创建日志；用户轮次通过 `user_turn` 区分。没有新增长期记忆、会话恢复、TUI 或其他 slash 命令。
