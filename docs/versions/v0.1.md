# v0.1 · 模型调用

**状态：基础问答已通过用户初步验收；命令安装与启动体验在 v0.2 完善。**

[返回总体路线图](../johnny-code-roadmap.md)

## 目标

打通“终端输入 → 模型服务 → 流式终端输出”，使用真实模型服务完成一次文本问答，并理解配置加载、请求发送、响应处理和程序退出的完整流程。

## 已确认事项

- 项目使用 **Go** 构建。
- v0.1 聚焦最小模型调用链路：输入一段话，获得真实模型回复。
- 使用中转站提供的 **DeepSeek** 模型；Key、URL 和模型名称由用户在本机填写。
- 回复采用 **流式输出**，收到正文片段后立即显示。
- 每个版本的具体讨论、方案与验收单独记录。
- 本项目不使用面向百度内部研发流程的 `dev-flow` 技能。

## 本版方案

### 使用方式

在项目根目录配置 `.env`，然后执行：

```sh
go run ./cmd/johnny "你好，请简单介绍一下你自己"
```

程序进行一次文本请求，逐段输出正文并退出。`Ctrl+C` 可以取消请求。

后续由 v0.2 引入全局 `johnny` 命令，v0.6 引入 TUI。

### 模型协议与客户端

用户提供的配置截图明确采用 **Anthropic 原生 Messages** 协议，以及 `ANTHROPIC_AUTH_TOKEN` 对应的 Bearer Token 认证。客户端据此使用官方 `anthropic-sdk-go` SDK。

请求发送到配置的服务根地址下的 `v1/messages` 路径，并启用流式响应。模型名称原样使用中转站提供的标识。不会混用宿主环境中其他应用的 Anthropic 凭据。

v0.3 再结合实际使用经验建设统一模型接口。

### 工程结构

```text
Johnny-Code/
├── cmd/johnny/main.go
├── internal/
│   ├── config/
│   │   ├── config.go
│   │   └── config_test.go
│   └── model/
│       ├── client.go
│       └── client_test.go
├── .env.example
├── go.mod
├── go.sum
└── README.md
```

- `main.go`：读取输入、组织调用、输出状态，并处理取消和退出码。
- `config.go`：读取 `.env` 与环境变量，检查必要配置和 API 根地址。
- `client.go`：通过 SDK 发送流式请求，逐段输出正文，检查请求是否正常结束。
- 测试：通过本地模拟服务验证流式行为、错误和取消，无需真实 Key。

### 配置

在项目根目录的 `.env` 中填写：

```dotenv
JOHNNY_API_KEY=你的中转站Token
JOHNNY_BASE_URL=https://你的中转站地址
JOHNNY_MODEL=中转站提供的模型名称
```

`JOHNNY_API_KEY` 作为 Bearer Token 使用。`JOHNNY_BASE_URL` 填写服务根地址，SDK 会追加 `v1/messages`。例如接口为 `https://relay.example/gateway/v1/messages`，这里填写 `https://relay.example/gateway`。

环境变量优先于 `.env` 中的同名配置。配置加载使用 `godotenv`，本地 `.env` 被 Git 忽略，仓库只保留模板。请求沿用标准 HTTP 代理环境变量。

### 输出与错误处理

- 模型正文写入标准输出，等待提示与错误写入标准错误。
- 服务单独返回的推理字段不作为正文显示。
- 请求总时限为 5 分钟，回复上限为 4096 个输出 token，取消后结束连接。
- 通过 `message_stop` 与 `stop_reason` 判断响应是否完整；输出达到上限等情况会明确报错。
- v0.1 每次运行发送一次请求，关闭 SDK 的自动重试。
- 对缺失配置、错误地址、HTTP 错误、流内服务错误、连接失败和空回复给出明确提示；错误提示不回显服务端原始载荷。
- 首次取消后恢复默认信号处理，必要时再次 `Ctrl+C` 可以强制结束进程。
- 中途断流或模型以非正常原因结束时返回错误，保留已显示的部分内容。
- 正常退出码为 0，失败为 1，取消为 130；通过 `go run` 启动时，退出状态由 Go 工具转述。

## 验收标准

### 本地自动验证

- `.env` 可读取，环境变量可以覆盖同名配置。
- 请求保留中转站路径前缀，正确传递 Key、模型名称、用户输入与流式选项。
- 服务端收到客户端已显示首段内容的通知后才继续发送后续内容，以此验证即时输出。
- HTTP 错误、提前断流与不完整回复能够被识别。
- 取消请求可以终止正在读取的流。
- Go 测试、竞态检查、静态检查与编译通过。

### 真实服务验收

已按用户提供的配置完成真实流式请求验证。用户随后自行运行中文问答并确认能够正常回复，基础功能初步验收成功。取消、断流等边界场景已有本地自动验证；用户尚未单独反馈这些场景的人工验收结果。

## 已知限制与后续衔接

`go run` 每次启动都经过 Go 的构建流程，再运行临时可执行文件。构建缓存可以复用依赖等产物，但仍可能存在编译、链接或构建检查开销，不能将启动等待全部归因为每次完整重编译。

v0.2 将通过构建、安装后的 `johnny` 可执行文件直接启动，后续仅在源码更新后重新构建或安装。模型首段输出前的网络与推理等待另行观察。
