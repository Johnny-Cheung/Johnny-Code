# v0.6 · TUI

**状态：已实现并完成自动化、PTY 与安装验证，待用户验收。**

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

在 v0.5 已完成的 Agent Loop 和同进程多轮上下文之上，提供一个简洁、清楚、接近 Claude Code 使用体验的终端交互界面。TUI 的职责是改善输入、过程显示和中断体验，不重新实现模型调用、工具执行或 Agent Loop。

本版的技术实现继续使用 Go。具体终端事件处理、布局、渲染和输入编辑由实现负责；用户主要从使用场景和可见行为验收。

## 已确认的交互范围

### 启动入口

- `johnny "任务"` 继续执行一个任务后退出，保持普通文本输出和原有退出码。
- 交互模式 `johnny` 在标准输入、标准输出均为真实终端时使用 TUI。
- 管道、重定向、测试替身以及其他非终端输入输出继续使用 v0.5 的普通行模式，不输出 ANSI 控制序列。
- 不通过打开 `/dev/tty` 绕过调用方提供的输入；重定向和管道语义保持可预测。

### 输入

- `Enter` 发送当前输入。
- `Alt+Enter` 插入换行，不发送任务。
- 多行粘贴保留换行；粘贴本身不发送，用户主动按 Enter 后才提交。
- 支持基本输入编辑，包括左右移动、Home/End、删除和必要的多行光标移动。
- 上下方向键浏览当前进程内已经发送过的输入；不读取旧 JSONL，不跨进程保存输入历史。
- 空输入按 `Ctrl+D` 正常退出。
- `/exit` 作为完整输入时本地正常退出，不请求模型、不执行工具。

### 执行与取消

- 同一时间只执行一个用户任务，不排队接收新任务。
- 任务运行期间继续显示模型正文和工具执行进展。
- 任务运行期间按 `Ctrl+C` 只取消当前这一轮；等待当前模型请求或工具清理完成后，回到输入状态。
- 取消后保留已经合法加入的对话历史、工具结果和已经发生的文件修改；下一轮可以继续处理。
- 空闲时按 `Ctrl+C` 清空当前输入但不退出会话；输入为空时仍保持等待。
- 退出或终端错误前，等待正在运行的 Agent 任务真正结束，避免后台请求或工具继续运行。

## 界面方向

采用随终端向下追加的对话式界面，保留终端原生滚动、选择和复制能力，而不是建立复杂的全屏历史面板。动态区域主要用于当前输入和当前执行状态；已经完成的模型正文和工具摘要提交到终端 scrollback，避免固定高度窗口遮挡长任务输出。

启动或空闲时显示当前模型和工作目录。对话中区分用户输入、模型正文和工具状态；工具状态包含工具名、路径或命令等有限关键参数、执行中、成功、失败和取消结果。工具结果只显示有限摘要，展示截断不改变回传模型的原始结果。

外部模型文本、工具参数和结果中的控制字符必须以安全可见形式显示，不直接改变终端状态。界面需要适应窗口大小变化和中文文本，不能因窗口较窄或内容较长而丢失已完成输出。

## 技术方案

- 使用 Bubble Tea 处理终端输入、窗口变化和 UI 状态更新。
- 使用 Bubbles textarea 提供多行输入、光标移动和粘贴处理。
- 使用 Lip Gloss 统一标题、状态和工具摘要的轻量样式。
- UI 线程与 Agent 工作线程分离，通过有序消息和背压传递事件；渲染失败必须同步阻止后续工具副作用，沿用 v0.5 的观察者错误契约。
- 每轮任务使用独立取消 context；Agent 继续复用 `internal/agent.Conversation.Run`、完整事件和既有历史修复，不在 TUI 层复制循环逻辑。
- 会话 JSONL 继续由现有 `sessionLogger` 延迟创建和同步记录；TUI 不读取旧记录、不增加记忆处理。
- 终端模式只在真实 TTY 的交互入口启用；参数任务和非 TTY 路径保留原有纯文本 renderer，保证脚本和管道兼容。

## 验收场景

1. **基础对话**：启动 `johnny`，输入普通问题，观察流式回复，完成后仍回到输入区域；继续输入第二个问题，能够携带同一会话上下文。
2. **多行任务**：使用 `Alt+Enter` 或粘贴输入包含多行代码的任务；确认粘贴不会自动提交，按 Enter 后完整发送。
3. **工具任务**：让模型使用 `write`、`read`、`edit`、`bash` 完成文件创建、读取、修改和运行检查；工具名、关键参数、成功/失败和摘要清楚可读，长结果不淹没界面。
4. **输入历史**：完成多条任务后使用上下键找回之前的输入，修改后重新发送；当前进程结束后历史不再保留。
5. **取消后继续**：模型请求或 Bash 执行期间按 Ctrl+C；确认本轮停止、终端回到输入状态、已完成副作用保留，下一轮能够继续，且没有并发执行旧任务。
6. **退出与恢复**：`/exit`、空输入 Ctrl+D、SIGTERM 和终端关闭都能结束；退出后终端不残留 raw 模式或 echo 关闭状态。
7. **兼容入口**：参数模式不读取 stdin；输入或输出被管道/重定向时不输出 ANSI，普通文本行为、请求次数、日志位置和退出码保持 v0.5 契约。
8. **窗口变化**：调整终端大小不会 panic，中文、长回复和长工具输出仍能继续查看和复制。

### 生命周期与显示细节

- UI 与 Agent 通过无缓冲事件通道形成背压，完整消息历史、Replay 和原始工具结果不进入 UI 消息队列。
- 完整的 Markdown 块和工具摘要通过串行 print 消息进入终端 scrollback；动态区域只保留当前未完成块的原文预览、输入与状态，中文按显示宽度处理。
- 工具开始消息附带内部零宽写入标记。标记在底层终端写出前移除，只有实际写成功才确认观察者并开始工具；短写或错误会取消会话并阻止该工具执行。
- 取消后的工具结果和终态仍可以显示；整个界面退出时取消并等待全部任务，之后才由 CLI 关闭日志。
- 使用静态输入光标，避免输入组件的异步闪烁闭包与状态替换产生数据竞争；输入样式继承终端前景/背景，使用固定中灰提示色。
- 仅真实文件输入保留终端文件接口，普通 Reader 保持普通读取器语义，避免 Linux 对无效文件描述符注册 epoll。窗口变化只更新布局，尾行随下一次有序事件提交，避免额外空行或独立 print 命令引起顺序竞争。工具摘要和日志提示只在最终打印处处理末尾换行。
- 输入换行也支持 `Ctrl+J`。粘贴统一 CRLF/CR 为 LF；受输入组件上限约束，单次输入最多 10000 行，超限粘贴整体拒绝并提示，不静默丢弃尾部。
- 文件工具成功时展示简短摘要；失败和命令输出使用现有 20 行/4096 字节预览限制。展示不改变回传模型的内容。

用户反馈：输入中文拼音时，组合文本先显示在输入框下横线和状态提示的位置，提交汉字后才回到输入框。

- **效果：** 拼音组合文本和候选窗口应跟随输入框中的实际文字位置，而不是落在状态栏。
- **验证：** 增加了光标坐标测试（上边框之后、提示符之后、中文输入后位于文字末尾）和任务执行时隐藏输入光标的测试；真实 PTY 原始输出中确认空闲时界面会从状态行上移两行、移动到输入列并显示真实光标，输入法组合文本使用该位置。升级到 Bubble Tea v2 后，原有 PTY 输入、多行粘贴、四工具、Markdown、窗口变化、取消后继续、SIGTERM 与终端恢复场景继续通过；全量 race 测试、静态检查和构建检查通过。

## 当前界面范围

- Markdown 按块渲染，使用固定深色终端样式；没有主题切换、富文本图片或工具折叠面板。超长代码块在围栏结束或本轮结束时一次性提交，接收期间显示原文预览。

## 手动验收入口

在测试目录运行 `johnny`：

1. 输入“创建一个输出 hello 的 main.go，并读取确认”，观察工具进展和流式回复。
2. 下一轮输入“把刚才的输出改成 world，并运行检查”，确认沿用上下文。
3. 使用 Alt+Enter/Ctrl+J 或粘贴多行任务，确认主动按 Enter 才提交；使用上下键编辑之前的任务。
