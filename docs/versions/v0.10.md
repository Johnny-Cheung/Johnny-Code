# v0.10 · 上下文治理

**状态：已实现（2026-10-25），等待联合验收。** 已落地请求视图、32 KiB 工具结果预览、bash 大输出存档、轮级压缩、90%/95% 极限态触发、九段式摘要、失败降级、thrashing 熔断、`/context` 和 `/compact`；自动化测试、竞态测试、vet 和构建验证通过，真实长任务体验仍需联合验收。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

管理每一次模型请求实际携带的上下文，控制工具输出和历史增长，并在接近模型窗口时提供可解释的降级方式。

v0.10 的核心不是“把历史压缩得越小越好”，而是：

- 正常情况下，只追加、不改旧前缀，尽量保持前缀缓存命中；
- 新进入上下文的大载荷在入口处一次性治理；
- 接近窗口上限时，才允许整段改写或摘要；
- 用户能够看到上下文占用、截断和压缩行为；
- 所有请求仍然通过现有消息校验和权限体系。

v0.10 不负责跨会话记忆、会话恢复、MCP 或 SubAgent。

权限模型自 2026-10-25 起后置：开发阶段直接运行 `johnny` 默认进入 `allow`，`--permission-mode default` 和 `read-only` 保留为显式选项。本版上下文治理不依赖审批交互，但保留这两种模式作为可选路径。

## 已对齐术语

| 术语 | 定义 | 现有代码/记录对应 |
| --- | --- | --- |
| **会话** | 从终端启动 `johnny` 到退出 | 一个进程、一个 JSONL 文件 |
| **轮** | 一次用户任务，从提交到本轮结束 | `Conversation.Run`、`user_turn` |
| **请求** | 一次模型调用：输入上下文，模型输出结果 | `Client.Stream`、`turn` |

关系：

```text
一个会话
  └── 多轮
        └── 每轮 1..N 次请求
```

约定：

- 一轮可以包含多次请求；模型调用工具不结束本轮，只有最终答复、取消、失败或达到上限才结束。
- 本地命令不构成一轮，例如 `/skills`、`/permissions`、`/context`。
- 异常结束同样算一轮；正常结束以模型不再调用工具的最终输出为标志。
- 摘要请求也是模型请求，但属于“压缩请求”，不是任务轮次里的普通请求；不计入当前轮的 `MaxTurns`。

## 三层上下文

| 层级 | 内容 | 是否持续增长 | 治理方式 |
| --- | --- | --- | --- |
| **完整历史** | 全部 `messages`、工具调用与结果、Replay 数据 | 是 | 作为事实来源保留，正常态不压缩 |
| **请求视图** | 本次真正发给模型的 system、tools、消息子集、输出预留 | 每次请求生成 | v0.10 的核心治理对象 |
| **展示视图** | 终端对话、工具进展、本地命令输出、提示信息 | 是 | 不做上下文压缩，只负责如实展示 |

### 三层之间的关系

- 完整历史是事实来源，保留完整消息和工具结果。
- 请求视图是完整历史经过治理后的投影，每次请求可以不同，但不得写回完整历史。
- 展示视图是完整历史加运行时事件的投影；它不需要被压缩，但需要显示压缩和截断提示。
- 请求视图必须继续通过现有请求校验：不能出现悬空工具调用、孤立工具结果或错误的 Replay 来源。
- 工具结果可以有三层表示：完整历史保存完整结果，请求视图保存模型可见的截断结果，展示视图保存预览或折叠摘要。
- 模型摘要属于请求视图状态，不属于完整历史；摘要不改变原始对话。

### 完整历史的已知边界

v0.10 不压缩完整历史，因此以下问题仍然存在：

- 进程内存会随会话增长；
- JSONL 会随会话增长；
- 超长会话最终可能影响性能和磁盘。

这些是运行层问题，不属于本版的请求级上下文治理；在文档中保留为已知限制，后续版本再处理。

## 两种压缩场景

### 请求级正常态（基础策略已确认）

触发条件：上下文还没有接近模型窗口上限。

目标：

- 控制新进入上下文的大工具输出和大工具参数；
- 保持系统提示、工具定义和旧消息字节稳定；
- 尽量保持服务端前缀缓存命中；
- 不为节省空间而回头改写旧消息。

原则：

- **只追加，不改写旧消息。** 已发送过的前缀保持原样。
- **新载荷在进入上下文时一次性治理。** 截断策略固定，不随当前剩余预算变化。
- **系统提示和工具定义保持稳定。** 不把动态用量、压缩状态写入系统提示；工具顺序和 Schema 字节保持稳定。
- **记录缓存指标。** 使用 `Usage.CacheReadTokens` 和 `Usage.CacheWriteTokens` 验证前缀缓存是否命中。

正常态不解决累计增长；累计到阈值后进入极限态。

### 极限态（触发机制和预算口径已确认）

预算口径：

- `W`：模型上下文窗口，通过 `JOHNNY_CONTEXT_WINDOW` 覆盖；默认 1,000,000。
- `O`：实际的每次请求最大输出 token，默认 4096，可通过 `JOHNNY_MAX_OUTPUT_TOKENS` 覆盖。
- `S`：安全余量，固定为 `max(16,384, W × 5%)`。
- `U = W - O - S`：可用输入预算。

触发条件按 `U` 计算：

- **轮开始前**：加入本轮用户消息后、第一次请求前，估计达到 90% U，触发自动压缩；
- **每次请求前**：估计达到 95% U，触发自动压缩；
- 保留当前轮 + 最近 5 个已完成轮次；
- 更早轮次使用模型摘要；摘要失败时降级为确定性裁剪；
- 不设置 75% 固定压缩目标；压缩到触发线以下即可，实际结果可能远低于触发线；
- 允许一次前缀缓存失效。

摘要流程见“极限态摘要流程”；最近 5 轮本身过大、当前轮本身过大等边界在实现前继续确认。

## 已确认策略（2026-10-25）

### 请求级

- 单次工具结果超过 32 KiB 时，请求视图最多保留 32 KiB 预览；完整结果落盘，模型可以再次读取。
- 关键大文件可以通过分页读取看全；非关键大文件不会长期把完整内容放进上下文。
- 32 KiB 是模型可见预览的上限，不是完整输出的上限。
- 预览上限固定，不随当前剩余预算变化；截断和落盘发生在工具结果进入上下文之前。
- 最终分配：bash 保留开头 24 KiB 和结尾 8 KiB；`read` 保留开头 32 KiB 并给出下一次 `offset`；其他工具保留开头 32 KiB。
- 轮内预览另设累计预算：当前轮所有工具预览累计达到 128 KiB 后，后续大结果只保留 8 KiB 小预览和存档/续读路径。该预算不改变单次 32 KiB 上限，只限制轮内总量。

### 工具输出存档

- 位置：`<workdir>/.johnny/artifacts/<session-id>/`。
- 命名：按轮次和调用序号生成，例如 `turn-2/call-3-bash.log`；不把命令原文写进文件名。
- 模型看到相对工作目录的路径，可以直接用 `read` 再次读取，不新增 `read_artifact` 工具。
- 目录权限 0700，文件权限 0600；第一次需要落盘时才创建。
- 只为 `bash` 类的大输出落盘；`read` 使用原文件路径和 offset 范围，`skill` 使用 `SKILL.md` 路径，`write` / `edit` 保留目标文件路径和状态。
- 存档内容用于模型再次读取时清理 ANSI 和非法 UTF-8；JSONL 保留原始完整结果。
- JSONL 同时记录完整工具结果和存档路径，避免存档清理后失去排查信息。
- 正常退出时删除当前会话的存档目录；异常退出可能残留，后续可增加启动清理。
- 工作目录不可写或创建存档失败时，降级为只显示预览并给出警告，不阻断任务。
- `.johnny/artifacts` 应被 Git 忽略；本项目已通过 `.johnny/*` 忽略，其他工作目录如果不忽略应提示用户。
- 存档是完整历史的外部附件，不是会话记忆，也不是会话恢复来源。

### 轮级

- 每轮结束都评估，但只在节省显著时压缩。
- 只压缩刚结束的这一轮；更早轮次在正常态不重写，避免共同前缀不断缩短。
- 节省量判断的初始公式：
  - `original`：本轮工具结果的估算 token；
  - `compact`：压缩后记录的估算 token；
  - `saved = original - compact`；
  - 当 `saved >= 4096` 且 `saved >= original / 2` 时，整轮压缩。
- 压缩时整轮统一处理，不零散替换。
- 压缩记录保留工具名、状态、摘要、artifact 路径和小预览；小结果可以保留内容或摘要。
- 替换 `tool_result` 的内容，不删除消息本身；`tool_call` 和 `tool_result` 必须保持成对。
- 轮级压缩会改变刚结束这一轮的前缀，但更早的已压缩历史仍然是共同前缀，可以继续复用缓存。实际命中率用 `cache_read_tokens` 验证。

### 极限态摘要流程（已实现）

- 保留当前轮 + 最近 5 个已完成轮次；最近 5 轮不参与摘要。
- 摘要输入 = 上一次压缩的摘要 + 最近 5 轮之前的旧轮次；旧工具输出使用已压缩记录和存档路径，不重复喂原始大日志。
- 摘要请求是独立模型请求：禁止调用工具、单次请求完成、只输出文本；不占当前轮任务请求次数；有独立超时、输出上限和摘要事件记录。
- 摘要提示词采用九段式，并在 `<summary>` 开头增加“当前交互模式 / 等待用户决定”，同时带入“历史摘要”。
- 长期约束、禁止事项、已确认决策只增不减，尽量保留原文。
- 用户消息：安全/约束类保留原文，普通消息保留关键句，超长粘贴保留摘要 + 存档路径。
- 文件与代码：保留路径、修改目的和关键片段，不要求完整代码。
- 模型先输出 `<analysis>`，再输出 `<summary>`；运行时丢弃 analysis，只保留 summary。
- 摘要作为一条明确的合成 user 消息插入，并附 compact 边界；只保留最新摘要，旧摘要不堆叠；完整历史、JSONL 和工具输出存档继续保留。
- 摘要目标 2～4k token，硬上限 4096（当前 `O`）；优先保留长期约束、文件路径、错误、待办和当前状态。
- 摘要失败：先尝试重试或降级为确定性裁剪；降级后仍超过 95% U 则报 `context_exceeded`。
- Thrashing 保护：连续 3 次摘要失败，或 3 轮内 3 次快速回填时停止自动压缩；`/compact` 不受影响。
- 压缩开始、成功和失败在展示视图给出提示；摘要可通过 `/context` 查看，`/context` 显示压缩前后估算和缓存指标；TUI 中 `/compact` 后台执行并支持 `Ctrl+C`。

九段结构：

| 段 | 内容 |
| --- | --- |
| 1 | 用户请求、意图与长期约束 |
| 2 | 关键概念、方案与已确认决策 |
| 3 | 文件、代码与产物 |
| 4 | 错误、失败与修复 |
| 5 | 问题解决、验证与当前状态 |
| 6 | 用户消息原文 |
| 7 | 待办事项 |
| 8 | 摘要截止点的工作状态 |
| 9 | 与最近 5 轮的衔接 |

## 当前实现基线

以下是 v0.10 开始前的实际行为：

- `Conversation` 在内存中保存 `options`、`messages`、`seen` 和 `userTurn`，不读取旧日志。`internal/agent/agent.go:16`
- 每次请求发送完整的 `system`、`messages`、全部工具定义和 `MaxOutputTokens`，没有增量请求或服务端状态。`internal/agent/agent.go:103-106`
- 没有输入 token 预算、token 估算、裁剪、摘要或压缩；只有请求次数、请求超时和输出 token 上限。`internal/agent/types.go:12-30`
- 默认每个用户输入最多 50 次请求，每次请求 5 分钟超时，最大输出 4096 token。`internal/agent/types.go:12-15`、`cmd/johnny/main.go:182`
- 工具运行时默认每路输出 256 KiB；bash 的 stdout 和 stderr 各自 256 KiB。`internal/tool/runtime.go:12`、`internal/tool/bash.go:72`
- 工具结果和 assistant 消息会原样追加到历史；工具调用参数本身没有统一上限。`internal/agent/agent.go:147`、`internal/agent/agent.go:171`
- OpenAI Responses 的 `Replay.Data` 会随 assistant 轮次累积并重放。`internal/model/openai_responses.go:333`
- 模型 usage 只写入 JSONL，没有用于预算；TUI 不使用 usage 计算上下文占用。`internal/session/session.go:285`、`cmd/johnny/tui.go:94`
- Anthropic 的 `model_context_window_exceeded` 被映射为 `StopMaxTokens`，当前用户会看到“模型达到输出上限”。`internal/model/anthropic.go:190`、`internal/agent/types.go:46`
- JSONL 是只写诊断记录，不恢复会话，也不作为记忆。`internal/session/session.go:4`
- 请求校验要求工具调用和结果成对、消息角色合法、Replay 来源一致；任何上下文视图都必须满足这些约束。`internal/model/client.go:75-141`

## 请求级正常态：实现后的边界

1. **大 tool call 参数。** 工具调用参数超过 32 KiB 时，请求视图把它替换为包含工具名、大小和路径/命令前缀的 JSON 对象；完整参数仍保存在完整历史和 JSONL 中，工具按原始参数执行。
2. **Skill 正文。** 与普通工具结果一样按 32 KiB 预览；完整正文仍在本地 Skill 文件中，模型可以再次通过 `skill` 加载。
3. **用户输入和 assistant 文本。** 正常态不截断；极端情况下由极限态摘要或确定性裁剪处理旧轮次，当前用户输入本身过大时可能返回 `context_exceeded`。
4. **Replay 数据。** OpenAI Responses 的 `Replay.Data` 仍原样重放，本版不截断，避免破坏协议续接；这是已知的上下文增长来源。
5. **轮内预算。** 当前轮工具预览累计 128 KiB 后，后续大结果使用 8 KiB 小预览；这是轮级总量限制，不改变单次 32 KiB 上限。
6. **前缀缓存。** 本版不添加显式 `cache_control`；依赖服务端自动缓存，`/context` 显示最近请求的缓存读写，JSONL 保留 usage。
7. **工具结果清理。** 轮级压缩只处理刚结束的一轮；极限态先摘要，再确定性裁剪，再对可见工具结果做 512 字节应急压缩。
8. **完整历史。** 完整历史、JSONL 和工具输出存档不压缩；内存和 JSONL 随会话增长仍是已知运行层限制。

## 暂不做的事

- 不实现精确 tokenizer；使用保守估算，并用服务返回的 usage 校准。
- 不在正常态压缩完整历史。
- 不实现会话恢复或跨会话记忆；这些属于 v0.11。
- 不实现 MCP 或 SubAgent。
- 不增加 OS sandbox 或改变现有权限模式。
- 不继续投入权限模型；v0.7 验收与最终收口后置，最终收口放在 v0.12 之后。
- 不处理 JSONL 轮转、归档或会话大小上限；保留为已知运行层限制。
- 不在本版做 TUI 交互调优；只增加必要的上下文状态和提示。

## 验收场景

1. **大工具结果**：一次 bash/read 返回超过 32 KiB 时，请求视图只包含预览，完整结果落盘并可再次读取，标记信息清楚。
2. **前缀稳定**：正常态连续请求中，旧消息字节不变；工具输出截断发生在 append 边界，不随剩余预算变化。
3. **缓存指标**：`/context` 或 JSONL 能显示 `cache_read_tokens` 和 `cache_write_tokens`；连续请求可以看到缓存命中的变化。
4. **大 tool call 参数**：write/edit 的大参数在请求视图中被压缩，工具执行和文件结果仍然正确。
5. **校验完整性**：任何截断或替换后，请求仍通过工具调用/结果配对校验。
6. **接近阈值**：达到正常态阈值后，明确进入极限态讨论范围，不在正常态静默丢旧轮次。
7. **用户可见性**：用户可以通过 `/context` 看到 system、tools、消息、工具结果和输出预留的估算占用。
8. **轮级压缩**：每轮结束按节省量决定；只压缩刚结束的一轮；压缩记录保留状态、摘要和路径；`tool_call` / `tool_result` 保持成对；更早轮次不被重写。
9. **轮内预算**：当前轮工具预览总量超过 128 KiB 后，后续大结果只给小预览和路径，不回写旧消息。
10. **工具输出存档**：大输出保存在 `.johnny/artifacts/<session-id>/`，路径可再次读取；正常退出后清理；工作目录不可写时降级为预览。
11. **极限态触发**：轮开始前估计达到 90% U，或每次请求前达到 95% U 时触发压缩；保留当前轮 + 最近 5 个已完成轮次；不设 75% 固定目标，压缩后低于触发线即可。
12. **摘要请求独立**：摘要请求禁止工具、单次请求完成，不占当前轮任务请求次数；超时、输出和摘要事件单独记录。
13. **摘要结构与替换**：摘要包含九段、当前交互模式和历史摘要；作为合成 user 消息插入并带 compact 边界；只保留最新摘要；当前轮 + 最近 5 轮保留。
14. **失败与 thrashing**：摘要失败时降级为确定性裁剪；仍超限时报 `context_exceeded`；连续失败或快速回填时停止自动压缩。
15. **手动命令**：`/context` 显示预算、缓存、摘要和存档；`/compact` 在 TUI 后台执行并可取消，结果写回同一会话。
16. **配置覆盖**：`JOHNNY_CONTEXT_WINDOW` 和 `JOHNNY_MAX_OUTPUT_TOKENS` 生效，非法值在启动时明确报错。
