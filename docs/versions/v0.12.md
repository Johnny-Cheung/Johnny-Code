# v0.12 · SubAgent

**状态：讨论中（2026-10-27）。** 本文记录初版方案、边界和待确认事项，尚未进入实现，也不代表已经定稿。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

让主 Agent 能把一个边界清晰、可以独立完成的任务委派给子 Agent，并满足四件事：

- **独立上下文**：子 Agent 不继承主对话历史，只接收显式任务说明；
- **执行范围**：不同子 Agent 拥有不同工具集合和权限边界；
- **受控并行**：只并行真正独立的任务，限制数量，避免并发写入冲突；
- **取消与回收**：主任务取消时子任务一起停止，子任务只把最终结果交回主上下文。

SubAgent 不是新的权限层，也不是长期记忆。它只是把一次任务放进一个新的 Agent Loop 中执行。

## 与前后版本的边界

- 复用 v0.5 的 Agent Loop、v0.7 的权限模式、v0.8 的 Skill、v0.10 的上下文治理和 v0.11 的 AGENTS/记忆读取。
- 子 Agent 的完整过程不进入主上下文；主 Agent 只收到有大小上限的结果。
- 子 Agent 不写长期记忆、不修改用户 AGENTS、不触发轮末记忆审查。
- 子 Agent 只能使用当前会话已有的模型客户端，不新增模型配置。
- 子 Agent 不能继续创建子 Agent，v0.12 只允许一层。
- 子 Agent 在同一个工作目录中执行，v0.12 不引入 worktree 隔离。

## 建议方案

### 入口

新增一个模型工具 `task`，由主模型显式调用。它不是一个本地斜杠命令；用户仍然通过自然语言让主 Agent 决定是否委派。

参数使用任务数组，一次调用可以表达一个或多个独立任务：

```json
{
  "tasks": [
    {
      "agent": "explore",
      "description": "查清认证入口",
      "prompt": "只读调查认证流程。说明入口文件、关键函数和调用链，给出文件路径和行号。"
    },
    {
      "agent": "explore",
      "description": "检查测试布局",
      "prompt": "只读检查 tests 目录的结构和现有 mock 方式，给出可以复用的测试文件路径。"
    }
  ]
}
```

- `agent`：`explore` 或 `general`，必填。
- `description`：短标签，用于终端展示和子会话元数据。
- `prompt`：自包含任务说明；子 Agent 看不到父对话，必须包含目标、约束和期望输出。
- 一次最多 4 个任务；最多 3 个同时执行，超出的排队。
- 可并行任务放进同一个 `task` 调用；分成多次工具调用会按顺序执行。

选择“单次调用带任务数组”，而不是让模型在一次响应里发多个 `task` 调用，原因是不改动现有 Agent Loop 的工具串行执行逻辑，并行上限和结果合并都收敛在 `task` 工具内部。代价是模型需要学会把独立任务放进同一个数组。

### 代理类型

v0.12 只提供两个内置类型，不支持自定义 Agent 文件。

| 类型 | 工具范围 | 并行 | 典型用途 |
| --- | --- | --- | --- |
| `explore` | `read`、受限 `bash`、`skill`、只读 `memory` | 可并行 | 代码调查、定位入口、梳理调用链、查找测试 |
| `general` | `bash`、`read`、`write`、`edit`、`skill`、只读 `memory` | 串行 | 实现一个独立子任务、修复一组测试、生成一个模块 |

- `explore` 始终使用只读工具包装：不能写文件，`bash` 只允许 v0.7 的只读查询白名单，不进入审批。
- `general` 继承当前会话的权限模式：`allow` 直接执行，`default` 走审批，`read-only` 拒绝创建。
- 两种类型都没有 `remember`，也不能创建新的 `task`。
- 子 Agent 可以读取 AGENTS 和记忆索引，也可以调用只读 `memory` 工具，但不能写长期记忆。

### 独立上下文

子 Agent 启动时只获得：

1. 子 Agent 基础系统提示和类型说明；
2. 当前 Skill 元数据；
3. 用户 AGENTS、项目 AGENTS、用户记忆索引、项目记忆索引；
4. 父 Agent 写入的 `prompt`。

它不获得父对话消息、父工具结果或父摘要。父 Agent 必须把必要背景写进 `prompt`；子 Agent 需要更多信息时，用自己的工具读取。

子 Agent 拥有独立的上下文管理器和压缩流程，可以按 v0.10 的规则压缩自己的历史。它不参与父会话的摘要，也不会把子过程写入父上下文。

### 执行与并行

- 前台执行：父 Agent 调用 `task` 后等待结果，不提供后台运行。
- `explore` 可以并行；`general` 同一时刻只允许一个，避免多个子 Agent 同时改文件。
- 一次调用的任务按请求顺序返回结果，即使实际完成顺序不同。
- 单个子任务失败不影响同批其他任务；父 Agent 会看到每个任务的状态。
- 不自动重试失败任务。

并行边界是“独立任务”，不是“任何任务”。有依赖关系、会修改同一文件、需要共享中间结果的任务，应放在不同轮次或改由主 Agent 串行处理。

### 权限

- `task` 工具本身不是权限边界，子 Agent 的工具调用才受权限模式约束。
- `default` 模式下，`task` 调用本身直接通过；`general` 子 Agent 的写文件、命令执行仍然逐次审批。
- 子 Agent 不能提升权限，也不能切换权限模式。
- `read-only` 模式下只允许 `explore`；`general` 返回明确错误。
- 子 Agent 的审批沿用到父 TUI，原因中标注“子代理 general”；因为 general 串行，同一时刻只有一个子代理审批。
- 子 Agent 不写长期记忆，避免多个上下文并发写入和重复审查。

### 取消、超时与失败

- 父任务取消（`Ctrl+C`、信号或父 context 结束）时，所有子任务一起取消。
- 单个子任务默认最多 30 次模型请求、总时长 15 分钟；单次模型请求仍使用 5 分钟超时。
- 子任务超时、达到请求上限、模型失败或工具失败时，返回对应状态和已有文本，不拖垮父任务。
- 子任务不自动重试；父 Agent 可以缩小范围后重新委派。
- 子 Agent 的工具输出存档放在自己的会话命名空间下，子任务结束时清理。

### 结果回收

父上下文只接收“结果摘要”，不接收子 Agent 的完整消息和工具记录。

每个任务返回：

- 类型和描述；
- 状态：完成、取消、超时、请求上限、失败；
- 模型请求次数和耗时；
- 最终文本，单任务最多 8 KiB；单次调用合计最多 24 KiB，超出截断并提示。

单个任务失败时，仍然返回已有文本和错误原因。全部任务失败或参数校验失败时，整个 `task` 工具结果标记为错误；部分成功时保留成功结果，并在每个段落中标注状态。

主 Agent 负责综合结果，不直接复制子 Agent 的长文本；需要继续操作时，由主 Agent 或其他子 Agent 基于结果继续。

### 会话与诊断

- 父会话 JSONL 记录 `task` 的调用参数和最终合并结果。
- 每个子 Agent 使用独立 JSONL：`~/.johnny/sessions/<父会话ID>-sub-N.jsonl`，元数据包含父会话 ID、任务序号、类型和描述。
- 子 Agent 的完整工具过程只写入自己的 JSONL，不进入父上下文。
- 子 Agent 的工具输出存档使用自己的会话 ID，和父会话存档隔离。
- v0.12 不在 TUI 中嵌套展示子 Agent 的流式过程；只显示一条 `task` 工具进展和最终结果。需要排查时查看子会话 JSONL。

## 工具与命令

模型工具从 7 个增加到 8 个：

1. `bash`
2. `read`
3. `write`
4. `edit`
5. `skill`
6. `memory`
7. `remember`
8. `task`

子 Agent 的工具集合：

- `explore`：`read`、受限 `bash`、`skill`、`memory`；
- `general`：`bash`、`read`、`write`、`edit`、`skill`、`memory`。

v0.12 不新增本地斜杠命令。`task` 只由模型调用，TUI 斜杠菜单保持不变。

## 暂不做

- 自定义 Agent 文件（`.johnny/agents/*.md`）和角色配置；
- 后台子 Agent、完成后通知、恢复和重新接续；
- 多层嵌套子 Agent；
- worktree 隔离或独立工作目录；
- 子 Agent 独立模型选择；
- 子 Agent 写长期记忆或用户 AGENTS；
- 子 Agent 与用户直接交互、向用户提问；
- TUI 中嵌套流式展示子 Agent 过程；
- 自动重试、自动合并子 Agent 结果或自动拆分任务；
- 跨子 Agent 共享上下文或共享中间文件。

## 待确认

1. **并行入口**：采用单次 `task` 调用带 `tasks` 数组（当前建议），还是允许模型在一次响应中发多个 `task` 调用并由 Agent Loop 并行执行。
2. **子 Agent 类型**：v0.12 只做 `explore` / `general` 两个内置类型（当前建议），还是同时支持 `.johnny/agents/*.md` 自定义类型。
3. **子会话记录**：每个子 Agent 写独立 JSONL 并通过父会话 ID 关联（当前建议），还是只把子事件写入父 JSONL。
4. **general 并发**：`general` 串行（当前建议），还是允许并行并在结果中提示文件冲突风险。
5. **结果大小**：单任务 8 KiB、单次调用 24 KiB 是否合适；还是只返回更短摘要，详细内容让子 Agent 写入文件。

## 验收场景（草案）

1. **上下文隔离**：父对话中的临时信息没有出现在子 Agent 请求中；子 Agent 只能看到 `prompt`、AGENTS、记忆索引和 Skill 元数据。
2. **explore 只读**：`explore` 能读文件、搜索和总结；尝试写文件或执行非查询命令时被拒绝。
3. **general 权限**：`general` 在 `allow` 下修改文件；在 `default` 下触发父 TUI 审批；用户拒绝后子 Agent 如实报告阻塞。
4. **只读父会话**：父会话为 `read-only` 时，`explore` 可用，`general` 被拒绝。
5. **并行边界**：多个 `explore` 任务受并发上限控制；`general` 同时只运行一个。
6. **结果顺序**：并行任务完成顺序不同，父 Agent 收到的结果仍按请求顺序排列。
7. **单任务失败**：一个子任务失败，其他子任务完成，父 Agent 收到分任务状态，不丢失成功结果。
8. **取消**：父任务 `Ctrl+C` 后所有子任务停止，没有残留 Bash 进程；父轮次以取消结束。
9. **上限**：子任务达到请求上限或总超时后返回状态和已有文本；结果超过大小上限时截断并提示。
10. **无递归**：子 Agent 的工具集合中没有 `task` 和 `remember`；不能创建新的子 Agent。
11. **记忆边界**：子 Agent 可以 `memory search/read`，但不会写记忆、不改 AGENTS、不触发旁路审查。
12. **诊断记录**：父 JSONL 有 `task` 调用和合并结果；子 JSONL 可通过父会话 ID 找到，包含子 Agent 的完整过程。
13. **工具数量**：父模型工具为 8 个；斜杠菜单不变。
14. **TUI**：`task` 工具进展显示类型和任务描述；子 Agent 过程不混入父回答；结果可折叠查看。

## 实现入口（草案）

- `internal/subagent/`：子 Agent 类型、任务解析、并行调度、结果回收、子会话记录和提示词。
- `internal/tool/`：`task` 工具的注册与展示所需的最小接口；默认/只读模式允许 `task` 通过，由子 Agent 工具集合和权限模式约束实际能力。
- `internal/agent/`：复用现有 Agent Loop；不为 v0.12 的并行入口改动工具串行执行逻辑。
- `internal/session/`：子会话元数据增加父会话 ID、任务序号、类型和描述。
- `internal/contextview/`：子 Agent 使用独立会话 ID，复用现有存档命名空间。
- `cmd/johnny/main.go`：构建子 Agent 工具工厂、共享模型客户端、权限规则、审批 gate 和记忆上下文。
- `cmd/johnny/tui.go`、`cmd/johnny/main.go`：`task` 工具展示键和帮助文本。
