## 目标

完成安装后，在任意目录输入 `johnny` 即可启动程序。日常直接运行已经构建好的可执行文件，复用现有项目配置，并保持启动位置作为工作目录。

## 已明确的使用需求

- 全局启动命令为 `johnny`。
- 用户可以在终端的任意目录调用程序。
- v0.1 已经能够正常回复，用户反馈 `go run` 启动等待较长，该体验在本版完善。
- 本版沿用单轮文本问答和流式输出，后续通过同一入口接入 Agent 和 TUI。
- 无参数运行 `johnny` 时采用单轮模式：显示输入提示，读取一个问题，流式回复完成后退出；每次运行处理一个独立问题。
- 现有源码项目根目录的 `.env` 已配置完成，原位复用，不迁移、不复制，也不要求用户重新填写。

## 当前代码与问题

- `cmd/johnny/main.go` 将参数拼成问题；没有参数时提示用法并退出，尚无帮助和版本入口。
- `internal/config/config.go` 从当前目录的 `.env` 读取配置，进入其他项目后需要明确定位到原有配置文件。
- 目前主要通过 `go run` 启动，日常使用仍需经过 Go 工具的构建和启动流程。

## 方案草案

以下为当前建议，尚未全部确认；进入实现前根据讨论结果收敛。

### 1. 用一个脚本完成安装和更新

建议提供以下安装入口，在源码目录执行：

```sh
./scripts/install.sh
```

该脚本是待实现的方案。内部使用 Go 构建、安装可执行文件，并自动记录现有项目 `.env` 的位置和构建版本信息。记录的是配置文件路径，配置内容仍在原文件中。

安装目标遵循 Go 的标准规则：优先使用 `GOBIN`；未设置时使用 `GOPATH/bin`。当前开发机未设置 `GOBIN`，默认目标为 `~/go/bin/johnny`。

安装过程检查目标目录是否在 `PATH` 中。首次安装时按当前 shell 补齐必要的路径配置，说明所改文件，避免重复写入；在新终端中验证命令可用。具体 shell 配置文件在实现时检查现有内容后确定。

更新源码后重新运行同一个安装脚本，成功构建后更新可执行文件。已有配置保持原位和原内容。需要回退程序时，在对应源码版本重新安装。

日常运行 `johnny` 时直接执行已安装的二进制，安装脚本只在安装和更新时运行。

### 2. 原位复用已有配置

用户确认，当前源码项目根目录的 `.env` 已经配置完成且真实调用成功。v0.2 原位复用这份文件，保持其位置、内容和现有读取优先级，不新建配置目录、不迁移或复制配置，也不要求用户重新填写。

全局命令从任意工作目录启动时，都需要定位到这份已有的项目配置。配置文件位置的定位由安装流程内部处理；用户无需额外配置路径，程序也不应通过切换工作目录来寻找 `.env`。

凭据继续只保留在被 Git 忽略的现有 `.env` 中，安装程序时只记录文件位置，不将配置值编译进可执行文件。

### 3. 保留工作目录

程序安装位置、配置位置和工作目录分别管理：

- 安装目录负责提供 `johnny` 命令。
- 源码项目根目录的 `.env` 继续保存现有模型配置。
- 终端当前目录作为本次工作目录。

启动时不切换到源码目录或安装目录。未来文件工具和命令执行可以继续使用同一工作目录约定。

### 4. 完善最小命令交互

建议支持：

```sh
johnny "你好，请介绍一下 Go 语言"
johnny
johnny --help
johnny --version
```

- 带问题参数：沿用现有行为，流式输出一次回复后退出。
- 无参数：已确认显示简短提示并读取一个问题，流式输出后退出，与当前单轮模型调用能力保持一致。
- `--help`：展示两种问答用法、帮助与版本选项、取消方式和现有配置文件的位置。
- `--version`：建议展示版本号和构建时的 Git 短提交号，方便确认安装和更新结果；若构建时包含未提交改动，则加以标识。

帮助和版本查询应在加载模型配置之前处理，不访问模型服务。输入、取消和退出行为保持清楚。

本版建议使用 Go 标准库处理这几个入口，随着命令结构复杂度再评估额外 CLI 框架。

## 本版涉及的主要位置

- `cmd/johnny/main.go`：参数解析、无参数输入、帮助、版本及启动提示。
- `internal/config/`：跨目录定位已有配置，保留现有读取优先级与校验逻辑。
- `scripts/install.sh`：构建和安装可执行文件，自动记录配置文件位置及构建信息，检查并处理 `PATH`。
- `README.md`：安装、更新与日常运行说明。
- 对应测试：帮助和版本、跨目录复用已有配置、输入与退出行为。

## 验收方向草案

1. 安装一次后，在新的终端会话中可以直接找到并运行 `johnny`。
2. 在两个不同目录启动，均能读取原有源码项目中的同一份 `.env`，工作目录分别对应启动位置。
3. 连续启动直接运行已安装的可执行文件，无需执行 `go run` 或重新构建。
4. 带参数与无参数启动均能完成单轮问答和流式输出；无参数模式收到一次回复后退出，不继续等待下一次提问。
5. 没有可用模型配置时，`--help` 和 `--version` 仍能正常工作且不访问模型服务。
6. 更新可执行文件后版本信息正确，现有 `.env` 的位置和内容不变，无需用户重复配置。

启动验收分别观察本地进程启动耗时和模型首段响应等待。Go 构建缓存可以减少 `go run` 的部分开销，安装后的命令直接跳过构建入口；网络和模型推理耗时独立判断。
