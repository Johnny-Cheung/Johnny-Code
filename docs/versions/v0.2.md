## 目标

完成安装后，在任意目录输入 `johnny` 即可启动程序。日常直接运行已经构建好的可执行文件，复用用户级配置，并保持启动位置作为工作目录。

## 已明确的使用需求

- 全局启动命令为 `johnny`。
- 用户可以在终端的任意目录调用程序。
- v0.1 已经能够正常回复，用户反馈 `go run` 启动等待较长，该体验在本版完善。
- 本版沿用单轮文本问答和流式输出，后续通过同一入口接入 Agent 和 TUI。

## 当前代码与问题

- `cmd/johnny/main.go` 将参数拼成问题；没有参数时提示用法并退出，尚无帮助和版本入口。
- `internal/config/config.go` 从当前目录的 `.env` 读取配置，进入其他项目后无法直接复用已有配置。
- 目前主要通过 `go run` 启动，日常使用仍需经过 Go 工具的构建和启动流程。

## 方案草案

以下为当前建议，尚未全部确认；进入实现前根据讨论结果收敛。

### 1. 使用 Go 标准安装方式

建议先在源码目录执行：

```sh
go install ./cmd/johnny
```

安装目标遵循 Go 的标准规则：优先使用 `GOBIN`；未设置时使用 `GOPATH/bin`。当前开发机未设置 `GOBIN`，默认目标为 `~/go/bin/johnny`。

安装后检查目标目录是否在 `PATH` 中。需要调整 shell 配置时，说明具体变更，避免重复写入。

日常直接运行 `johnny`；更新源码后重新执行安装命令，替换可执行文件。已有用户配置保留。

### 2. 引入独立的用户级配置

建议使用：

```text
~/.johnny/config.env
```

保留现有三个配置项，复用 dotenv 格式：

```dotenv
JOHNNY_API_KEY=你的中转站Token
JOHNNY_BASE_URL=https://你的中转站地址
JOHNNY_MODEL=中转站提供的模型名称
```

建议优先级为：

```text
JOHNNY_* 环境变量 > ~/.johnny/config.env
```

应用运行时明确读取用户配置，项目级配置待有实际需求时再按明确路径设计。配置缺失时给出实际查找路径和需要填写的配置项。

实施本版时，将现有项目 `.env` 中的三个配置值迁移到用户配置文件，保留原文件。迁移属于本次明确的初始化操作；已有用户配置时保留并核对，不自动覆盖。文件只对当前用户开放读写，密钥不进入源码、日志或提交。

### 3. 保留工作目录

程序安装位置、配置位置和工作目录分别管理：

- 安装目录负责提供 `johnny` 命令。
- 用户目录负责保存用户配置。
- 终端当前目录作为本次工作目录。

启动时不切换到源码目录或安装目录。未来文件工具和命令执行可以继续使用同一工作目录约定。

### 4. 完善最小命令交互

建议支持：

```sh
johnny "你好，请介绍一下 Go 语言"
johnny
johnny --help
johnny --version
```

- 带问题参数：沿用现有行为，流式输出一次回复后退出。
- 无参数：建议显示简短提示并读取一个问题，流式输出后退出。该行为仍需讨论确认。
- `--help`：展示用法和配置位置。
- `--version`：展示当前版本，方便确认安装和更新结果。

帮助和版本查询应在加载模型配置之前处理，不访问模型服务。输入、取消和退出行为保持清楚。

本版建议使用 Go 标准库处理这几个入口，随着命令结构复杂度再评估额外 CLI 框架。

## 本版涉及的主要位置

- `cmd/johnny/main.go`：参数解析、无参数输入、帮助、版本及启动提示。
- `internal/config/`：用户配置位置、加载顺序和错误提示。
- `README.md`：安装、更新、配置与日常运行说明。
- 对应测试：无配置时查询帮助和版本、跨目录配置读取、输入与退出行为。

## 待讨论问题

- 是否采用 `~/.johnny/config.env` 作为当前用户的配置入口。

- 首版安装是否采用上述 `go install` 方式，以及帮助和版本信息的具体展示。

## 验收方向草案

1. 安装一次后，在新的终端会话中可以直接找到并运行 `johnny`。
2. 在两个不同目录启动均能读取用户配置，工作目录分别对应启动位置。
3. 连续启动直接运行已安装的可执行文件，无需执行 `go run` 或重新构建。
4. 带参数的单轮问答与流式输出继续可用；无参数交互按最终确认方案验收。
5. 没有模型配置时，`--help` 和 `--version` 仍能正常工作且不访问模型服务。
6. 更新可执行文件后版本信息正确，原有用户配置保留。

启动验收分别观察本地进程启动耗时和模型首段响应等待。Go 构建缓存可以减少 `go run` 的部分开销，安装后的命令直接跳过构建入口；网络和模型推理耗时独立判断。
