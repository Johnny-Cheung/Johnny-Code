## 目标与已确认范围

- 安装后，在任意目录输入 `johnny` 即可启动程序。
- 日常直接运行已构建的可执行文件，更新源码后再重新安装。
- 无参数时读取一个问题，流式回复后退出；带参数时直接请求一次并退出。
- 原位复用当前源码项目根目录已经配置好的 `.env`，保持文件位置、内容和读取优先级。
- 程序保持启动位置作为工作目录。
- 提供无需读取模型配置、无需访问模型服务的帮助和版本查询。

## 安装与更新

在源码目录执行：

```sh
./scripts/install.sh
```

脚本根据自身位置定位源码目录，使用 `go install` 构建和安装程序。安装位置优先使用 `GOBIN`，未设置时使用 `GOPATH/bin`，当前本机安装位置为 `~/go/bin/johnny`。

安装时写入两项构建信息：

- 现有 `.env` 的绝对路径，经 Base64 编码写入链接参数，确保路径中的空格和引号能正确处理。
- Git 短提交号；源码包含未提交改动时标记为 `dirty`，无法获取 Git 信息时使用 `unknown`。

版本号在程序中维护。构建信息只记录配置文件的位置，配置内容始终留在原文件中。

更新源码后重新执行同一个脚本。构建失败时保留已安装的程序；安装位置存在其他程序、目录或符号链接时拒绝覆盖。需要回退程序时，在对应源码版本重新安装。

## PATH 与 shell 配置

- zsh：在 `${ZDOTDIR:-$HOME}/.zshrc` 中追加 PATH 配置。
- Bash：同时处理 `.bashrc` 和优先读取的现有登录配置文件；没有登录配置时使用 `.bash_profile`。
- 每条配置有明确的 Johnny-Code 标记，重复安装不会重复写入。
- shell 加载时也会检查 PATH，避免两个启动文件重复添加同一目录。
- 原有 shell 配置内容保留，脚本会显示实际修改的文件。

首次安装后新开终端，或在当前终端加载脚本所提示的 shell 配置文件。当前本机使用 zsh，已在 `~/.zshrc` 中补齐 PATH。

## 命令交互

```sh
johnny "你好，请介绍一下 Go 语言"
johnny
johnny --help
johnny --version
```

### 带参数

参数组成一个问题，流式输出一次回复后退出。以 `-` 开头的问题可以放在 `--` 后面。

### 无参数

显示“请输入问题：”，读取一个问题，流式回复后退出。每次运行处理一个独立问题，不保留会话历史。

- 空行或纯空白问题：提示错误，退出码为 1。
- 输入结束且没有问题：退出码为 0。
- 输入末尾没有换行但已有内容：正常处理该问题。
- `Ctrl+C`：取消等待输入或模型请求，退出码为 130。

### 帮助与版本

`--help`（或 `-h`）显示用法、取消方式及实际配置文件路径。`--version` 显示版本号和构建提交信息。

这两类查询在配置加载之前处理，即使配置文件不存在也能使用。未知选项返回非零退出状态。

## 原位配置与工作目录

`internal/config.Load(path)` 接收明确的配置路径，保留 v0.1 的字段、校验规则及环境变量优先级。显式空环境变量继续覆盖文件值并被报告为缺失。

安装后的程序使用构建时记录的源码项目 `.env`，从其他目录启动时也读取同一份文件。程序不会通过切换工作目录来寻找配置。

开发阶段通过 `go run ./cmd/johnny` 启动时，仍默认读取当前目录 `.env`。源码目录位置变化后，重新安装以更新文件定位。

模型正文写入标准输出，输入提示、等待状态与错误写入标准错误。模型调用仍使用 Anthropic 原生 Messages 协议，保留流式输出、5 分钟时限与 4096 个输出 token 上限。

## 主要代码与执行流程

- `scripts/install.sh`：构建、安装、记录配置路径与提交号、处理 PATH 和更新保护。
- `cmd/johnny/main.go`：解析选项；优先处理帮助与版本；定位并加载配置；读取一次问题；调用模型；处理取消与退出状态。
- `internal/config/config.go`：按传入路径读取已有配置，报告文件位置及缺失项。
- `internal/model/client.go`：沿用 v0.1 的流式请求与错误处理，本版未改变其模型协议实现。

普通问答的执行顺序是：解析参数 → 定位并加载已有配置 → 获取一个问题 → 流式调用 → 退出。
