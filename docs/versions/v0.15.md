# v0.15 · JEV 权限模式

**状态：已实现（2026-11-24），待用户验收。**

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

在 `default`、`read-only`、`allow` 之外增加 `--jev` 权限模式：

- 只接管 `bash`，文件工具继续沿用 `default` 的路径规则；
- JEV 模式下不再使用固定查询白名单、项目命令前缀或危险后缀黑名单；
- 模型生成的原始 bash 命令直接交给 JEV，按 `allow` / `ask` / `deny` 执行；
- JEV 请求失败时，这条命令回退 `default` 策略；
- 不做决策缓存，每条命令独立判断。

## 已确认的产品行为

1. **启动方式。** `johnny --jev` 或 `johnny --permission-mode jev`；与 `--read`、`--skip` 互斥。
2. **只接管 bash。** `read`、`write`、`edit` 仍按工作目录和项目路径白名单；`remember` 仍需审批；`skill`、`memory`、`history` 仍自动执行。
3. **不解析后再判断。** 原始命令字符串直接发给 JEV，不在 JEV 之前执行 `parseShellCommand`；避免通配符、16 段上限或复杂 shell 语法在 JEV 看到之前就被拒绝。
4. **完整 shell 执行。** JEV 返回 `allow` 后用 `bash -c` 执行原始命令，可以使用管道、`&&`/`||`/`;`、重定向、通配符、变量、子 shell 和脚本。
5. **`ask` 使用现有审批面板。** 只提供“允许本次/拒绝本次”，不提供本会话或项目记录，避免模型判断变成新的白名单。
6. **`deny` 直接拒绝。** 返回原因，并提示用户可改用 `--permission-mode default` 或 `--skip` 重新运行；当前模式内不提供覆盖按钮。
7. **失败降级。** 超时、网络错误、5xx/429、响应格式异常或未知决策时，这条命令回退 `default`；连续失败 3 次后本会话停用 JEV，全部回退 `default`。
8. **配置缺失启动报错。** 需要 `JOHNNY_JEV_BASE_URL`、`JOHNNY_JEV_API_KEY`；`JOHNNY_JEV_MODEL` 默认 `jev-latest`。
9. **子 Agent 沿用。** 写入类子任务共享父会话的分类器和降级回调；`access=read` 子任务仍是只读。
10. **不做缓存。** 每条命令都是一个独立请求；相同命令重复出现也重新判断。

## 实现

- `internal/jev`：System One 客户端，构造 `state + questions` 请求，解析 `decision` / `reason`，处理超时、HTTP 错误和常见凭据脱敏。
- `internal/tool/jev.go`：包装 `Default`，只拦截 `bash`；`allow` 直接走完整 `Bash`，`ask` 走 `ApprovalGate`，`deny` 返回权限错误，分类失败走 `Default.Execute`。
- `internal/config`：读取可选的 `JOHNNY_JEV_*`，其他模式不要求填写。
- `cmd/johnny`：`--jev` 参数、模式解析、系统提示、启动提示、帮助、分类器接线和降级警告。
- `internal/subagent`：新增 `ModeJEV`，把分类器和降级回调传给写入类子任务。
- `internal/session`：`permission` 事件增加 `classifier`、`classifier_model`、`classified_decision`、`classified_reason`、`classified_probabilities`。

## 边界与限制

1. **不是沙箱。** JEV 只看命令文本和工作目录，看不到脚本内容和文件内容；误判或提示注入可能让危险命令被放行。
2. **信任是显式选择。** `--jev` 高于 `default` 的自动化程度，接近 `--skip`，但保留模型否决权和 `ask` 审批机会。
3. **请求延迟。** 每条 bash 命令增加一次 JEV 请求；没有缓存，命令多时延迟会累加。
4. **隐私。** 命令会发送到 JEV 服务；已对常见 Bearer、`sk-`、`token=`、`password=` 片段脱敏，但不能保证覆盖所有敏感信息。
5. **文件工具不归 JEV。** 工作目录外的文件读写仍由 `default` 路径规则和审批处理。
