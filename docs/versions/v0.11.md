# v0.11 · 长期记忆

**状态：待讨论（2026-10-25）。** 本文只记录范围、边界和进入讨论时需要回答的问题；尚未确认任何存储、写入、检索或交互方案。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

让 Johnny-Code 在跨会话场景中保存和检索真正有价值的信息，而不是把所有对话都当作记忆。需要覆盖：

- 什么信息值得长期保存；
- 谁触发保存：模型、用户还是固定规则；
- 如何检索并控制注入上下文的大小；
- 如何更新、纠错、合并、删除和管理时效；
- 用户如何查看、修改和撤销记忆；
- 如何避免把凭据、临时状态和一次性任务误存为长期事实。

## 与 v0.10 的边界

- v0.10 的完整历史、JSONL 和工具输出存档都不是长期记忆，也不用于会话恢复。
- v0.10 的摘要只在当前会话的请求视图中生效，不跨会话。
- v0.11 需要明确区分“会话事实”“项目约定”“用户偏好”和“可复用参考信息”。
- v0.11 不自动继承 v0.10 的压缩摘要；是否从摘要中提取记忆需要单独决定。

## 进入讨论时先回答的问题

1. **记忆类型**
   - 用户偏好、项目约定、已确认决策、反馈纠正、外部参考，哪些需要长期保存？
   - 是否区分用户级和项目级？同名冲突如何处理？

2. **写入方式**
   - 模型通过工具主动写入，还是运行时自动提取，或由用户显式命令写入？
   - 写入是否需要确认？是否只在特定权限模式下允许？
   - 如何避免把临时任务、错误猜测和敏感信息写成记忆？

3. **存储与格式**
   - 保存在 `~/.johnny/`、项目 `.johnny/`，还是分别保存？
   - 使用 Markdown、JSON、JSONL 还是索引数据库？
   - 是否需要人类可读、可版本控制、可导出和可迁移？

4. **检索与注入**
   - 启动时注入、按任务检索，还是模型通过工具查询？
   - 使用关键词、路径、标签、时间还是向量检索？
   - 每次最多注入多少 token？如何与 v0.10 的上下文预算配合？
   - 检索不到或记忆冲突时如何降级？

5. **生命周期**
   - 如何更新时间、来源和置信度？
   - 如何合并重复项、处理冲突和失效？
   - 删除是立即物理删除，还是保留审计记录？
   - 是否需要过期时间、项目归档或用户手动清理？

6. **权限与隐私**
   - 路径白名单、只读模式和放行模式分别如何影响记忆写入？
   - `.env`、私钥、令牌和其他敏感内容是否默认禁止写入？
   - 项目记忆是否可以随仓库提交？用户记忆如何隔离？
   - 日志中是否记录记忆正文？如何避免泄漏？

7. **用户交互**
   - 是否需要 `/memory` 查看、搜索、编辑、删除和导出？
   - 如何显示本轮使用了哪些记忆、来源和最后更新时间？
   - 用户纠正后，如何让旧记忆失效而不是继续被检索？

8. **与相邻能力的关系**
   - 与 Skills 的区别：Skill 是任务指导，记忆是事实和偏好。
   - 与 JSONL/摘要/存档的区别：诊断、当前会话视图和长期事实分别存放。
   - 是否为 v0.12 SubAgent 提供受控的共享记忆或独立记忆？

## 暂不预设的方案

本版不预先决定 SQLite、向量数据库、嵌入模型、自动摘要提取、后台索引或跨设备同步。先讨论最小可用范围，再决定是否需要这些能力。

从“什么信息值得长期保存”和“写入由谁触发”开始讨论，逐项确认后再形成实现方案和验收场景。
