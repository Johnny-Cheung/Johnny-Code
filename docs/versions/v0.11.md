# v0.11 · 长期记忆

**状态：已确认冻结（2026-10-26）。** 四层结构、规则与知识的边界、AGENTS 与 memory 的写入职责、存储布局、前缀快照时机、读取路径、显式与隐式写入、模型工具和本地命令均已完成实现并通过自动化及终端模拟验证。用户确认当前 `/remember` 提示式实现足够，专用 diff 视图后置。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

让 Johnny-Code 在跨会话场景中保存两类内容：

- **规则**：少量、稳定、每次会话都生效的项目和用户指令；
- **知识**：大量、可增长、通过索引按需读取的偏好、纠正、项目事实和参考。

核心原则：

- AGENTS 是规则，memory 是知识；
- AGENTS 少量常驻，memory 大量按需；
- 规则由人批准，知识由模型维护；
- 记忆是建议性上下文，不是权限，也不能授予权限；
- 全部使用人类可读的本地 Markdown，不引入数据库或向量检索。

## 与 v0.10 的边界

- v0.10 的完整历史、JSONL、工具输出存档和摘要都不是长期记忆，也不用于会话恢复。
- v0.11 不从会话摘要或 JSONL 自动提取记忆。
- AGENTS 和记忆索引固定在请求前缀中，不参与摘要；`/compact` 后重新构建。
- `memory` 工具的结果仍然受上下文治理约束，但单条正文限制为 8 KiB，不会触发工具输出存档。
- v0.11 不实现会话恢复，也不把记忆写回 v0.10 的完整历史。

## 核心结论

### 规则与知识

| | AGENTS | memory |
| --- | --- | --- |
| 性质 | 规则、约束、约定 | 事实、偏好、经验、参考 |
| 写入者 | 人批准 | 模型维护 |
| 规模 | 少量 | 大量 |
| 加载 | 每次会话固定注入 | 索引常驻，正文按需 |
| 权威性 | 高；冲突时优先 | 低；可能过时或推断错误 |
| 失败模式 | 过时规则、互相冲突 | 错误推断、事实过时、过度泛化 |

模型推断出的偏好只进入 memory；只有用户明确表达的全局规则，或用户确认后的提升，才进入用户 AGENTS。

### 四层结构

| 层 | 路径 | 写入者 | 加载 | 规模 | 共享 |
| --- | --- | --- | --- | --- | --- |
| 用户 AGENTS | `~/.johnny/AGENTS.md` | 模型，只写明确全局规则或确认提升 | 每次会话固定注入 | 少量 | 私有 |
| 项目 AGENTS | `<repo>/AGENTS.md` | 用户；用户通过 `/remember` 起草或明确要求时代写 | 每次会话固定注入 | 少量 | 随仓库提交 |
| 用户 memory | `~/.johnny/memory/` | 模型 | 索引常驻，正文按需 | 大量 | 机器本地私有 |
| 项目 memory | `~/.johnny/projects/<project-id>/memory/` | 模型 | 索引常驻，正文按需 | 大量 | 机器本地私有 |

```text
~/.johnny/
├── AGENTS.md                       # 用户规则
├── backups/agents/                 # 用户 AGENTS 写入前备份
├── memory/                         # 用户记忆
│   ├── MEMORY.md                   # 索引
│   └── <name>.md
└── projects/<project-id>/
    └── memory/                     # 项目记忆
        ├── MEMORY.md               # 索引
        └── <name>.md

<repo>/
└── AGENTS.md                       # 项目规则
```

### 入口分层

| 入口 | 谁使用 | 是否经过模型 | 作用 |
| --- | --- | --- | --- |
| `/memory` | 用户 | 否 | 查看用户级和项目级两个 `MEMORY.md` 索引 |
| `/remember [text]` | 用户 | 是，主 Agent 回合 | 让模型起草或更新项目 AGENTS，先展示拟修改内容，确认后写入 |
| `memory` 工具 | 主模型 | 是，轮内调用 | 搜索、读取记忆 |
| `remember` 工具 | 主模型 | 是，轮内调用 | 结构化写入 memory 或用户 AGENTS |
| 轮末旁路审查 | 运行时 | 是，独立旁路请求 | 自动提取隐式学习 |

`/memory` 直接读取索引；`/remember` 把起草指令发送给主 Agent，不通过模型工具。模型工具只供主模型在任务中调用。

### 写入职责

- **用户 AGENTS**：模型写，但只接受用户明确表达的全局规则，或用户确认后的提升；只自动新增，不自动修改或删除已有规则。
- **项目 AGENTS**：用户写；`/remember` 可以让模型起草并先展示拟修改内容，用户确认后再写入；模型不会自动修改。
- **用户 memory**：模型写，每轮评估；跨项目生效。
- **项目 memory**：模型写，每轮评估；只对当前项目生效。
- **Skill**：仍然是按需加载的任务步骤，不由 memory 自动生成。

## 前缀快照与加载时机

固定前缀包含：用户 AGENTS、项目 AGENTS、用户记忆索引、项目记忆索引。

只在以下时机构建或重建：

1. 新会话启动；
2. 自动极限压缩成功之后；
3. 手动 `/compact` 成功之后；
4. 压缩失败但降级为确定性裁剪之后。

除此之外不重新加载：

- 写入 memory 不重载；
- 写入用户 AGENTS 不重载；
- `/memory` 和 `/remember` 不重载固定前缀；
- 当前会话继续使用启动时或上次压缩后生成的索引快照。

这样写入不会触发前缀缓存失效，压缩本来就会改变前缀，顺便刷新 AGENTS 和索引，成本最低。

前缀中的索引是**快照**，不是唯一事实来源：

- `memory` 工具的 `search` 查询磁盘上的最新索引，并过滤已不存在的文件；
- `memory` 工具的 `read` 直接读取记忆文件；
- 当前会话新写入的记忆可以通过 `search` 找到，已删除的记忆不会再返回；
- 固定索引只负责零成本提示“大概有哪些记忆”。

用户 AGENTS 的写入在当前轮通过 `remember` 工具结果和对话记录可见；下一次新会话或压缩后进入固定规则区。

## AGENTS

### 加载

- v0.11 只加载两个文件：用户级 `~/.johnny/AGENTS.md` 和项目根目录 `AGENTS.md`。
- 项目根优先使用 git 根目录；不在 git 仓库内时使用启动工作目录。
- v0.11 不加载嵌套目录的 AGENTS，也不支持 `@import`。
- 加载顺序：用户 AGENTS，然后项目 AGENTS；注入时带来源标题，方便区分和冲突处理。
- 只注入存在的文件；空文件或不存在不占上下文。
- 上限：用户 AGENTS 100 行或 1,000 token；项目 AGENTS 200 行或 2,000 token，先到者生效。超限时截断并显示警告。
- 固定前缀目标总量不超过 6,000 token；窗口小于 64K 时提示精简。
- `/compact` 后重新构建，不参与摘要。

### 用户 AGENTS

用户 AGENTS 由模型维护，但边界严格：

- 只接受用户明确说出的全局规则，例如“以后所有项目回答都用中文”“所有项目提交前都跑测试”；
- 只接受用户确认后的 memory 提升；
- 模型从行为或单次对话推断出的偏好，不写入用户 AGENTS，只写用户 memory；
- 不自动修改已有规则，不自动删除。

文件保留一个人工可编辑的整体结构，并包含运行时管理的自动规则区：

```markdown
# 用户规则

## 手动规则

- 不要自动 commit 或 push。

## 自动规则

<!-- johnny:auto:start -->
- `answer-language-zh` [2026-10-26] 所有回答使用中文。
<!-- johnny:auto:end -->
```

运行时只操作 `johnny:auto` 标记之间的内容；每条自动规则带稳定 ID，便于更新和去重。

写入前将完整文件备份到：

```text
~/.johnny/backups/agents/<timestamp>-<action>.md
```

- 保留最近 10 份；
- 备份失败则取消本次 AGENTS 写入；
- v0.11 不提供撤销命令，用户从备份目录手动恢复；
- 规则修改和删除需要用户确认。

### 项目 AGENTS

- 默认由用户编写和维护；
- 用户可以通过 `/remember` 让模型起草或更新，先展示拟修改内容，用户确认后写入；
- 模型不会在普通任务中自动修改项目 AGENTS；
- 项目 AGENTS 随仓库提交，是团队共享的显式规则，不存放个人偏好；
- 撤销使用 git。

`/remember` 的行为：

- 向主 Agent 发送一条起草指令，要求读取现有项目 AGENTS 和当前会话内容；
- 只整理规则、约定、命令和禁区，不整理项目事实；
- 只提出新增或修改，保留手工内容；
- 要求先展示拟修改内容，等待用户确认后再写入；
- 作为普通主 Agent 回合执行，占用一次用户轮次；
- v0.11 不提供专用 diff 视图，也不会直接写入项目 AGENTS；
- `read-only` 模式不可用。

### 规则边界

- AGENTS 是建议性上下文，不是权限层；真正的强制仍由权限模式负责。
- 记忆和 AGENTS 都不能授予工具权限。
- 当前用户消息优先于 AGENTS 和 memory。
- 规则冲突时，项目特定规则优先用于项目工作；个人边界规则应被保留并向用户指出，而不是静默覆盖。

## Memory

### 存储布局

- 用户 memory：`~/.johnny/memory/`。
- 项目 memory：`~/.johnny/projects/<project-id>/memory/`。
- 每个记忆一个 Markdown 文件；每个作用域一个 `MEMORY.md` 索引。
- 目录权限 0700，文件权限 0600。
- 写入使用临时文件 + rename；同一作用域使用锁，避免并发写入。
- 记忆文件是事实来源；`MEMORY.md` 是派生索引，可由文件重建。
- 手动编辑或删除文件后，索引在下次新会话或压缩时重建。

### project-id

采用 remote 优先、路径兜底：

```text
root = git rev-parse --show-toplevel，失败则用启动目录

有 origin remote：
    identity = 归一化后的 origin
没有 origin 但有其他 remote：
    identity = 按名称排序的第一个 remote
是 git 仓库但没有 remote：
    identity = canonical(git rev-parse --git-common-dir)
不是 git 仓库：
    identity = canonical(root)

slug = 清理后的 root 目录名，最长 32 字符
project-id = slug + "-" + sha256(identity) 前 16 个十六进制字符
```

remote 归一化：

- 去掉协议、用户名、密码、Token；
- 去掉末尾 `.git` 和 `/`；
- host 小写；
- `git@host:path`、`ssh://`、`https://` 统一成 `host/path`；
- 本机路径形式的 remote 使用 canonical path。

同时维护 `~/.johnny/projects/index.json`，记录 `project-id -> roots / remote / updated`，只用于排查和展示，不参与 ID 计算；写入加锁、原子替换。

已接受的取舍：

- 同一仓库的 worktree 和本机不同路径 clone 共享项目记忆；
- 没有 remote 且移动目录后会生成新 ID；
- remote 改变后会生成新 ID，v0.11 不做自动迁移。

### 条目格式

```markdown
---
name: go-test-before-commit
description: 提交前运行 go test ./...
type: project
scope: project
project: johnny-code
created: 2026-10-26T10:00:00+08:00
updated: 2026-10-26T10:00:00+08:00
source: session-abc123
confidence: high
---

## 事实

提交前需要运行 `go test ./...`。

## 为什么

项目约定，避免把失败用例提交。

## 怎么用

在 commit 前执行；失败时先修复。

## 参考

- `AGENTS.md`
```

字段：

| 字段 | 说明 |
| --- | --- |
| `name` | kebab-case，同作用域内唯一，最多 64 字符 |
| `description` | 一行描述，进入索引，最多 40 个中文字符 |
| `type` | `preference` / `feedback` / `project` / `reference` / `environment` |
| `scope` | `user` / `project` |
| `project` | 项目记忆必填，用户记忆不填 |
| `created` / `updated` | ISO 8601 时间 |
| `source` | 会话 ID，必要时带轮次 |
| `confidence` | `high` / `medium` / `low`，区分明确表达、观察确认和模型推断 |

类型约定：

- `preference`：稳定的个人偏好、沟通方式、工具习惯；
- `feedback`：用户纠正过的做法、确认过的方法；
- `project`：项目事实、已确认决策、约定、坑；
- `reference`：外部文档、面板、issue、规范链接；
- `environment`：工具链、版本、路径、环境怪癖。

正文只放事实、原因、用法和参考，建议不超过 8 KiB；不放大段代码、完整日志或原始工具输出。

### 索引

每个作用域一个 `MEMORY.md`，一行一条：

```markdown
# Project Memory

- `go-test-before-commit` [project, high, 2026-10-26] — 提交前运行 go test ./...
- `pty-test-mock-server` [project, medium, 2026-10-20] — PTY 测试需要本地 mock 服务。
```

注入时合并为用户和项目两个区块：

```text
## 用户记忆索引
- ...

## 项目记忆索引
- ...
```

预算：

- 用户索引 1,000 token，项目索引 2,000 token；
- 固定前缀合计不超过 6,000 token（含两个 AGENTS）；
- 每个作用域最多 256 条，200 条时提示整理；
- 单行描述最多 40 个中文字符；
- 搜索最多返回 10 条；
- 单条正文最多 8 KiB。

索引超预算时：

1. 先保留 `confidence=high` 的条目；
2. 再按 `updated` 从新到旧；
3. 剩余截断，并加一行“另有 N 条，使用 memory search 查找”；
4. 只影响注入，不修改索引文件。

AGENTS 超预算时：加载到上限后追加截断提示，启动时显示警告；不自动删除内容。

### 读取

`memory` 工具只读，提供：

- `memory search <关键词> [--scope user|project]`
- `memory read <scope>/<name>`
- `memory list [--scope user|project]`

读取规则：

- 固定索引已经常驻，简单任务不需要调用工具；
- `search` 查询磁盘最新索引，并过滤不存在的文件；
- 项目相关或任务不明确时，先搜 1～3 次；
- 最多读 1～2 条正文；
- 没有命中就停止，不扩大搜索；
- 不使用向量检索或嵌入模型；
- 同名条目跨作用域时，搜索结果同时展示，并带 `[user]` / `[project]` 标签。

冲突处理：

- 权限 > 当前用户消息 > 显式 AGENTS > memory；
- 项目事实和约定优先使用项目 memory；
- 个人偏好优先使用用户 memory；
- 无法判断时两条都展示，由模型根据上下文选择；v0.11 不单独标记冲突。

记忆使用情况通过 TUI 提示和 JSONL 记录；v0.11 不要求模型在回答末尾附加引用块。

### 写入

写入分为显式路径和隐式路径，二者共用一个底层 `MemoryStore`。

#### 显式 `remember` 工具

主模型通过 `remember` 工具处理用户明确要求：

```json
{
  "target": "user_memory | project_memory | user_agents",
  "type": "preference | feedback | project | reference | environment",
  "name": "kebab-case 唯一名称",
  "description": "一行描述",
  "body": "完整正文",
  "confidence": "high | medium | low",
  "evidence": "用户原话或判断依据"
}
```

约束：

- 只在用户明确说“记住这个”“以后都这样”“写进规则”时调用；
- 模型自行推断的偏好不调用 `remember`，交给轮末旁路审查；
- `target=user_agents` 时，`evidence` 必须是用户明确表达的全局规则，且 `confidence=high`；
- 没有项目 AGENTS 的 target；项目 AGENTS 通过 `/remember` 或用户手动编辑；
- 同名条目默认更新，不新增重复项；
- 写入成功后返回 `ok`、`action`、`target`、`name`、`path` 和 `updated`；模型只有收到成功结果才能说“已记住”，失败必须如实说明。

#### 轮末旁路审查

每轮正常结束后，异步启动一次独立的记忆审查请求：

```text
主回答完成
  → 快照本轮：用户消息、最终回答、工具调用与预览
  → 旁路请求：判断 no-op / create / update
  → 返回结构化候选
  → 运行时校验、去重、脱敏
  → 写 memory 或用户 AGENTS
  → 重建磁盘索引 + TUI 提示
```

约定：

- 独立请求，不使用工具，不占当前轮 `--max-turns`；
- 默认复用当前模型，使用独立提示词和严格 JSON 输出；
- 输入只给本轮内容、现有索引、现有 AGENTS 和本轮 `remember` 结果，不喂完整历史或工具存档；
- 输入上限约 8k token，输出上限约 2k token；
- 异步执行，不阻塞下一次输入；串行队列，最多 3 个待审查轮次；
- 允许 no-op；宁可不写，也不要写错；
- 项目 AGENTS 只输出建议，不写入；用户 AGENTS 只接受明确全局规则；
- 失败、超时或 JSON 解析错误只记录警告，不影响本轮回答。

超时与重试：

- 单次超时 30 秒；
- 最多 2 次尝试，重试间隔 2 秒；
- 非法 JSON 视为失败，重试时追加“只输出 JSON”的约束；
- 连续 3 次失败后，本会话暂停自动审查；新会话恢复，或通过环境变量重新启用；
- 取消、失败、达到请求上限的轮次不审查。

审查输出：

```json
{
  "memories": [],
  "user_agents": [],
  "project_agents_suggestions": []
}
```

`memories` 用于用户/项目 memory；`user_agents` 必须带用户原话；`project_agents_suggestions` 只提示用户，不自动执行。

#### 校验、去重与更新

- `name` 只允许小写字母、数字和连字符；
- `description` 一行，最多 40 个中文字符；
- 正文不超过 8 KiB；
- 拒绝密钥、Token、私钥、`.env` 内容和明显的长随机字符串；
- 拒绝大段原始工具输出，只保留摘要、错误片段和路径；
- 同名条目更新 `description`、`body`、`type`、`confidence` 和 `updated`，保留 `created`；
- 不自动删除记忆；删除由用户直接编辑文件完成；
- v0.11 不做自动合并或后台整理。

#### 权限、并发与失败

- `remember` 作为模型写入工具受权限模式管理：`allow` 直接执行，`default` 走审批，`read-only` 不注册或拒绝。
- 旁路审查属于运行时内部写入：`allow` / `default` 允许自动写入，首次写入显示提示；`read-only` 禁用。
- 可通过 `JOHNNY_MEMORY_AUTO=off` 关闭本会话的旁路审查。
- 同一作用域使用锁；锁忙时跳过本次写入，下一轮再更新。
- 写入失败、磁盘不可写或索引重建失败时给出提示，但不影响当前回答。
- JSONL 记录 `memory_write` 事件，包含作用域、动作、名称和路径，不记录完整正文。

### 生命周期

- `updated` 是新鲜度依据；超过 90 天可在 `/memory` 提示“可能过时”，v0.11 不自动过期。
- 用户通过 `/memory` 查看索引，通过文件路径查看、编辑和删除正文。
- 项目记忆提升为用户记忆不在 v0.11 提供命令；需要时手动移动文件或通过模型重新记录。
- 删除是物理删除；是否保留审计记录待定。

## 工具与命令

### 模型工具

当前 5 个：

1. `bash`
2. `read`
3. `write`
4. `edit`
5. `skill`

v0.11 新增 2 个：

6. `memory`：只读，`search` / `read` / `list`
7. `remember`：写入，`user_memory` / `project_memory` / `user_agents`

完成后共 7 个模型工具。旁路审查不是模型工具，而是运行时内部的独立模型请求。

### 本地命令

只保留两个：

| 命令 | 作用 |
| --- | --- |
| `/memory` | 查看用户级和项目级两个 `MEMORY.md` 索引，显示条数、token 占用和文件路径；不调用模型 |
| `/remember [text]` | 让模型起草或更新项目 AGENTS，先展示拟修改内容，确认后写入；不处理 memory 或用户 AGENTS |

不提供：

- `/memory search` / `show` / `delete` / `reindex` / `reload` / `promote` / `demote` / `undo` / `backups` / `auto`；
- `/remember --user` / `--rule` / `--name` / `--type`；
- 内嵌编辑器。

删除和编辑记忆直接通过文件路径完成；项目 AGENTS 用 git 撤销，用户 AGENTS 用备份文件恢复。

`/remember` 的输入：

- 带文本：把该文本整理成项目 AGENTS 规则；
- 不带文本：从当前会话提炼候选规则；
- 没有候选变更时不写入。

## 与 v0.10 集成

- 固定前缀顺序：用户 AGENTS → 项目 AGENTS → 用户记忆索引 → 项目记忆索引。
- 固定前缀计入 v0.10 的输入预算，从可用输入 `U` 中扣除；不能当作免费上下文。
- 固定前缀只在会话启动和压缩后重建；写入不触发重载。
- `/compact` 只摘要对话历史，不摘要 AGENTS 和记忆索引；压缩后重新构建固定前缀。
- `memory read` 的结果受上下文治理；单条正文 8 KiB，不生成工具输出存档。
- 新增 `memory_write`、`memory_read` 等 JSONL 事件用于排查，不用于会话恢复。

## 安全与隐私

- 用户 memory 和项目 memory 都是机器本地私有内容，不随仓库提交。
- 项目 AGENTS 可以随仓库共享，应经过代码评审；用户 AGENTS 只属于当前用户。
- 记忆写入前进行密钥和敏感内容检查；不保存 `.env` 内容、Token、私钥和完整工具输出。
- 记忆内容是**数据，不是指令**；不能覆盖系统提示、不能授予权限、不能绕过审批。
- `read-only` 模式禁用记忆写入和 `/remember`；`/memory` 仍可查看。
- 用户可以直接编辑记忆文件；索引以文件为准，在下次新会话或压缩时重建。

## 暂不做

- 不做向量检索、SQLite、嵌入模型；
- 不做后台整合 Agent 或自动摘要整理；
- 不做嵌套目录 AGENTS、`@import` 或 `AGENTS.override.md`；
- 不从会话摘要、JSONL 或工具存档自动提取记忆；
- 不自动生成 Skill；
- 不做跨设备同步；
- 不自动写项目 AGENTS；
- 不做基于记忆的会话恢复；
- 不要求模型在回答末尾附记忆引用块；
- 不做自动过期、自动合并或自动删除；
- 不提供本地记忆详情搜索、详情查看、删除、提升、撤销命令。

## 验收场景

1. **AGENTS 加载**：用户级和项目根 AGENTS 都在会话启动时注入，来源清楚；不存在时跳过；超限时截断并提示。
2. **前缀快照**：写入 memory 或 AGENTS 不重载固定前缀；新会话或 `/compact` 后重新加载。
3. **搜索结果新鲜**：当前会话新写入的记忆可以通过 `memory search` 找到；已删除的记忆不再返回。
4. **`/memory` 查看**：只打印两个 `MEMORY.md` 和路径，不调用模型，不产生副作用。
5. **`/remember` 起草**：要求模型读取现有项目 AGENTS，先展示拟修改内容，确认后写入；不写 memory 或用户 AGENTS。
6. **项目 AGENTS 边界**：普通任务中模型不会自动修改项目 AGENTS；用户手动编辑和 git 撤销可用。
7. **用户 AGENTS 边界**：用户明确表达全局规则时由模型写入自动规则区；模型推断的偏好只写用户 memory。
8. **条目与索引**：每条记忆生成独立 Markdown 文件和一行索引；索引可由文件重建。
9. **显式写入**：模型 `remember` 工具写入或更新记忆并返回成功结果；失败时模型不得声称已记住。
10. **旁路审查**：普通任务中的项目知识、纠正和环境怪癖被记录；无内容时 no-op；失败不影响本轮回答。
11. **读取路径**：固定索引是快照；`memory read` 读最新文件；正文按需进入上下文。
12. **作用域隔离**：项目 A 的记忆不出现在项目 B；用户记忆在两个项目中都可见。
13. **敏感内容**：Token、私钥、`.env` 内容和原始大日志不会被写入记忆。
14. **预算控制**：索引超过预算时截断并提示；AGENTS 超限时截断并提示。
15. **压缩集成**：`/compact` 后 AGENTS 和记忆索引被重新构建，不被摘要替代。
16. **只读模式**：`/memory` 可查看，`/remember`、`remember` 工具和旁路写入被禁用。
17. **工具与命令**：模型工具从 5 个增加到 7 个；本地命令只有 `/memory` 和 `/remember`。
18. **并发写入**：两个会话同时写同一作用域时，锁保证不产生半写文件；锁忙时可跳过并在后续轮次更新。
19. **项目身份**：同一仓库的 worktree 共享项目记忆；不同仓库相互隔离。
20. **审计**：TUI 提示记忆写入；JSONL 记录动作、作用域、名称和路径，不记录正文。

## 实现取舍

| 问题 | 最终取舍 |
| --- | --- |
| `project-id` | remote 优先、路径兜底；`slug + sha256(identity)[:16]`；`index.json` 记录映射 |
| AGENTS 上限 | 用户 100 行/1,000 token；项目 200 行/2,000 token |
| 嵌套 AGENTS | v0.11 只加载用户级和项目根 |
| 前缀加载时机 | 新会话、自动/手动压缩或裁剪成功后重建；写入不重载 |
| 索引预算 | 用户 1,000 token + 项目 2,000 token；固定前缀合计 ≤6,000 token |
| 索引条目 | 每作用域最多 256 条，200 条提示整理；描述 40 个中文字符 |
| 旁路审查频率 | 每轮正常结束都审查；纯显式记忆轮次的跳过优化后置 |
| 旁路审查模型 | 默认复用当前模型，独立提示词 |
| 旁路审查超时/重试 | 30 秒；最多 2 次尝试；间隔 2 秒；连续 3 次失败暂停本会话 |
| 旁路审查队列 | 串行，最多 3 个待审查轮次；输入 8k token，输出 2k token |
| `default` 模式记忆写入 | `remember` 工具走审批；旁路内部写入允许，首次提示；`read-only` 禁用 |
| 用户 AGENTS 自动规则区 | `johnny:auto` 标记，只自动新增；修改/删除确认 |
| 用户 AGENTS 备份 | 写入前备份最近 10 份；v0.11 不提供撤销命令 |
| 项目 AGENTS 写入 | 用户手动或 `/remember` 起草；先展示拟修改内容，确认后写入；git 撤销 |
| `/remember` 执行方式 | 转为主 Agent 回合，要求先展示拟修改内容；用户确认当前实现够用，专用 diff 视图后置 |
| 记忆使用展示 | TUI 提示 + JSONL；不要求引用块 |
| 过期处理 | 显示 `updated`，超过 90 天提示可能过时；不自动删除 |
| 自动合并/整理 | v0.11 不做 |
| 本地命令 | 只有 `/memory` 查看索引和 `/remember` 起草项目 AGENTS |
| 记忆删除/编辑 | 直接编辑文件；索引在下次新会话或压缩时重建 |
| 自动记忆开关 | `JOHNNY_MEMORY_AUTO=off` 关闭旁路审查 |
| 项目记忆位置 | 机器本地 `~/.johnny/projects/<project-id>/memory/` |
| 当前会话规则生效 | 下次会话或压缩后进入固定前缀；当前轮通过工具结果可见 |
