# v0.11 · 长期记忆

**状态：设计已确认（2026-10-26），待实现。** 已确认四层结构、规则与知识的边界、AGENTS 与 memory 的写入职责、存储布局、索引读取、显式与隐式写入路径，以及模型工具拆分。文中标注“待定”的实现细节在开工前继续确认。

[返回总体路线图](../johnny-code-roadmap.md)

## 本版目标

让 Johnny-Code 在跨会话场景中保存两类内容：

- **规则**：少量、稳定、每次会话都生效的项目和用户指令；
- **知识**：大量、可增长、通过索引按需读取的偏好、纠正、项目事实和参考。

核心原则：

- AGENTS 是规则，memory 是知识；
- AGENTS 少量常驻，memory 大量按需；
- 规则由人批准，知识由模型维护；
- 记忆是建议性上下文，不是权限，也不能授予权限；
- 全部使用人类可读的本地 Markdown，不引入数据库或向量检索。

## 与 v0.10 的边界

- v0.10 的完整历史、JSONL、工具输出存档和摘要都不是长期记忆，也不用于会话恢复。
- v0.11 不从会话摘要或 JSONL 自动提取记忆。
- 记忆索引固定在请求前缀中，不参与摘要；`/compact` 后重新注入。
- `memory read` 的结果仍然受上下文治理约束，但单条正文限制为 8 KiB，不会触发工具输出存档。
- v0.11 不实现会话恢复，也不把记忆写回 v0.10 的完整历史。

## 核心结论

### 规则与知识

| | AGENTS | memory |
| --- | --- | --- |
| 性质 | 规则、约束、约定 | 事实、偏好、经验、参考 |
| 写入者 | 人批准 | 模型维护 |
| 规模 | 少量 | 大量 |
| 加载 | 每次会话固定注入 | 索引常驻，正文按需 |
| 权威性 | 高；冲突时优先 | 低；可能过时或推断错误 |
| 失败模式 | 过时规则、互相冲突 | 错误推断、事实过时、过度泛化 |

模型推断出的偏好只进入 memory；只有用户明确表达的全局规则，或用户确认后的提升，才进入用户 AGENTS。

### 四层结构

| 层 | 路径 | 写入者 | 加载 | 规模 | 共享 |
| --- | --- | --- | --- | --- | --- |
| 用户 AGENTS | `~/.johnny/AGENTS.md` | 模型，只写明确全局规则或确认提升 | 每次必带 | 少量 | 私有 |
| 项目 AGENTS | `<repo>/AGENTS.md` | 用户；用户明确要求时模型可代写 | 每次必带 | 少量 | 随仓库提交 |
| 用户 memory | `~/.johnny/memory/` | 模型 | 索引常驻，正文按需 | 大量 | 机器本地私有 |
| 项目 memory | `~/.johnny/projects/<project-id>/memory/` | 模型 | 索引常驻，正文按需 | 大量 | 机器本地私有 |

```text
~/.johnny/
├── AGENTS.md                       # 用户规则
├── memory/                         # 用户记忆
│   ├── MEMORY.md                   # 索引
│   └── <name>.md
└── projects/<project-id>/
    └── memory/                     # 项目记忆
        ├── MEMORY.md               # 索引
        └── <name>.md

<repo>/
└── AGENTS.md                       # 项目规则
```

### 写入职责

- **用户 AGENTS**：模型写，但只接受用户明确表达的全局规则，或用户确认后的提升；只自动新增，不自动修改或删除已有规则。
- **项目 AGENTS**：用户写；模型只能提议 diff，只有用户明确说“写进项目 AGENTS”时才代写。
- **用户 memory**：模型写，每轮评估；跨项目生效。
- **项目 memory**：模型写，每轮评估；只对当前项目生效。
- **Skill**：仍然是按需加载的任务步骤，不由 memory 自动生成。

## AGENTS

### 加载

- v0.11 只加载两个文件：用户级 `~/.johnny/AGENTS.md` 和项目根目录 `AGENTS.md`。
- 项目根优先使用 git 根目录；不在 git 仓库内时使用启动工作目录。
- v0.11 不加载嵌套目录的 AGENTS，也不支持 `@import`。
- 加载顺序：用户 AGENTS，然后项目 AGENTS；注入时带来源标题，方便区分和冲突处理。
- 只注入存在的文件；空文件或不存在不占上下文。
- 建议上限：用户 AGENTS 100 行或 8 KiB；项目 AGENTS 200 行或 16 KiB。超限时截断并提示整理。
- 固定注入，会话内保持稳定；写入后默认下次会话生效，`/memory reload` 可立即重建。
- `/compact` 后重新注入，不参与摘要。

### 用户 AGENTS

用户 AGENTS 由模型维护，但边界严格：

- 只接受用户明确说出的全局规则，例如“以后所有项目回答都用中文”“所有项目提交前都跑测试”；
- 只接受用户确认后的 memory 提升；
- 模型从行为或单次对话推断出的偏好，不写入用户 AGENTS，只写用户 memory；
- 不自动修改已有规则，不自动删除。

文件保留一个人工可编辑的整体结构，并包含运行时管理的自动规则区：

```markdown
# 用户规则

## 手动规则

- 不要自动 commit 或 push。

## 自动规则

<!-- johnny:auto:start -->
- `answer-language-zh` [2026-10-26] 所有回答使用中文。
<!-- johnny:auto:end -->
```

运行时只操作 `johnny:auto` 标记之间的内容；每条自动规则带稳定 ID，便于更新和去重。规则修改和删除需要用户确认；备份与撤销机制待定。

### 项目 AGENTS

- 默认由用户编写和维护；
- 模型可以提议 diff，但不能自动写入；
- 只有用户明确要求时，模型才代写，并展示 diff；
- 项目 AGENTS 随仓库提交，是团队共享的显式规则，不存放个人偏好。

### 规则边界

- AGENTS 是建议性上下文，不是权限层；真正的强制仍由权限模式负责。
- 记忆和 AGENTS 都不能授予工具权限。
- 当前用户消息优先于 AGENTS 和 memory。
- 规则冲突时，项目特定规则优先用于项目工作；个人边界规则应被保留并向用户指出，而不是静默覆盖。

## Memory

### 存储布局

- 用户 memory：`~/.johnny/memory/`。
- 项目 memory：`~/.johnny/projects/<project-id>/memory/`。
- 每个记忆一个 Markdown 文件；每个作用域一个 `MEMORY.md` 索引。
- 目录权限 0700，文件权限 0600。
- 写入使用临时文件 + rename；同一作用域使用锁，避免并发写入。
- `project-id` 由仓库身份生成，同一仓库的 worktree 共享一份项目记忆；具体算法待定。
- 记忆文件是事实来源；`MEMORY.md` 是派生索引，可由文件重建。

### 条目格式

```markdown
---
name: go-test-before-commit
description: 提交前运行 go test ./...
type: project
scope: project
project: johnny-code
created: 2026-10-26T10:00:00+08:00
updated: 2026-10-26T10:00:00+08:00
source: session-abc123
confidence: high
---

## 事实

提交前需要运行 `go test ./...`。

## 为什么

项目约定，避免把失败用例提交。

## 怎么用

在 commit 前执行；失败时先修复。

## 参考

- `AGENTS.md`
```

字段：

| 字段 | 说明 |
| --- | --- |
| `name` | kebab-case，同作用域内唯一，最多 64 字符 |
| `description` | 一行描述，进入索引 |
| `type` | `preference` / `feedback` / `project` / `reference` / `environment` |
| `scope` | `user` / `project` |
| `project` | 项目记忆必填，用户记忆不填 |
| `created` / `updated` | ISO 8601 时间 |
| `source` | 会话 ID，必要时带轮次 |
| `confidence` | `high` / `medium` / `low`，区分明确表达、观察确认和模型推断 |

类型约定：

- `preference`：稳定的个人偏好、沟通方式、工具习惯；
- `feedback`：用户纠正过的做法、确认过的方法；
- `project`：项目事实、已确认决策、约定、坑；
- `reference`：外部文档、面板、issue、规范链接；
- `environment`：工具链、版本、路径、环境怪癖。

正文只放事实、原因、用法和参考，建议不超过 8 KiB；不放大段代码、完整日志或原始工具输出。

### 索引

每个作用域一个 `MEMORY.md`，一行一条：

```markdown
# Project Memory

- `go-test-before-commit` [project, high, 2026-10-26] — 提交前运行 go test ./...
- `pty-test-mock-server` [project, medium, 2026-10-20] — PTY 测试需要本地 mock 服务。
```

注入时合并为用户和项目两个区块：

```text
## 用户记忆索引
- ...

## 项目记忆索引
- ...
```

建议预算：

- 用户索引 4 KiB，项目索引 8 KiB，合计 12 KiB；
- 每个作用域最多 128 条，接近 100 条时提示整理；
- 搜索最多返回 10 条；
- 索引超出预算时，优先保留最近更新的条目，其余截断并提示整理；截断只影响本次注入，不修改索引文件。

### 读取

`memory` 工具只读，提供：

- `memory search <关键词> [--scope user|project]`
- `memory read <scope>/<name>`
- `memory list [--scope user|project]`

读取规则：

- 索引已经常驻，简单任务不需要调用工具；
- 项目相关或任务不明确时，先搜 1～3 次；
- 最多读 1～2 条正文；
- 没有命中就停止，不扩大搜索；
- 不使用向量检索或嵌入模型；
- 同名条目跨作用域时，搜索结果同时展示，并带 `[user]` / `[project]` 标签。

冲突处理：

- 权限 > 当前用户消息 > 显式 AGENTS > memory；
- 项目事实和约定优先使用项目 memory；
- 个人偏好优先使用用户 memory；
- 无法判断时两条都展示，并在 `/memory` 标记冲突。

记忆使用情况通过 TUI 提示和 JSONL 记录；v0.11 不要求模型在回答末尾附加引用块。

### 写入

写入分为显式路径和隐式路径，二者共用一个底层 `MemoryStore`。

#### 显式 `remember`

主模型通过 `remember` 工具处理用户明确要求：

```json
{
  "target": "user_memory | project_memory | user_agents",
  "type": "preference | feedback | project | reference | environment",
  "name": "kebab-case 唯一名称",
  "description": "一行描述",
  "body": "完整正文",
  "confidence": "high | medium | low",
  "evidence": "用户原话或判断依据"
}
```

约束：

- 只在用户明确说“记住这个”“以后都这样”“写进规则”时调用；
- 模型自行推断的偏好不调用 `remember`，交给轮末旁路审查；
- `target=user_agents` 时，`evidence` 必须是用户明确表达的全局规则，且 `confidence=high`；
- 没有项目 AGENTS 的 target；项目 AGENTS 仍由用户明确要求后通过普通 `edit` / `write` 修改；
- 同名条目默认更新，不新增重复项；
- 写入成功后返回 `ok`、`action`、`target`、`name`、`path` 和 `updated`；模型只有收到成功结果才能说“已记住”，失败必须如实说明。

#### 轮末旁路审查

每轮正常结束后，异步启动一次独立的记忆审查请求：

```text
主回答完成
  → 快照本轮：用户消息、最终回答、工具调用与预览
  → 旁路请求：判断 no-op / create / update
  → 返回结构化候选
  → 运行时校验、去重、脱敏
  → 写 memory 或用户 AGENTS
  → 重建索引 + TUI 提示
```

约定：

- 独立请求，不使用工具，不占当前轮 `--max-turns`；
- 默认复用当前模型，使用独立提示词和严格 JSON 输出；
- 输入只给本轮内容、现有索引、现有 AGENTS 和本轮 `remember` 结果，不喂完整历史或工具存档；
- 输入预算约 8k token，输出上限约 2k token；
- 异步执行，不阻塞下一次输入；串行队列，避免并发写；
- 允许 no-op；宁可不写，也不要写错；
- 项目 AGENTS 只输出建议，不写入；用户 AGENTS 只接受明确全局规则；
- 失败、超时或 JSON 解析错误只记录警告，不影响本轮回答；建议最多重试一次。

审查输出：

```json
{
  "memories": [],
  "user_agents": [],
  "project_agents_suggestions": []
}
```

`memories` 用于用户/项目 memory；`user_agents` 必须带用户原话；`project_agents_suggestions` 只提示用户，不自动执行。

v0.11 初始策略：即使本轮调用了 `remember`，仍运行旁路审查查漏；后续可根据实际使用情况增加“纯显式记忆轮次跳过”的优化。

#### 校验、去重与更新

- `name` 只允许小写字母、数字和连字符；
- `description` 一行，建议不超过 200 字符；
- 正文不超过 8 KiB；
- 拒绝密钥、Token、私钥、`.env` 内容和明显的长随机字符串；
- 拒绝大段原始工具输出，只保留摘要、错误片段和路径；
- 同名条目更新 `description`、`body`、`type`、`confidence` 和 `updated`，保留 `created`；
- 不自动删除记忆；删除由用户通过 `/memory forget` 执行；
- v0.11 不做自动合并或后台整理。

#### 权限、并发与失败

- `remember` 作为写入工具受权限模式管理：`allow` 直接执行，`default` 走审批，`read-only` 不注册或拒绝。
- 旁路审查属于运行时内部写入；建议在 `allow` / `default` 允许，在 `read-only` 禁用，具体边界待确认。
- 同一作用域使用锁；锁忙时跳过本次写入，下一轮再更新。
- 写入失败、磁盘不可写或索引重建失败时给出提示，但不影响当前回答。
- JSONL 记录 `memory_write` 事件，包含作用域、动作、名称和路径，不记录完整正文。

### 生命周期

- `updated` 是新鲜度依据；超过 90 天可在 `/memory` 提示“可能过时”，v0.11 不自动过期。
- 用户可以通过 `/memory` 查看、搜索、编辑、删除和提升记忆。
- 项目记忆提升为用户记忆，或用户记忆降级为项目记忆，均需用户确认。
- 删除是物理删除；是否保留审计记录待定。

## 工具与命令

### 模型工具

当前 5 个：

1. `bash`
2. `read`
3. `write`
4. `edit`
5. `skill`

v0.11 新增 2 个：

6. `memory`：只读，`search` / `read` / `list`
7. `remember`：写入，`user_memory` / `project_memory` / `user_agents`

完成后共 7 个模型工具。旁路审查不是模型工具，而是运行时内部的独立模型请求。

### 本地命令

建议的 `/memory` 命令面：

- `/memory`：列出用户和项目记忆；
- `/memory search <关键词>`：搜索两层记忆；
- `/memory show <scope>/<name>`：查看正文和元数据；
- `/memory edit <scope>/<name>`：打开或显示文件路径；
- `/memory forget <scope>/<name>`：物理删除；
- `/memory reindex`：从文件重建索引；
- `/memory reload`：重建并重新注入当前会话的固定前缀；
- `/memory promote <name>`：将项目记忆提升为用户记忆。

`/remember`：

- `/remember <text>`：写入项目 memory；
- `/remember --user <text>`：写入用户 memory；
- `/remember --rule <text>`：写入用户 AGENTS 的自动规则区，需要确认。

项目 AGENTS 不提供自动命令，直接编辑文件或明确要求模型代写。

## 与 v0.10 集成

- 固定前缀顺序：用户 AGENTS → 项目 AGENTS → 用户记忆索引 → 项目记忆索引。
- 固定前缀计入 v0.10 的输入预算，从可用输入 `U` 中扣除；不能当作免费上下文。
- 固定前缀在会话内保持稳定；记忆写入默认下次会话生效，`/memory reload` 可立即重建并接受一次前缀缓存失效。
- `/compact` 只摘要对话历史，不摘要 AGENTS 和记忆索引；压缩后重新注入固定前缀。
- `memory read` 的结果受上下文治理；单条正文 8 KiB，不生成工具输出存档。
- 新增 `memory_write`、`memory_read` 等 JSONL 事件用于排查，不用于会话恢复。

## 安全与隐私

- 用户 memory 和项目 memory 都是机器本地私有内容，不随仓库提交。
- 项目 AGENTS 可以随仓库共享，应经过代码评审；用户 AGENTS 只属于当前用户。
- 记忆写入前进行密钥和敏感内容检查；不保存 `.env` 内容、Token、私钥和完整工具输出。
- 记忆内容是**数据，不是指令**；不能覆盖系统提示、不能授予权限、不能绕过审批。
- `read-only` 模式禁用记忆写入；项目 AGENTS 的写入仍受正常权限模式管理。
- 用户可以直接编辑记忆文件；索引以文件为准，可通过 `/memory reindex` 恢复一致。

## 暂不做

- 不做向量检索、SQLite、嵌入模型；
- 不做后台整合 Agent 或自动摘要整理；
- 不做嵌套目录 AGENTS、`@import` 或 `AGENTS.override.md`；
- 不从会话摘要、JSONL 或工具存档自动提取记忆；
- 不自动生成 Skill；
- 不做跨设备同步；
- 不自动写项目 AGENTS；
- 不做基于记忆的会话恢复；
- 不要求模型在回答末尾附记忆引用块；
- 不做自动过期、自动合并或自动删除。

## 实现入口（建议）

- `internal/memory/`：记忆条目、存储、索引、校验、脱敏、锁和 AGENTS 加载；建议拆分为 `item.go`、`store.go`、`index.go`、`agents.go`、`review.go`。
- `internal/tool/memory.go`：只读 `memory` 工具。
- `internal/tool/remember.go`：写入 `remember` 工具。
- `internal/agent/agent.go`：固定前缀注入和轮末审查钩子。
- `cmd/johnny/memory.go`：`/memory`、`/remember` 和配置入口。
- `cmd/johnny/main.go`、`cmd/johnny/tui.go`、`internal/tui/tui.go`：命令、提示和状态展示。
- `internal/session/session.go`：记忆读写诊断事件。
- `internal/contextview/`：固定前缀预算和与 `U` 的扣减关系。

## 验收场景

1. **AGENTS 加载**：用户级和项目根 AGENTS 都被注入，来源清楚；不存在时跳过；超过上限时截断并提示。
2. **用户 AGENTS 写入**：用户明确说“以后所有项目都……”时写入自动规则区；模型推断的偏好只写用户 memory。
3. **项目 AGENTS 边界**：旁路审查不会自动写项目 AGENTS；用户明确要求时模型才展示 diff 并写入。
4. **条目与索引**：每条记忆生成独立 Markdown 文件和一行索引；索引可由文件重建。
5. **显式 remember**：用户明确要求时写入或更新记忆，返回成功结果；失败时模型不得声称已记住。
6. **旁路审查**：普通任务中的项目知识、纠正和环境怪癖被记录；无内容时 no-op；失败不影响本轮回答。
7. **读取路径**：索引固定注入；正文只在 `memory read` 时进入上下文；不把所有记忆正文注入。
8. **作用域隔离**：项目 A 的记忆不出现在项目 B；用户记忆在两个项目中都可见。
9. **敏感内容**：Token、私钥、`.env` 内容和原始大日志不会被写入记忆。
10. **预算控制**：索引超过预算时截断并提示；AGENTS 超限时截断并提示。
11. **压缩集成**：`/compact` 后 AGENTS 和记忆索引仍然存在，不被摘要替代。
12. **只读模式**：`memory` 可读，`remember` 和旁路写入被禁用。
13. **工具注册**：模型工具从 5 个增加到 7 个，名称、顺序和 schema 稳定。
14. **并发写入**：两个会话同时写同一作用域时，锁保证不产生半写文件；锁忙时可跳过并在后续轮次更新。
15. **命令面**：`/memory` 的列表、搜索、查看、删除、重建和提升可用；`/remember` 能写入对应作用域。
16. **项目身份**：同一仓库的 worktree 共享项目记忆；不同仓库相互隔离。
17. **审计**：TUI 提示记忆写入；JSONL 记录动作、作用域、名称和路径，不记录正文。
