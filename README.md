# Johnny-Code

使用 Go 逐步搭建的 Coding Agent CLI。v0.13 在 v0.12 上增加 Workflow：主 Agent 用 `workflow` 工具先声明分步大纲，再逐步补细节并启动每一步的并行子 Agent；一步全部结束后所有报告合并送回、只唤醒一次，同时最多 5 个任务并行，多出的排队，子 Agent 之间不通信；任务区移到输入框下边线之下，同时显示 workflow 进度和单个子任务。v0.12 在 v0.11 基础上增加后台子 Agent：主 Agent 通过 `task` 工具把边界清晰的任务委派给 `fresh`（干净上下文）或 `fork`（带主对话历史快照）子 Agent，子任务在后台并行运行，主 Agent 不等待；结果在主 Agent 下一次请求前自动注入，主 Agent 空闲时自动唤醒汇总；写入类子任务必须声明文件范围，审批来源清楚，`Ctrl+C` 一起取消。v0.10 在 v0.8 基础上增加上下文治理：完整历史与每次请求视图分离，单次工具结果模型可见预览最多 32 KiB，bash 大输出保存到 `.johnny/artifacts/<会话ID>/`，每轮结束按节省量压缩工具结果，接近模型窗口时保留最近 5 个已完成轮次并生成九段式摘要；`/context` 查看预算、缓存和摘要，`/compact` 手动压缩。v0.8 在 v0.7 权限体系上增加本地 Skills：从项目级和用户级目录发现 `SKILL.md`，系统提示只注入名称和描述，模型按需通过 `skill` 工具加载正文，也可以用 `/skill` 或独立 `/skill-name` 显式调用；Skill 只提供任务指导，不授予权限。v0.7 提供默认、只读、放行三种权限模式：默认模式自动执行路径白名单内的文件操作和固定查询命令，其余操作通过 TUI 逐次审批；支持项目命令前缀白名单、项目路径白名单、固定危险后缀黑名单和进程内“本会话内允许”。2026-10-29 的权限收口已实现：固定查询扩为 21 个命令（14 个纯读、7 个逃逸口），默认和只读模式共用最多 8 段的分段器，支持管道、`&&`/`||`/`;` 和三种尾部安全重定向；仍然不是 OS sandbox。CLI 只支持在终端运行 `johnny` 进入 TUI，参数任务、管道和重定向会被拒绝。支持 Anthropic Messages、OpenAI Responses 和 OpenAI Chat Completions，可在任意目录启动并切换模型。v0.4 与 v0.5 已通过用户联合验收；v0.6 已通过用户验收；v0.8 已于 2026-10-25 确认冻结；v0.7 已实现、权限收口也已实现，待与 v0.12、v0.13 一起验收；`johnny` 默认进入逐次审批，`--read` 选择只读模式，`--skip` 选择放行模式。v0.10 已于 2026-10-25 确认冻结；v0.11 长期记忆已于 2026-10-26 确认冻结；v0.12 SubAgent 已于 2026-10-28 实现，验收后置到 v0.13 完成之后；v0.13 Workflow 已于 2026-10-28 实现，待与 v0.12、v0.7 一起验收。

## 安装和更新

需要 Go 1.26 或更新版本。在源码目录执行：

```sh
./scripts/install.sh
```

安装脚本使用 `GOBIN`，未设置时使用 `GOPATH/bin`；通常安装为 `~/go/bin/johnny`。首次安装会补齐当前 shell 的 PATH，新开终端后即可使用。也可以按脚本提示，在当前终端加载所修改的 shell 配置文件。

脚本支持 zsh 和 Bash，尊重 `ZDOTDIR` 与已有 Bash 登录配置，并避免重复添加路径。目标位置存在其他程序时会停止，不覆盖该文件。

更新源码后，重新运行同一个脚本即可更新程序。构建失败时保留已安装的程序，现有 `.env` 始终保持原位和原内容。

## 使用

在任意目录的终端直接运行：

```sh
johnny
```

Johnny-Code 只支持以这种方式进入 TUI 交互模式。参数任务、管道和重定向会在读取配置前被拒绝，不会请求模型，也不会打开 `/dev/tty`。

- 每轮结束后继续等待输入，同一进程内保留用户消息、模型回复和工具结果。
- 输入完整的 `/exit` 或在空输入处按 `Ctrl+D`（EOF）正常退出；空行不发送请求。

TUI 操作：

| 操作 | 行为 |
| --- | --- |
| `Enter` | 发送当前任务 |
| `Alt+Enter` 或 `Ctrl+J` | 输入换行；Alt 组合键需要终端发送相应按键序列 |
| 粘贴多行文本 | 保留换行，按 Enter 后才提交；使用终端自带粘贴快捷键 |
| 左右方向键、Home/End、删除键 | 编辑输入 |
| 上下方向键 | 在多行内移动；位于首行/末行时切换本进程输入历史；斜杠菜单打开时改为选择菜单项 |
| 输入 `/` | 在输入框上方打开 Skill 和内置命令菜单；继续输入自动过滤 |
| 菜单中 `Enter` 或 `Tab` | 补全选中的命令；完整命令直接按 `Enter` 执行 |
| 菜单中 `Esc` | 关闭菜单；清空输入后重新输入 `/` 可再次打开 |
| 中文等输入法 | 组合文本和候选窗口跟随输入框中的真实光标位置 |
| 任务执行中 | 输入框上方实时逐条显示工具名、路径或命令和执行状态 |
| 有后台子任务或 workflow 时 | 输入框下边线之下、页脚之上常驻任务区，最多占终端高度的三分之一：单个子任务一行（ID、描述、耗时、状态：运行中 / 等待审批），workflow 显示大纲进度、当前步骤和运行中的任务；单个子任务结束时打印一行提示，workflow 每步结束和整个结束各打印一行汇总，不显示子任务的过程 |
| 本轮结束按 `Ctrl+O` | 展开最近一次工具过程；默认折叠为一行摘要 |
| 任务中 `Ctrl+C` | 取消本轮和全部子任务，等待当前操作停止后继续输入；上下文和已完成修改保留 |
| 审批等待中 `↑`/`↓`、`k`/`j`、`Enter` | 选择“允许本次 / 拒绝本次 / 本会话内允许 / 批准并记录”（后两项按条件显示）；默认焦点在拒绝；主 Agent 空闲时也能响应子任务的审批，来自子任务的请求标明来源，多个请求按先进先出排队 |
| 审批等待中 `Ctrl+C` | 取消本轮和全部子任务，丢弃全部待审批请求，不执行待审批操作 |
| `/permissions` | 查看固定白名单、危险后缀黑名单、项目规则和本会话授权；支持 `remove-command`、`remove-path`、`clear`、`clear-session` |
| `/context` | 查看上下文估算、窗口预算、缓存指标、摘要和工具输出存档 |
| `/compact` | 手动压缩较早的已完成轮次；压缩期间 `Ctrl+C` 取消 |
| `/memory` | 查看用户级和项目级 `MEMORY.md` 索引 |
| `/remember [内容]` | 让模型起草或更新项目 AGENTS，先展示拟修改内容，确认后写入 |
| `/skills` | 查看已加载、被项目级覆盖、未加载和未注入提示的 Skill |
| `/skills reload` | 重新扫描项目级和用户级 Skill 目录，并更新后续轮次的系统提示 |
| `/skill <name> [参数]` | 显式使用某个 Skill；正文直接进入本轮任务，终端只显示原始命令 |
| 空闲时 `Ctrl+C` | 输入框有内容时清空输入，保留会话；输入框为空且有子任务或 workflow 时取消全部 |
| `/exit`、空输入 `Ctrl+D` | 正常退出；有子任务在运行时提示“N 个子任务将被取消”，取消并等它们停止后退出 |

权限模式：

```sh
johnny                                      # 默认模式：逐次审批
johnny --read                               # 只读模式
johnny --skip                               # 放行模式：跳过逐次审批
```

`--permission-mode default|read-only|allow` 长写法继续保留；与 `--read`/`--skip` 同时使用时必须一致，否则启动报错。

- `default`：不传权限参数时的默认模式，也可用 `--permission-mode default` 显式指定。启动工作目录和项目路径白名单内 `read`、`write`、`edit` 自动执行；固定查询分两档：纯读 14 个（`echo`、`basename`、`dirname`、`pwd`、`realpath`、`ls`、`grep`、`cat`、`head`、`tail`、`wc`、`stat`、`du`、`diff`），逃逸口 7 个（`find`、`rg`、`sed`、`sort`、`uniq`、`tree`、`file`），各自使用封闭参数表和语义解析；其余文件访问、Bash 命令通过审批。
- 自动执行必须同时满足：未命中危险后缀黑名单；每个命令段命中固定查询表、已记录的项目前缀或本会话授权；可识别的路径参数都在项目路径白名单内（含会话路径授权）。文件工具和查询命令的路径仍逐项检查，已有命令授权不会顺带放行新的路径。
- 默认模式和只读模式共用同一个分段器：按 `&&`、`||`、`;` 连接管道，`|` 绑定更紧，整条命令最多 8 个命令段；逐段判定，全部自动放行才执行。`cd <目录>` 只能作为整条命令的第一段，后续段按虚拟工作目录解析相对路径并继续做路径检查；`cd` 不能参与管道，也不能紧邻 `||`。满足条件时按直接 argv 加 OS pipe 执行，不经过 shell；`&&`、`||`、`;` 按原始退出码短路，管道退出码取最后一段，不设 pipefail。只认命令段末尾的 `2>&1`、`>/dev/null`、`2>/dev/null`，并按出现顺序应用。未引用的通配符在默认和只读模式下都直接拒绝，并提示改用 `find -name`（需要 shell 通配符时可使用 `--skip` 放行模式）；写入真实文件的重定向、输入重定向、后台执行、命令替换、循环、条件、变量展开不在受控语法范围，默认模式对这类语法做一次完整 shell 审批且不提供记录或会话授权，只读模式直接拒绝。直接调用解释器等非查询程序仍需审批；未获项目规则放行的非查询管道消费者不提供会话授权，避免更换上游输入后复用同一个 argv。固定查询命令可以作为管道生产端，项目前缀命令也可以。除通配符外，无法直接转换成 argv 的语法会回退为一次完整 shell 审批，审批原因中说明具体构造，例如命令替换或超过 8 段。工作目录内不存在的查询路径不再提前审批或拒绝，交给实际程序报告“文件不存在”。
- 项目命令前缀只接受固定工具族的安全子命令，例如 `git status`、`git log`、`go test`、`go build`、`cargo test`、`npm run build`、`make test`。首次审批选择“批准并记录”后写入 `.johnny/permissions.local.json`，后续同前缀自动执行；解释器、shell、危险后缀不提供记录。可记录工具族与危险后缀表在本次收口中保持不变。
- 项目前缀命令会检查形似路径的参数和常见选项值；脚本、测试和构建目标内部访问仍无法静态限制，这是应用层策略的边界。
- 审批提供“允许本次”“拒绝本次”“本会话内允许”“批准并记录”；默认焦点在拒绝。“本会话内允许”只在当前 johnny 进程内有效，主 Agent、子任务和 workflow 任务共享，进程退出即失效，不写项目规则文件；它按可记录前缀加规范工作目录、不可记录命令的完整 argv 加有序重定向和工作目录、或路径规则（目录记目录、文件记文件）记住授权。“批准并记录”只在可记录时出现，“本会话内允许”只在请求带有可记住的授权键时出现；命中危险后缀和 `remember` 始终每次询问。队列中同键的待审批请求在显示前重检，命中已有授权会自动放行。等待审批期间 `Ctrl+C` 取消本轮。参数任务、管道和重定向在入口处直接拒绝，不会进入 TUI 或打开 `/dev/tty`。
- 项目规则文件加载前会展示内容并请求确认，确认后的内容哈希保存在 `~/.johnny/trusted_permissions.json`；文件变化后重新确认。该信任哈希机制没有随本次收口改变。
- `read-only`：拒绝 `write`、`edit`；`read` 只能读取启动工作目录内的文件（允许读取 `.env` 等敏感文件）；`bash` 只允许固定查询两档共 21 个命令的受限形式，使用与默认模式相同的分段器，支持管道、`&&`、`||`、`;`、工作目录内的虚拟 `cd` 和三种尾部安全重定向，不经过 shell；未命中固定表或表格外选项直接拒绝，不支持项目前缀和会话授权。解析失败时说明具体原因和处理建议，例如“命令共 12 段，超过 8 段上限；请拆成多条 bash 调用”“不支持未引用的通配符 `*`；受控执行不展开通配符。查找文件请用 find -name '模式'”，不再只返回笼统的“不支持该 shell 语法”。不做 shell 通配符展开，给文件通配符加引号也不会展开；按名称查找文件请用 `find -name`。
- `allow`：用 `--skip`（或 `--permission-mode allow`）显式选择；直接执行工具（包括 `skill`），不进行逐次确认。
- 权限收口已实现并通过自动化验证：固定查询 21 个、纯读与逃逸口两档、默认和只读模式共用统一分段器、只读模式复合命令、安全重定向和进程内“本会话内允许”。全量 `go test -race ./...`、`go vet ./...`、`go build ./...`、`bash -n scripts/install.sh` 均通过；独立复核发现的问题已修正并补测试。真实模型在只读模式下观察到语法拒绝提示过于笼统后，已补强为说明具体原因和处理建议。用户验收仍与 v0.12、v0.13 一起安排，不能视为已完成验收。细节见 [v0.7 文档](docs/versions/v0.7.md)。
- 三种模式都是应用层策略，不是操作系统沙箱。默认模式的 Bash 仍以当前用户权限运行，脚本内部行为不受路径检查限制；只读模式允许读取范围内的 `.env`、私钥、`.git` 等文件但拒绝写入；放行模式不应用路径规则。默认模式路径白名单内的 `.env`、私钥、`.git` 和 `.johnny` 权限文件可以直接读写，这是明确取舍。默认模式的子进程环境会过滤 Johnny 和模型服务凭据变量，但不能阻止命令读取磁盘上的配置。
- 固定查询的封闭参数表收窄的是可自动执行的命令形式，不等于“零副作用”或“绝对不写盘”：例如 `sort` 在输入超过内存缓冲时仍可能向系统临时目录写临时文件；`stat`、`file` 等程序的可用选项按平台不同；被允许的程序内部行为不在应用层路径检查范围内。只读模式是策略性只读，不是 OS 隔离。
- 默认模式不是“所有操作都自动”，也不是“所有操作都弹窗”：低风险、可解释的操作保持流畅，写入、任意命令和范围外访问由用户决定。

常见自动执行示例（默认模式下；只读模式在启动工作目录内使用同一套固定表和分段器）：

```sh
rg -n "TODO" . | head -20
find . -name '*.go' | head
cat a.txt | grep -v '^#' | wc -l
sed -n '1,20p' README.md
git status 2>/dev/null     # 已记录 git status 前缀后
go test ./... | tail -20   # 已记录 go test 前缀后
```

示例中的固定查询选项、路径和重定向仍需通过当前的封闭参数表与路径检查；任一段未命中时，默认模式整条命令一次性审批并标出需要审批的段，只读模式整条拒绝。

> 下文所说的“默认模式”指权限模式 `default`，也是不传权限参数时的 CLI 默认值。`--read` 和 `--skip` 分别对应 `read-only` 和 `allow`。

## 上下文治理

v0.10 把上下文分成三层：完整历史、每次实际发送给模型的请求视图、终端展示视图。完整历史只追加不压缩；请求视图按预算截断大载荷、保存工具输出并在接近窗口上限时压缩；展示视图只负责如实显示，不做上下文压缩。

- 单次工具结果超过 32 KiB 时，模型可见内容最多保留 32 KiB 预览；完整结果仍在会话 JSONL 中。bash 超出部分保存到 `<工作目录>/.johnny/artifacts/<会话ID>/turn-N/call-M-bash.log`，模型可以直接用 `read` 再次读取；目录权限 0700，文件 0600，正常退出时删除当前会话存档。
- bash 预览保留开头 24 KiB 和结尾 8 KiB，便于同时看到启动信息和错误尾部；`read` 保留开头 32 KiB，并在预览中给出下一次 `offset`；其他工具保留开头 32 KiB。
- 一轮内工具预览累计达到 128 KiB 后，后续大结果只保留 8 KiB 小预览和存档/续读路径。
- 每轮结束评估该轮工具结果：只有节省至少 4096 token 且至少节省一半时才整轮替换为压缩记录。压缩记录保留工具名、状态、大小、存档路径和小预览；`tool_call` / `tool_result` 保持成对，更早轮次不重写。
- 接近窗口时自动压缩：轮开始前估算达到 90% 可用输入预算，或每次请求前达到 95%，保留当前轮和最近 5 个已完成轮次，把更早轮次替换为一条带边界的合成 user 摘要消息。只保留最新摘要，旧摘要通过“历史摘要”字段带入新摘要。
- 摘要请求不使用工具，独立超时并使用单独输出上限，不占当前轮 `--max-turns`。摘要采用九段结构，并包含当前交互模式、历史摘要、待办和与最近轮次的衔接；运行时会丢弃 `<analysis>`，只保留 `<summary>`。
- 摘要失败时降级为确定性裁剪；仍超过预算时报 `context_exceeded`。连续失败或压缩后快速回填会触发 thrashing 熔断，停止自动压缩；`/compact` 仍可手动执行。
- 预算口径：`W` 为窗口，`O` 为输出预留，`S = max(16384, W × 5%)`，`U = W - O - S`。`JOHNNY_CONTEXT_WINDOW` 覆盖 `W`（默认 1000000），`JOHNNY_MAX_OUTPUT_TOKENS` 覆盖 `O`（默认 4096）。
- `JOHNNY_MEMORY_AUTO=off` 关闭轮末自动记忆审查；显式 `remember`、`/remember` 和 `/memory` 仍可用。
- `read` / `bash` 的大结果预览是请求视图，不改变完整历史和 JSONL 记录；工具结果存档不是长期记忆，也不用于会话恢复。
- `/context` 显示估算占用、预算、最近请求缓存读写、摘要和存档目录；JSONL 中 `notice` / `summary` 事件记录压缩过程和摘要正文，`tool_end` 同时记录完整结果和存档路径。

## 长期记忆（已确认冻结）

v0.11 增加 AGENTS 规则和跨会话记忆：

- 用户级 AGENTS 与项目级 AGENTS：少量规则，每次会话固定注入；只在会话启动和压缩后重新加载；
- 用户级 memory 与项目级 memory：一条一个 Markdown 文件，`MEMORY.md` 索引常驻，正文按需读取；
- 模型通过只读 `memory` 工具检索，通过 `remember` 工具写入用户/项目记忆或用户规则；
- `/memory` 查看两个记忆索引；`/remember` 让模型读取项目 AGENTS，先展示拟修改内容，确认后写入；
- 轮末旁路审查自动提取隐式学习，结果在下一轮提示；`JOHNNY_MEMORY_AUTO=off` 可关闭；
- 项目 AGENTS 由用户维护，memory 由模型维护、用户可审计。

详见 [v0.11 设计文档](docs/versions/v0.11.md)。

## SubAgent（后台子任务）

主 Agent 用 `task` 工具委派任务；用户只和主 Agent 对话，用自然语言说“让子 Agent 去查一下……”即可，`fresh` 还是 `fork` 由主 Agent 判断。`task` 只在终端 TUI 入口注册，参数任务等非终端路径不提供。

- `kind=fresh`：干净上下文，只看到 `prompt`、AGENTS、记忆索引和 Skill 元数据；`kind=fork`：复制主对话请求视图（含摘要）的快照，截到派出之前最后一个完整消息边界；主对话超过可用输入预算的 50% 时拒绝 fork，提示改用 `fresh`。
- `access=read`（默认）：不论父权限模式一律只读包装；`access=write`：沿用父权限策略（默认模式走审批，放行模式直接执行），必须用 `paths` 声明负责的文件或目录。父会话为只读模式时拒绝写入类子任务。
- 同一条消息里的多个 `task` 调用依次启动，同时最多 5 个（与 workflow 的任务共用名额，没有空闲名额或有任务排队时直接拒绝）；每个子任务最多 30 次模型请求、20 分钟，单次请求超时沿用 5 分钟。没有 wait 或 poll 工具，主 Agent 派出后继续其他工作或结束本轮。
- 结果自动回来：主 Agent 仍在运行时，报告（最多 8 KiB，包装为“仅作数据”的数据块，一次注入合并最多 24 KiB）在下一次模型请求前注入当轮；主 Agent 空闲、输入框为空时自动唤醒它汇总，同时完成的多个结果合并为一次唤醒；用户正在输入时不抢占。同一次用户输入之后连续自动唤醒最多 5 轮。被取消的子任务不注入。
- 状态：`completed`、`canceled`、`request_timeout`、`max_turns`、`max_tokens`、`refusal`、`failed`，以及 `time_limit`（20 分钟总时长）；`max_turns`、`max_tokens`、`time_limit` 标注为部分结果，最后一次响应里未执行的工具调用不进入报告。
- 文件范围：运行中的写入类子任务占用其 `paths`，范围不能重叠；子任务的 `write`/`edit` 只能落在自己的范围内，主 Agent 的 `write`/`edit` 遇到被占用路径会被拒绝并说明占用者；子任务结束（成功、失败或取消）立即释放。`bash` 不受限，这是防误写的护栏，不是安全边界。
- 子 Agent 工具：`bash`、`read`、`write`、`edit`、`skill`、只读 `memory`，受访问级别约束；没有 `remember`、没有 `task` 和 `workflow`（只有一层）；不写长期记忆，不触发轮末记忆审查。主 Agent 的轮末记忆审查也会排除子任务报告，唤醒轮不审查。
- 审批：子任务需要审批时暂停等待，审批面板标明“来源：子任务 ID 描述”，审计记录带 `origin` 字段；“批准并记录”写入同一份项目规则，“本会话内允许”写入同一份进程内会话授权，对主 Agent、其他子任务和 workflow 任务同样生效。子 Agent 的输出不能代表用户同意，也不能改变权限。
- 取消与退出：忙碌时 `Ctrl+C` 取消主 Agent 当前轮和全部子任务；空闲时输入框有内容先清空，为空则取消全部子任务；`/exit` 或 `Ctrl+D` 提示后取消并等待停止；收到 SIGINT、SIGTERM 或挂断信号同样取消全部子任务。没有单独停止某个子任务的入口。
- 日志：每个子 Agent 写独立 JSONL `~/.johnny/sessions/<主会话ID>-sub-<子任务ID>.jsonl`，元数据含 `parent_id`、`subagent_id`、`kind`、`access`、`paths`、`description`；主会话 JSONL 记录 `subagent_start`、`subagent_end` 和 `inject` 事件（`sources` 标明来源）。子任务的工具输出存档在子任务结束时清理。

详见 [v0.12 设计文档](docs/versions/v0.12.md)。

## Workflow（分步并行）

主 Agent 用 `workflow` 工具把较大的任务拆成有顺序的几步，每一步内多个子 Agent 并行执行，子 Agent 之间不通信。用户仍然用自然语言提出要求，不设斜杠命令；`workflow` 和 `task` 一样只在终端 TUI 入口注册（TUI 入口共 9 个工具）。

- 三个动作：`start` 先声明大纲（标题和每步的标题、目标，最多 10 步，不写任务细节）；`run` 轮到某一步时给出这一步的任务（最多 8 个，字段与 `task` 相同）并启动，立即返回；`end` 提前结束，运行中的任务被取消，剩余步骤标为未执行。
- 整批启动：一步的任务一起校验，范围重叠、超限、参数错误或与运行中任务冲突时整批拒绝，不启动任何任务；文件范围在启动时一次登记，包括排队的任务。步骤必须按顺序启动，上一步结束前不能启动下一步，同一时间只有一个工作流，大纲不能修改，计划不合适时用 `end` 结束再另起一个。父会话为只读模式时拒绝含写入类任务的整步。
- 并行与排队：同时运行最多 5 个任务，多出的按先进先出排队补位；`fork` 任务的对话快照在 `run` 时就取好，排队的也一样。
- 整步送回：一步的任务全部结束后，所有报告按任务顺序合并成一条消息送回主 Agent，只唤醒一次。消息开头是运行时生成的步骤标题、工作流进度和下一步提示，之后才是各任务的报告；正文里同形的块标记会被转义，不能伪造进度。每份报告沿用“仅作数据”的声明，一步的报告总量（含进度和包装）不超过 32 KiB，8 个任务时每份正文约 3 KiB。普通子任务结果的唤醒仍受“连续唤醒 5 次”限制，步骤唤醒单独计数、上限 20 次，两类都在用户输入时归零。
- 失败：任务失败、超时或达到上限照常写进报告，工作流不自动终止，由主 Agent 决定重试、换方案或结束。
- 取消：`Ctrl+C` 取消运行中的任务、丢弃排队的任务，剩余步骤标为未执行，不唤醒主 Agent；之后再启动步骤会得到“工作流已被取消”的提示。`/exit` 的行为与 SubAgent 一致。`end` 会等被取消的任务真正释放文件范围和名额（最多 10 秒）再返回，紧接着重新开始不会撞上旧的占用。
- 日志：主会话 JSONL 增加 `workflow_start`、`workflow_step_start`、`workflow_step_end`、`workflow_end`，`subagent_start`/`subagent_end` 带 `step`，子会话元数据带 `workflow_step`；整步消息作为 `inject` 事件，`sources` 为 `workflow:step-N`。

详见 [v0.13 设计文档](docs/versions/v0.13.md)。

## Skills

Skill 是任务指导包，不是新的执行引擎。它告诉模型某类任务应遵循的步骤和项目约定；Skill 不能授予工具权限，真正的文件读写和命令执行仍受当前权限模式管理。

发现位置：

```text
<启动工作目录>/.johnny/skills/<name>/SKILL.md     # 项目级，优先
~/.johnny/skills/<name>/SKILL.md                  # 用户级
```

`SKILL.md` 使用最小 frontmatter：

```markdown
---
name: go-test
description: 当需要运行 Go 测试、定位失败用例或补充回归测试时使用。
---

# Go 测试流程

1. 先运行 `go test ./...`
2. 失败时按包定位
```

- 启动时只解析名称、描述和正文；系统提示只注入名称、描述和来源，正文不进入上下文。
- 输入 `/` 会在输入框上方打开斜杠菜单，列出全部 Skill 和内置命令；继续输入按名称过滤，`↑`/`↓` 选择，`Enter` 或 `Tab` 补全，`Esc` 关闭。选中后会补全为 `/skill-name ` 并留一个空格，便于继续输入参数。
- 每个 Skill 同时是独立的 `/skill-name` 命令，例如 `/hello-file`、`/report-maker`；原来的 `/skill <name> [参数]` 继续保留。输入完整命令后直接 `Enter` 执行；只输入前缀时第一次 `Enter` 补全，第二次执行。
- 内置命令优先于同名 Skill；例如 Skill 名为 `exit` 时，`/exit` 仍然是退出，使用该 Skill 需要输入 `/skill exit`。
- 模型判断任务匹配后调用 `skill` 工具加载完整正文；`/skill <name> [参数]` 可以直接显式加载，正文进入本轮任务但不写入终端滚动历史。
- 项目级与用户级同名时项目级覆盖用户级；项目级 Skill 自动加载，不额外请求信任确认；无效项不会阻断启动，`/skills` 显示原因。
- `/skills reload` 重新扫描并更新后续轮次的系统提示；任一目录无法读取时保留原集合。
- 最多 64 个 Skill；名称和描述等元数据最多 8 KiB；单个正文 128 KiB；描述 1024 字节。名称只能使用小写字母、数字和连字符，并与目录名一致。
- `allowed-tools` 在 v0.8 静默忽略，不改变工具集合。
- 用户级 Skill 的引用文件位于工作目录外，只读模式下不可读；需要引用文件时建议放在项目级目录。
- `.johnny/*` 默认不进入仓库，但 `.johnny/skills/` 保留，项目级 Skill 可以随项目提交。

任务执行期间不排队提交新任务。界面显示模型、工作目录、等待/接收/执行/取消状态。执行期间，工具调用会在输入框上方按顺序实时显示，使用终端可用高度；超过一屏时保留最新记录并在顶部提示更早条数。本轮结束时清除实时进展，在最终回答前保留一行折叠摘要（已执行次数、工具名，按 `Ctrl+O` 展开），随后显示完整的最终回答。完整工具调用与结果保留在会话 JSONL 中；需要回看时用 `Ctrl+O` 展开最近一次过程。模型回复按 Markdown 渲染标题、列表、引用、表格和代码块；明确语言的代码块包含语法高亮，未标注或纯文本代码块按无高亮等宽原文显示，长行按词换行。目录树有单独的排版规则：无围栏也能识别，不进行语法高亮；宽度足够时保持原始列，窄终端压缩数字列并把说明换行到说明列或条目下方，树形分支不会被拆断。调用链、关系图等自由排版内容保留原缩进换行，长说明不会被省略号截断。当前使用深色终端样式，暂不提供主题切换。生成期间状态区显示已接收字数，不把回答原文写入动态区域；响应结束后先提交折叠摘要，再提交排版后的正文，避免重复显示。单次输入最多 10000 行，超限粘贴会整体拒绝并提示，不静默截断。

例如，第一轮输入“创建一个输出 hello 的 Go 程序”，下一轮可以继续输入“把刚才的输出改成 world 并运行检查”。后一次请求会携带当前会话历史。

每轮内部都可以多次请求模型和执行工具。交互模式中，模型请求失败、截断或达到次数上限会说明原因，然后继续等待输入。TUI 中的按键 `Ctrl+C` 只取消当前轮；外部 SIGINT、SIGTERM 或终端挂断信号会取消任务并退出。新进程从新会话开始，不加载旧记录。

临时切换模型或协议，不修改 `.env`：

```sh
johnny --model "服务提供的另一个模型名"
johnny --api openai-responses --model "服务提供的GPT模型名"
johnny --api openai-chat-completions --model "服务提供的模型名"
```

启动后直接在 TUI 中输入问题。选项放在启动命令上；包含空格的模型名用引号包围。`--model` 只替换模型名，`--api` 只替换协议，服务地址和 Key 继续使用当前配置。跨服务切换时，用 `JOHNNY_BASE_URL`、`JOHNNY_API_KEY` 环境变量提供相应配置。每次运行仍只访问一个服务，不自动探测或切换协议。

本地查询：

```sh
johnny --help
johnny --version
```

帮助显示实际配置位置；版本包含版本号与构建时的 Git 提交号，构建包含未提交改动时附加 `dirty` 标识。帮助和版本查询不读取模型配置、不访问模型服务。

程序保持启动时的工作目录。日常运行直接启动已构建的二进制，不经过 `go run`；网络和模型首段响应的等待时间独立于本地启动时间。

## 复用已有配置

已配置好的源码项目根目录 `.env` 继续使用，无需搬动、复制或重新填写。安装脚本只将该文件的位置写入构建信息，不读取或编译其中的凭据。修改配置内容后立即对下一次问答生效；源码目录位置变化后，重新运行安装脚本以更新定位。

第一次克隆且尚无配置时，才需要参考 `.env.example` 创建 `.env`，填写：

```dotenv
JOHNNY_API_KEY=你的中转站Token
JOHNNY_BASE_URL=https://你的中转站地址
JOHNNY_MODEL=中转站提供的模型名称
```

- `JOHNNY_API_KEY`：通过 `Authorization: Bearer` 发送。Anthropic 模式对应 `ANTHROPIC_AUTH_TOKEN` 认证方式。
- `JOHNNY_BASE_URL`：服务根地址或以 `/v1` 结尾的 API 根地址，程序按协议追加接口路径，避免重复 `/v1`。不支持填入完整接口地址。
- `JOHNNY_MODEL`：服务提供的模型标识。
- `JOHNNY_API`：可选协议字段，未配置时为 `anthropic-messages`。

| JOHNNY_API | 调用接口 |
| --- | --- |
| `anthropic-messages` | `/v1/messages` |
| `openai-responses` | `/v1/responses`，使用 `store: false` |
| `openai-chat-completions` | `/v1/chat/completions` |

命令行 `--api`、`--model` 优先于相应环境变量；`JOHNNY_*` 环境变量按字段优先于文件值。显式空值也会覆盖配置并报错；可选协议字段只有在完全未提供时才使用默认值。其他应用的 Anthropic/OpenAI 凭据不会覆盖本项目认证。`.env` 被 Git 忽略，仓库只包含模板。

每次模型请求最多等待 5 分钟、默认最多输出 4096 个 token（可用 `JOHNNY_MAX_OUTPUT_TOKENS` 覆盖）；每轮用户输入默认最多请求模型 100 次，可用 `--max-turns 正整数` 调整（选项放在启动命令上），下一轮重新计算预算。任务不设固定总超时。最后一次允许的响应仍请求工具时，不再执行这批工具，明确提示达到上限；截断、拒绝或请求失败也会清楚停止本轮，不自动重试。Bash 默认超时 2 分钟，工具参数可指定 1～600 秒。

模型正文在 TUI 中流式接收并按 Markdown 渲染；思考字段不作为正文显示。工具名称、路径或命令、成功或失败状态，以及有限结果预览在执行期间显示在输入框上方，本轮结束后折叠为一行摘要，可用 `Ctrl+O` 展开；日志路径和警告也经界面显示。成功退出码为 0，失败为 1，进程取消为 130；TUI 内取消单轮后仍保留进程，之后正常退出为 0。

会话调试记录保存到 `~/.johnny/sessions/<会话ID>.jsonl`，第一轮开始执行时显示路径；同一交互会话共用一个文件，记录完整消息、工具调用及结果、请求用量和停止原因。元数据包含启动工作目录、协议、模型和 `permission_mode`；不写入 API Key 或环境变量配置。审批决策额外记录为 `permission` 事件，包含工具调用 ID、目标、允许/拒绝/记录、来源、决策原因、请求原因（`request_reason` 和 `request_detail`）以及实际记录的命令前缀数组或路径。`user_turn` 表示第几次用户输入，`turn` 表示该轮内第几次模型请求。记录目录权限为 0700、文件为 0600；记录失败会警告并降级继续任务。记录只用于排查，不自动加载旧会话，不做记忆处理或会话恢复。

例如，在用于验证的空目录中运行 `johnny`，输入：

```text
用 write 创建输出 hello 的 main.go，用 read 读取，用 edit 将 hello 改成 world，再用 bash 执行 go run main.go 并检查输出。
```

`johnny` 默认逐次审批，`go run` 需要批准；想跳过审批时使用 `johnny --skip`。所有入口都必须是终端 TUI，参数任务和管道会被拒绝。

若网络需要代理，启动前设置本机适用的 `HTTPS_PROXY`、`HTTP_PROXY` 和 `NO_PROXY`。Go 默认依赖源不可访问时，可以临时为安装命令指定可用镜像：

```sh
GOPROXY=https://goproxy.cn ./scripts/install.sh
```

统一模型层位于 `internal/model`，独立工具层位于 `internal/tool`。`internal/contextview` 负责预算和 token 估算、工具结果预览与存档、请求视图、轮级压缩、摘要前缀替换和 thrashing 保护；`internal/agent` 负责本轮消息历史、模型与工具调度、摘要请求、固定前缀和轮末记忆审查及结束判断；`internal/memory` 负责 AGENTS 加载、用户/项目记忆、project-id、索引、用户规则、显式写入和旁路审查；`internal/session` 负责只写不读的 JSONL 调试记录；`internal/skill` 负责本地 Skill 发现、frontmatter 校验、项目覆盖用户、元数据预算、系统提示区块和重载；`internal/subagent` 负责后台子任务的登记、并发与时长限额、fresh/fork 子会话、受限工具集合、报告格式化和统一取消；`internal/tool/task.go`、`filescope.go`、`origin.go` 分别是 `task` 工具、写入文件范围守卫和审批来源。`internal/subagent/workflow.go`、`workflow_step.go` 是工作流进度账本、步骤屏障和整步报告，`internal/tool/workflow.go` 是 `workflow` 工具，`internal/tui/workflow.go`、`workflow_area.go` 是任务区。`internal/tui` 使用 Bubble Tea v2、Bubbles textarea 和 Lip Gloss v2 管理终端事件、输入、状态、审批面板与滚动输出，斜杠菜单在 `internal/tui/slash_menu.go`，Markdown 由 glamour v2 渲染，目录树由 `internal/tui/tree.go` 按列识别和排版；输入框使用真实终端光标，中文输入法组合文本会出现在输入位置。CLI 负责将有界显示数据与 Agent 事件衔接。工具开始状态更新后等待一个渲染周期并检查终端输出错误，再继续执行；界面输出失败会取消任务。系统提示要求目录树等对齐文本使用 text 围栏代码块，渲染层同时兼容无围栏或语言标注不合适的目录树。只读模式由 `internal/tool/readonly.go` 包装工具，工作目录边界在 `internal/tool/scope.go`，受限查询执行器在 `internal/tool/restricted_bash.go`；默认模式在 `internal/tool/default.go` 和 `internal/tool/bash_chain.go`，受控链执行器在 `internal/tool/controlled_exec.go`，审批接口和进程内会话授权在 `approval.go`、`session_grants.go`，项目规则在 `project_rules.go`，固定白名单和危险后缀分别在 `permission_whitelist.go`、`permission_blacklist.go`；`skill` 工具在 `internal/tool/skill.go`。它仍是工具策略，不是系统沙箱。
